## 一、常见发行位规格

> **口径声明**：下表为行业常见规格，用于**生成候选尺寸**。**最终以目标平台后台上传提示为准**——
> 平台的卡片位/推广位规格会随版本变化，不要用本表替代后台提示。

| 用途 | 尺寸 | 比例 | 布局 | 备注 |
|---|---|---|---|---|
| 短剧 App 卡片位（主流） | 1440×1920 | 4:3 竖 | stacked | 绝大多数竖屏短剧列表位 |
| 横版推广位 / 早期 Web | 1000×750 | 3:4 横 | stacked | 用户点名「3:4」时交付此档 |
| 短视频竖屏封面 | 1080×1920 | 9:16 | vertical | 抖音 / TikTok 视频封面 |
| 横屏缩略图 | 1920×1080 | 16:9 | wide | YouTube 缩略图、横屏广告 |
| 信息流方图 | 1080×1080 | 1:1 | stacked | Meta 信息流 / 部分信息流位 |
| 竖长海报 | 1080×1620 | 2:3 | vertical | 与多数人物立绘源图同比例，裁切损失最小 |
| 超宽 Banner | 2400×1000 | 12:5 | wide | 站内顶部 Banner |

**同一剧集建议一次产出 3—5 档**，覆盖「卡片位 + 缩略图 + 信息流」三类入口，风格必须一致。

## 二、布局自动判定

`pick_layout(w, h)` 按宽高比分流，阈值 1.45 / 0.85：

| 宽高比 a = w/h | 布局 | 适用 | 文字位置 |
|---|---|---|---|
| a ≥ 1.45 | **wide** | 16:9、2:1、21:9 等宽画幅 | 左栏分列，右侧留主体 |
| 0.85 < a < 1.45 | **stacked** | 3:4、4:3、1:1 等近方形 | 底部堆叠 |
| a ≤ 0.85 | **vertical** | 9:16、2:3、3:4 竖 | 底部堆叠（更高压缩比） |

**为什么必须分流**：宽画幅若沿用底部堆叠，画面会被切成一「文字块」加一条窄画面，主体几乎不可见。
左栏分列才能让宽画面的横向空间发挥作用。

显式传 `"layout": "wide"` 可覆盖自动判定，用于特殊构图。

## 三、取景参数 `focus`

`focus` 控制垂直取景位置：`0` = 贴近源图顶部，`1` = 贴近底部。

**先判断该方向有没有余量**。公式：`scale = max(tw/sw, th/sh)`；
若 `sw × scale > tw` 则水平有余量（可居中偏移），否则**水平被锁死**，主体无法左右平移，
只能靠 `focus` 在垂直方向取舍。

| 源图 | 目标 | 水平余量 | focus 建议 |
|---|---|---|---|
| 2:3 人物立绘 1248×1856 | 16:9 1920×1080 | **0（锁死）** | **0.10—0.15**（保头肩，否则只剩躯干） |
| 2:3 人物立绘 | 3:4 1000×750 | 0（锁死） | 0.30—0.38 |
| 2:3 人物立绘 | 1:1 1080×1080 | 0（锁死） | 0.15—0.25 |
| 2:3 场景图 | 16:9 1920×1080 | 0（锁死） | 0.30—0.45（保地平线） |
| 16:9 剧照 | 4:3 竖 1440×1920 | 0（锁死） | 0.35—0.50 |
| 16:9 剧照 | 1:1 1080×1080 | **>0（可调）** | 0.40—0.50 |

**最重要的规律**：源图比目标**更窄**时，水平方向零余量。竖版立绘转任何横版都属于这种情况——
这是最常见的隐性失效点，表现为「人物被切得只剩一条」。**转横版时 focus 必须往前调（取上部）**。

引擎在零余量时会打印 `[水平零余量:主体无法左右平移]` 提示，看到它就要检查 focus。

### 3.1 逐图确认，不可批量套用

上表给的是**起始值，不是安全值**。同一批资产图的人物占地面积常不一致——
立绘的头顶位置可能相差 10% 以上，用同一个 `focus` 会出现「这张露脸、那张只剩西装」。

**真实案例**：某批次两张人物定妆图同为 2:3（1248×1856），转 3:4 横（1000×750）时垂直余量为 737px。
- 图 A（人物偏上）：`focus=0.34` 五官完整
- 图 B（人物偏下）：`focus=0.30` 时 `top=221`，而头部在缩放后的 74—297 区间内，
  **几乎整张脸被切掉，只剩西装躯干**

结论：**取景后必须逐张目视确认五官可见**。缩略图里没有人脸的封面，
点击率显著低于有人脸的——「文字没压脸」不等于「脸在画面里」。

### 3.2 校正流程

1. 先按上表取起始 `focus` 出图
2. 逐张查看：五官是否完整、是否被文字覆盖
3. 切到脸 → **减小** `focus`（往上取）；主体太靠上失去构图 → 增大 `focus`
4. 每次调整后重新目视，不要凭公式推断

---

### 3.3 同一剧集的竖版与横幅：**底图必须分别生成**（2026-10-20 新增）

同一部剧同时要竖版（9:16 / 4:3）和横幅（16:9）时，**不要用一张竖版立绘去裁横幅**。

- 竖版底图的水平方向几乎没有余量：`scale = max(目标宽/源宽, 目标高/源高)`，竖图转宽幅时
  `scale` 由目标宽决定，画面被大幅纵向裁切——横幅最后只剩「一条躯干」，主体与留白都没了。
- 正确做法：spec 里**每一项独立给 `src`**（引擎支持逐项 `src`），横幅单独出一张横构图底图：
  左半暗部留白、右侧主体，文字压左栏。
- `--check` 会主动告警这类组合：

```
[WARN] cover_16x9：源图 900x1600（比例 0.56）比目标 1920x1080（比例 1.78）**更窄**
       ⇒ 水平零余量，横幅会被裁成一条躯干。这一档请单独用横版底图。
```

判据：`源图比例 < 目标比例 - 0.02` 且目标 `layout == wide`。这只提示、不阻断——
如果你确知主体在中轴、愿意接受裁切，可以忽略。

## 四、暗罩参数 `side` / `power` / `strength`

仅 `wide` 布局使用。

| 参数 | 作用 | 取值 |
|---|---|---|
| `side` | 压暗区占画宽的比例 | 0.55—0.78 |
| `power` | 衰减曲线陡度 | **0.78—0.90**（>1 衰减过快，中段失效） |
| `strength` | 最左端压暗强度（0—255） | 230—245 |
| `scrim` | 是否启用压暗 | `false` = 纯靠描边 |

**`power` 是最容易调错的参数**。取 1.25 时（直觉上的「平滑」）衰减过快，
画宽 62% 处的文字完全得不到压暗，白字压在浅色服饰或亮幕墙上会不可读。
降到 0.78—0.90 才能在中段维持有效压暗。

**不要靠加大 `side` 兜底**。`side=0.76` 能把文字区彻底压干净，
但会连主体一起压黑——人物脸部亮度下降约 40%，直接损失缩略图点击吸引力。
正确做法是**先把描边加厚，再把 `side` 收回来**。

## 五、文字可读性：三保险的优先级

按代价从低到高：

1. **描边（首选）**：`stroke_width = 画高 × 0.0055`（1080p 下约 6px），`stroke_fill=(0,0,0,205)`。
   代价为零，不影响画面。**所有文字都应默认描边**。
2. **投影（次选）**：多层低透明度偏移绘制（`layers=10—14`，`alpha=24—30`）。增强层次，代价低。
3. **压暗（最后手段）**：压低整块画面亮度。**代价最高**，只加到达标即止。

`stroke_scale` 可在单张封面级覆盖描边倍率，用于极端情况（如文字压在雪景、白墙上 → 1.3—1.5）。

## 六、安全区

| 风险 | 处理 |
|---|---|
| 平台底部进度条遮字 | 底部文字基线距底 ≥ 画高 × 0.06 |
| 右下角时长角标 | 关键信息放**左侧**；右侧 badge 只放可牺牲信息（语言/受众） |
| 圆角裁切（卡片位） | 四周留 ≥ 画宽 × 0.05 边距 |
| 文字压脸 | **绝对禁止**。取景后必须目视确认所有文字不覆盖五官 |

## 七、输出与验收

`export` 段控制产物：

```json
"export": { "png": true, "jpg": true, "jpg_quality": 92, "preview": true }
```

- **PNG**：无损，用于存档与后续再加工
- **JPG**（quality 92，`subsampling=0`）：体积降至 PNG 的 ~20%，用于实际上传
- **preview**：多方案拼版，**保比例居中**（不得拉伸），用于选图评审

验收三条硬指标：

1. 尺寸比例与目标**完全相等**（不要「差不多」）
2. 所有文字距边 ≥ 5% 画宽，且**无一处压在人物五官上**
3. 按缩略图尺寸（约 300px 宽）目视一遍，主标题仍可辨识

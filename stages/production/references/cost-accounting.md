# 成本口径与结账（只算时间，不算钱）

出图、出片、放大全部跑在本机，没有按次计费的平台。唯一稀缺的资源是 **本机 GPU 时间** ——
一集要跑 1 小时还是 8 小时，决定这件事能不能当产能用，比「￥0」有意义得多。

## 一、两条铁律

1. **耗时只认台账实测**（`run_ledger.py` 每次任务记一条真实墙钟时间），逐条累加。
2. **预估只用于排期，不用于结账**。`time_model.py` 的系数随显卡、工作流、分辨率变化，
   拿它当「已经花了多少时间」会和自己的记录对不上。

## 二、口径

| 项 | 单位 | 影响因子 |
|---|---|---|
| 资产图 / 分镜图 | 秒/张 | 分辨率、步数（`megapixels` 影响最大） |
| 出片 | 秒/镜 | 镜长 × 帧率 + 每镜固定开销（加载模型 / 编码），**占整集大头** |
| 剪辑 | 秒/集 | 拼接 + 放大 + 对齐 + 烧录 |

## 三、实测基准（RTX 4060 Laptop 8G + 16G）

| 项 | 实测 | 备注 |
|---|---|---|
| 单段出片 | 5–10 分钟 | 672×1216 / 8 步 turbo |
| 一集（8 镜 × 6 秒） | ≈ 2.5 小时 | 出片占 78% |
| 整季（30 集） | ≈ 76 小时 | 单卡并发恒 1 |

> 8G 显存下出图与出片争用同一张卡，必须串行。**并发 1 不是保守设定，是硬约束** ——
> 同时提交两个任务只会两边都变慢，还可能 OOM。

## 四、失败率

出片失败率 ≈ **10%**（历史实测 9.1%）。失败**不额外花钱，只额外花时间**，
排期时按 1.1 倍预留；重跑用 `--resume` 只补失败段，不重提已成功的段。

## 五、结账

```bash
drama.py time plan                  # 开工前：预计要跑多久
drama.py time report                # 收工后：已经跑了多久（读台账）
drama.py time plan --calibrate      # 用实测反推系数，写进 <工作区>/time-model.json
```

台账落在工作区（`run_ledger.py` 写入），`time report` 只做聚合，不改任何产物。

## 六、LLM 侧仍然按量计费

创作层（企划 / 剧本 / 资产库 / 导演手册）走大模型网关，按 token 计费：

- 只认网关返回的 `usage.cost`，**不按字数估算**；
- 余额只用于判断「够不够跑」，不做归因（余额变动混入充值、其他产品、其他使用者）。

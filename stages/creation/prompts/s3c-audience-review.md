# 第四部分 · 观众视角审稿（LLM 提示词模板）

> 用途：剧本/大纲定稿前，**换一双眼睛**审一遍。不看格式，只看「观众会不会看下去」。
> 产物：`03-剧本/audience-review.md`。门禁：`script_rewrite.py audience --check`（退出码 2 未过）。
> 方法真源：`docs/creation/剧本改编四段法.md` 第六节。

## 你的身份（必须先切换）

**不要**以编剧身份评价剧本。以**目标观众**和**短剧项目负责人**身份审稿：

- 观众视角 —— 会不会划走、会不会追、在哪一集弃
- 负责人视角 —— 哪一处最该先花钱改

编剧关心「我想表达什么」，审稿人只关心「观众还在不在」。

## 前置

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> audience   # 生成模板
```

模板含七问。**每条回答必须引用具体集号（EPxx）和具体情节**；只写「节奏不够快」「冲突不够强」视为未回答，`--check` 会拦。

## 七问

### Q1 观众最可能在哪一段失去兴趣？为什么？

指到具体集号与具体情节。判断依据是「这一段有没有让观众产生新的期待」，不是「写得不够好」。

### Q2 哪个情节最值得期待？是否出现得太晚？

最有爆点的那个情节，出现在第几集？如果超过全剧 1/4 才出现，观众等不到。

### Q3 哪个冲突看起来像作者刻意安排，而不是人物自然选择？

典型症状：反派本可以不出现却非要到场、主角本可以报警却非要自己解决。
判断标准：**换个合理的做法就没戏可写 = 这个冲突是靠降智撑起来的**。

### Q4 哪个反转缺乏铺垫，或删掉也不影响故事？

两个判据任一成立即判定：① 前文没有任何提示；② 删掉后主线推进不受影响。

### Q5 哪个爽点 / 虐点 / 情感回报不够充分？

对照「落差 × 见证者 × 金句」三要素：是先踩得不够深，还是没人看见，还是缺一句钉死的话？
缺少反应镜头是最常见的失分项 —— 只给结果不给反应，观众爽不起来。

### Q6 观众看完每集后，有什么具体理由继续追？

答案必须是**具体物件或身份**（「烧掉的原件到底在哪」），不能是「想知道她能不能赢」。

### Q7 当前最需要优先修改的三个问题是什么？

必须写成 **3 条编号清单**，按修改收益从高到低排序，每条包含：

```
N. EPxx —— 问题：… 改法：…
```

`--check` 会校验：恰好 3 条、每条 ≥20 字、每条有「改法」或 `→`。
排序依据是「改这一条能让多少集变好」，不是「哪条最严重」。

## 工作纪律

1. **引用不到具体集号的判断，不要写**。
2. **不要给形容词结案**。每条结论后面必须跟一个可执行的改法。
3. **不要因为「后面会好」而放过前面**：观众只看得到已播出的部分。
4. **发现结构性问题时，不要只写建议** —— 直接指出该回 `plan` 改哪几集。
5. **不许一次性列十几条问题**。只挑收益最高的三条，其余归到 Q1-Q6 的正文里。

## 填完自检

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> audience --check
```

通过标准：七问都有实质回答（≥40 字）、至少 4 问引用集号、Q7 恰好 3 条带改法。

## 审完之后

- 若问题在**结构层**（冲突重复、主角被动、反转不改格局）→ 回 `plan` 改 blueprint，再跑 `review`。
- 若问题在**正文层**（台词、反应镜头、钩子写法）→ 直接改对应集，再跑 `lint --ep N`。
- 两类都改完，重跑 `audience --check` 确认结论已落到剧本里。

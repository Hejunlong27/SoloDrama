# 本机 ComfyUI：连通稳定性与工作流编辑

> 这份文档回答两个问题：**为什么它有时候会「卡住」**，以及**在界面上到底能改工作流的什么**。

## 一、连通：一个出口，三层保险

所有连 ComfyUI 的请求都走 `stages/_comfy_http.py`（出图客户端、出片客户端、Studio 后端
共用同一份）。之前是两套各自实现的 urllib 调用 —— 同一件「ComfyUI 没开」在两处显示成
两种原因，用户要分别排查。

### 1.1 重试口径：GET 重试，POST `/prompt` 绝不重试

| 请求 | 重试 | 为什么 |
|---|---|---|
| `GET /system_stats` `/history` `/queue` `/object_info` | 3 次（退避 0.4→1.2→3s） | 幂等。8G 卡跑长任务时偶发 `ConnectionReset` 是常态，零重试等于一次抖动作废一整镜 |
| `POST /prompt` | **0 次** | 重发会**真的再出一遍**视频/图片。两份产物都算成功，时间翻倍，事后完全看不出发生了什么 |
| `POST /upload/image` | 1 次 | 同名覆盖，重发无副作用 |
| `GET /view`（下载） | 3 次 | 产物已在 ComfyUI 磁盘上，重下即可 |

「连接都没建立」（`ConnectionRefused` / DNS 失败）是唯一允许重发 POST 的情况 ——
请求肯定没到达服务端。

### 1.2 任务丢失检测：别把「任务没了」报成「超时」

ComfyUI 重启、队列被手工清空、显存不足被丢弃，都会让 `/history/<pid>` **永远空着**。
旧实现会死等到 20 分钟超时才报「超时」，而真正原因是任务没了 —— 于是人去查「是不是模型太慢」，
查错了方向。

现在轮询同时查 `/queue`：

```
history 有输出           → 成功
history 有 pid + error   → 失败（带 ComfyUI 原始状态）
history 没有 + 队列里有   → 继续等
history 没有 + 队列里也没有（连续 2 次，且已过 20 秒）→ 判定「任务消失」，立刻报错
```

提示里会直接写「重跑同一条命令即可，已完成的镜会自动跳过」。

### 1.3 探活缓存：3 秒，且按钮能绕开

`/api/comfy/status` 默认复用 3 秒内的结果。原因：状态面板是被**轮询**的，而 ComfyUI 在跑
长任务时 `/system_stats` 自己就会变慢 —— 不缓存会让看板越刷越卡，最后像是界面挂了，
其实是自己把服务问累了。

点「重新检测」走 `?fresh=1` 绕开缓存：用户按了按钮就该看到此刻的真实状态，
而不是 2 秒前的值（那会让人以为按钮没生效）。

面板上除了「在线」还显示**延迟 / 队列 / 空闲显存**：

- 延迟从 20ms 涨到 800ms = 它快撑不住了，是比「离线」更早的预警
- 队列 > 0 = 你这一镜会在后面等，不是「特别慢」
- 空闲显存 < 1G = 下一镜大概率 OOM，先点「释放显存」

### 1.4 排障顺序

| 现象 | 先看 | 再动 |
|---|---|---|
| 面板显示离线 | 状态面板的「原因」行（服务没起 / 端口不对 / 刚重启） | 点「启动」；30–90 秒内别重复点 |
| 在线但提交就失败 | 「校验」按钮的 errors（节点类缺失 / 模型文件没有） | 补自定义节点包或下载模型 |
| 卡在「已等 xxx 秒」很久 | ComfyUI 自己的队列面板 | 确认是排队还是在算；排队就等，算得慢就减帧数 |
| 报「任务从 ComfyUI 消失」 | 是否刚重启过 ComfyUI | 重跑同一条命令，已完成的会跳过 |
| 报「连续 3 次读不到 /history」 | 服务是否还活着 | 重启 ComfyUI；产物可能已在它的 output 目录 |

## 二、在界面上改工作流

入口：**连接中心 → 出片工作流**。每份工作流一张卡，四个按钮：`设为当前` / `改参数` / `改映射` / `更多`。

### 2.1 能改什么

**参数**（`改参数`）—— 生产里真正会调的那些：

| 字段 | 含义 | 范围 |
|---|---|---|
| `steps` / `denoise` | 步数 / 重绘幅度 | 1–200 / 0–1 |
| `cfg` | 提示词跟随度 | 0–30 |
| `width` `height` `megapixels` | 尺寸 | 64–8192 / 0.05–8 |
| `length` `frames` `seconds` `fps` | 时长 | 按字段 |
| `seed` `noise_seed` | 随机种子 | 0–2³² |
| `sampler_name` `scheduler` | 采样器 / 调度器 | 枚举 |
| `ckpt_name` `unet_name` `lora_name` `vae_name` `clip_name` | 模型文件 | 枚举 |
| `filename_prefix` `text` | 输出名前缀 / 提示词 | 字符串 |

**映射**（`改映射`）—— 角色 → 节点：

```
prompt    提示词写进哪个节点          （内置工作流是 238）
images    参考图铺到哪几个节点         （199,188,189,190,191,192 —— 顺序即槽位顺序）
seconds   时长（秒）                  （227）
steps / seed / aspect / prefix / duration
```

### 2.2 不能改什么，以及为什么界面要提前说

**三种情况字段显示为灰、带原因**，不允许编辑：

| 标记 | 含义 | 例子 |
|---|---|---|
| 由上游连线决定 | 值来自另一个节点的输出 | `136.width/height` 由 `228 ResolutionSelector` 算出来 |
| 被映射覆盖 | 运行时会被 `.map.json` 的 `_rewire` / `_substitute` 顶掉 | `136.length`（接回 `224` 秒×24）；`145.lora_name`（固定为本机量化版） |
| 内置只读 | 是仓库文件，改了下次更新就没了 | 整份 `builtin-h3-minimax` |

**为什么必须标出来**：这些字段在 JSON 里是一个可改的数字，提交**照样成功**，
但值不生效。表现是「我把帧数改成 5 秒，出来的还是 10 秒」——
人不会怀疑 JSON，会怀疑整个引擎。提前说清比事后解释便宜得多。

本仓库内置工作流里就有三个这样的坑：

- `136.length = 1008`（写死的 10 秒）→ 实际由 `_rewire` 接回 `224`
- `160.steps = 33` → 本工作流的采样步数由 `147 ManualSigmas` 的固定 10 段决定，改 steps 无效
- `145.lora_name` / `234.vae_name` / `232.clip_name` → 由 `_substitute` 固定为本机量化版

### 2.3 写入的规矩

- **改内置 → 拒绝**，并提示「先复制副本」。不是懒：内置是仓库文件，改了下次更新就没了。
- **一条不合法就整体拒绝**，不留「改了一半」的工作流。
- **写盘前自动备份** `.bak_<时间戳>`，`更多 → 备份与回滚` 可回到任意一版；回滚本身也会先备份，
  所以回滚也能反悔。
- **保存映射只覆盖角色键**，`_rewire` / `_substitute` / `_steps_ineffective` 这些元信息原样继承。
  这条是硬要求：丢了 `_rewire`，帧数会被写死 1008，而界面上的映射看起来完全正常。

### 2.4 校验：用「运行时的样子」判，不是文件原值

`校验` 会做四件事：

1. 有没有输出节点（没有就白跑）
2. 节点类在本机 ComfyUI 是否存在（缺自定义节点包）
3. 必需输入是否齐全（`values` 这类动态字段组按前缀匹配，不会误报）
4. 引用的模型文件本机是否有

**关键**：校验前会先应用 `.map.json` 的 `_substitute` / `_rewire`，与 `--check` 和真跑同口径。
拿文件原值去校验会报一堆「本机没有这个模型」—— 而真跑是通的。**误报比漏报更糟**：
用户会去改一个不该改的地方，改完发现没用，从此不信校验结果。

### 2.5 不做的事

**不做节点图编辑**（拖节点、连线、加自定义节点）。理由：

- 那等于重写 ComfyUI 前端
- 画布上的线在 API 格式里是 `[node_id, slot_index]`，改完无法保证仍然合法
- 真需要改结构时，回 ComfyUI 画布改，用「导出（API）」再传上来 —— 这条路径本来就是通的

## 三、出图工作流

出图（`workflow_qwen21_t2i_hq.json` / `workflow_qwen21_edit.json`）目前**没有**对应的界面编辑入口。
改动靠替换仓库文件（`stages/assets/comfyui/`）。原因：出图工作流只有 3 个可调点（cfg /
megapixels / 批量），而它的节点映射由 `COMFYUI_NODE_*` 环境变量管，走命令行更直接。
等出图也出现「换一份工作流要对一遍映射」的需求时，再纳进来 —— 那时复用同一套 `params` / `map`。

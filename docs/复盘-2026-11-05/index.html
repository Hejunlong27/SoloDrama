一、这是什么

不是"AI 生成工具"，而是一条可重复、可审计、可回滚的短剧生产流水线。
核心设计不是"把 AI 串起来"，而是把创作与执行切开，中间只留一份文件契约。

代价是"重复解析"；收益是任何一步都能单独重跑、任一步失败都不污染上游。

四、优势与劣势

优势（有证据）

  • 契约分层：换 Skill 模板，引擎零改动（宅斗 / 甜宠两套实测）
  • 错误会说人话且说对：缺件与连不上分流，双向断言钉住
  • 门禁拦在花钱之前：预检六层判据 + 428 确认闸门
  • 任何一步能单独重跑：--only / --force / 按 kind 出图
  • 成本口径是实测拟合：27 币+1 币/秒，推出"段越碎越贵"
  • 交付规格唯一真源：crop-to-fill，绝不 pad
  • 可审计：产物 / 判定 / 耗时 / 花费全有落点，像一份工作底稿

劣势（按严重度）

  • P0 没有对白配音：H3 出的是伴随音，不是可指定的台词配音
  • P0 8G 显存定天花板：int4 + 4step 蒸馏，672×1216，参考槽 1 个
  • P1 单机串行：30 集约 25 小时/季
  • P1 模板 92s vs 交付 60–80s 档打架
  • P1 通道确认（G0）仍在命令行
  • P2 文档 3.07 万行，双真源漂移风险
  • P2 续写靠模型自律，缺机械校验

五、与前沿技术的差距

图 3　三维度评分。差距最大的不是架构，是硬件；成本控制反而是强项。

5.1 生成能力：差距最大，但主要不是工程问题

指标本项目（本地 H3 turbo 4step）2026-11 市面前沿性质
分辨率672×12161080p / 4K（Seedance 2.5、Kling 3.0、Veo 3.1）硬件（8G 显存）
单段时长4–15s4–30s，部分 2–3 分钟模型 + 显存
原生对白伴随音（不可指定台词）Kling 3.0 / Vidu 支持中文对白 + 口型产品缺口
多参考1 槽（替代工作流）最多 50 个多模态参考（Seedance 2.5）工作流（可换，但要显存）
抽卡成本￥0，但 40 倍实时按秒计费，$0.075–0.5/秒时间换钱
这五项里，只有"原生对白"必须马上补——可以外挂 TTS + 口型对齐解决，不必换模型。其余四项是"要不要花硬件钱"的商业决策，不是技术债。

5.2 调度能力：差距中等，对本场景影响被高估

能力本项目前沿托管平台对本场景影响
并发无（单机串行）多实例并发大（30 集 25 小时）
断点续跑有（--only / 退出码 3）有平
资源生命周期有（Lease auto/keep/off，跑完即停）有平（多数自建方案没有）
失败处理失败必停 + 停机自动重试中
队列 / 优先级无有小（项目制，不是 SaaS）

判断：调度差距可以靠"多开几个进程 + 分段认领"解决 80%，不需要重写成分布式系统。真正的差距在"没人愿意写那个分段认领的调度器"。

5.3 成本控制：差距最小，且有领先项

能力本项目市面普遍水平
单位成本建模修正 双模型结构对，但默认值低报 4 倍；已改为报台账实测多数只看月度账单
段粒度优化领先 已知"段越碎越贵"（固定部分摊薄）少数团队知道
计费前置确认领先 428 + confirm多数直接扣
免费优先本地 ￥0 优先，付费需显式切换少见
闲置回收reap 兜底 15 分钟托管平台自带
质量-成本联合调度缺 所有镜头同一档前沿已按镜头难度分档

差距归因（一句话）

差在"模型能不能跑得动"，不差在"流程管不管得住"。

把架构换成前沿模型，它能立刻上一个台阶；把模型换成前沿，架构不用动。
这条流水线的瓶颈在 GPU，不在架构。

六、演进建议（按性价比，不按功能诱惑）

优先级动作理由
本周加 TTS 配音 + 口型对齐这是"短剧"的定义性能力，没有它其余白干
本周加镜号连续性机械校验半天工作量，把续写从"靠模型"变成"靠检查"
本周企划阶段约束镜数 × 时长把 92s 问题挡在花钱之前
本月分段并发调度（多进程认领 + claim.json 防重）不必分布式，解决 80% 产能问题
本月质量分档（关键镜头走高配，过场走本地）30 集规模下省 30–40%
本月补 8step LoRA一个文件换回 6 个参考槽，投入产出比最高的硬件投资
本季生成能力做成可插拔后端本地 / 云 ComfyUI / 官方 API 同一接口，编排与门禁留在自己手里
本季可审计交付包（ledger + 合规报告）与审计背景最契合的差异化

七、最后一段实话

这个项目的价值不在"能生成短剧"——2026 年任何一个人用可灵都能生成。

它的价值在于：当你要交付 30 集而不是 1 条 demo 时，你需要的不是更好的模型，是一套不会静默出错的流程。

而这套流程里最贵的部分，恰恰是踩过坑修出来的东西：nodeInfoList 是覆盖表（漏槽会串景 + OOM）、SAR 59:60 是错的（平台必补边）、--only 会把台账打成 1 条、缺一个 LoRA 会被说成"连不上"、竖屏项目出横屏。

这些不是代码，是别人花钱买不到的判断。保持这个方向，比追分辨率有用得多。

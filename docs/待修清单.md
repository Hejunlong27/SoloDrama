## T1 · 成本中心看不到 LLM 花费（2026-11-02 记）

**现象**
`/api/studio/cost` 与「AI 模型中心 · 调用记录」里，LLM 调用的金额一栏永远是「未知」，
只有 token 数。一次真实剧本生成（4286 入 / 3326 出）在账上体现为 ¥0。

**为什么现在没做**
DeepSeek 的接口只返回 `usage.{prompt,completion}_tokens`，**不返回金额**。
项目的硬规则是「金额只认 `usage.cost`，不猜」（`web/core/llm/store.py::_summary` 的
`cost_note` 就是如实写「供应商未返回金额，全部为未知」）。
要显示金额就得引入**价格表**（模型 × 单价 × token），那是一条新的真源，
和「不猜金额」冲突，属于产品决定，不是 bug 修复。

**动手前先看**
- `web/core/llm/store.py`：`usage()` / `_summary()`（金额聚合与 `cost_usd_known`；原 `usage.py` 已移除、并入本文件）
- `web/core/llm/gateway.py`：`complete()` 里 `cost` 的写入位置（现在写 `{"usd": None, "source": "unknown"}`）
- `web/core/llm/store.py`：`USAGE_FILE`（`web/var/llm/usage.jsonl`）的字段
- `web/ui/studio/js/views/cost.js` 第 ~102 行、`models.js` 的 `loadUsage()`
- 现有口径：`docs/` 里「金额只认 usage.cost」的约定

**两条候选路线（选一条，别混）**
1. **价格表**：加 `configs/llm-prices.json`（`{provider: {model: {in_per_1m, out_per_1m, currency}}}`），
   `gateway.complete()` 在拿到 usage 后按表算出 `cost.usd` 并写 `source: "price_table:<ver>"`。
   价格表要**带版本与生效日期**，改价不改历史账。
2. **只显示 token，不显示金额**：把成本中心的「金额」列换成「按量计费（供应商未给金额）」，
   并在页面上明确「LLM 花费请到供应商后台看」。改动小，但用户得去两个地方对数。

**验收标准**
- 任一历史调用在成本中心能显示「已知 / 未知」两种状态，未知的不能显示成 ¥0；
- 价格表缺失时**不许**回退成 0 或编一个默认价（沿用现在的 `cost_note` 口径）；
- 给 LLM 网关补一例测试（放在 `web/tests/` 下，尚未创建）：无价格表 → `usd=None`、`cost_records=0`；有价格表 → 金额可复算。

## T2 · RunningHub `status` 通道的字段名始终没实测（2026-11-06 记）

**现状**
`stages/video/workflow/scripts/engine/runninghub_client.py::query_status_v1` 对
`taskStatus / task_status / status / state` 与 `fileList / results / outputs` 做了**候选容错**，
注释里明写「字段名未实测」。这条是 `/openapi/v2/query` 不可用时的**兜底通道**
（`_v2_route_missing` 命中才会走到）。

**已做的防御（2026-11-06）**
解析不到状态时**直接抛错**并打印响应里实际有的键，而不是返回 None。
旧行为会被外层当成「还在排队」，一路轮询到超时，真因被彻底盖住。

**怎么收口（一次小样即可）**
1. 配好 Key 与站点，跑 `drama video rh.sample`（1 段小样，★计费）；
2. 把 `runninghub_client.py` 打出的「响应顶层键 / data 键」贴回来；
3. 按真实结构收紧候选表（只留实测存在的字段），删掉这段注释与本节。

**判据**
把候选表改成真实字段后，小样任务能在 1 次轮询内被判为 SUCCESS，且 `results` 里有产物 URL。

### 3.1 强调色：严格采用规范值，代价已确认

2.0 指令给定浅色强调色 `#9B7145`。实测：白底 **4.34:1**、`#EFECE5` 底 3.51:1，**不达 AA 正文（4.5）**。

处置（2026-11-10 用户确认：「严格，保持新版」）：

- `--sd-accent: #9B7145` —— **按规范值原样使用**，不做降深。
- 把更深一档 `#8A6439`（白底 5.30:1）留给**必须达 AA** 的场合：小字号金色文字、正文内可点击强调。
- 浅色下主按钮为 `#9B7145` 底 + 白字 = **4.34:1**，属「已知不足 AA」的有意取舍，记录在此，不再反复改动。

红线：**不得**为了提对比度把 `--sd-accent` 改回 `#8A6439`（那是把用户拍板的品牌色再改一次）；需要更强对比时只加 `--sd-accent-strong`。

## 4. 强调色使用纪律（比色值更重要）

香槟金是**稀缺资源**。同屏出现超过 3 处金色 = 品牌失效。

| 允许 | 禁止 |
|---|---|
| 品牌标志、当前导航选中项 | 所有链接都上金色 |
| 每个视图**唯一**主按钮 | 每个卡片一个金色按钮 |
| 计费 / 风险提示的图标与描边 | 用金色表达"好看" |
| 关键数字（成本、进度） | 用金色表达"次要信息" |

**"花钱"语义继承**：旧系统里琥珀兼任「品牌 + 要花钱」。2.0 保留这个语义合并，但改由 `--sd-warn` + 金色图标共同表达，且**必须带文字说明**（「本次预计 ¥2.40」），不靠颜色单独传达。

## 5. 状态色语义（固定，不许自造）

| 状态 | 色 | 配套标记 |
|---|---|---|
| 通过 / 已完成 | `--sd-ok` | 实心圆点 |
| 进行中 / 实时 | `--sd-teal` | 呼吸圆点（见动效） |
| 待办 / 未开始 | `--sd-text-3` | 空心圆点 |
| 被上游阻塞 | `--sd-warn` | 斜线圆点 + 文案「上游未通过：…」 |
| 失败 | `--sd-danger` | 叉形圆点 + 退出码 |
| 只读 | `--sd-info` | 文本徽标「只读模式」 |

六态与 `nodes.py` 的 `passed/failed/blocked/absent/skipped/stale` 一一对应，**UI 不得另立状态名**。

### 5.1 状态色必须分两档：图形档 / 文字档

同一个语义色，用在「描边、圆点、实心块」和用在「淡色底上的文字」，对比度要求不一样（3:1 vs 4.5:1）。
浅色主题里淡底会把颜色视觉上「抬亮」，只用一个值必然有一处不达标 —— 这是实测出来的，不是推演：

| 语义 | 图形档（3:1） | 文字档（4.5:1） | 淡底上不分的实测 |
|---|---|---|---|
| 通过 | `--sd-ok` `#72B89A` / `#2F7A50` | `--sd-ok-ink` `#72B89A` / `#22693F` | 浅色 **3.91** ⇒ 改文字档后 **4.97** |
| 实时 | `--sd-teal` `#78A9A4` / `#3F7F79` | `--sd-teal-ink` `#78A9A4` / `#2A6A64` | 浅色 **3.60** ⇒ **4.86** |
| 告警 | `--sd-warn` `#E0A45D` / `#8A6320` | `--sd-warn-ink` `#E0A45D` / `#7A5518` | 浅色 **3.46** ⇒ **5.34** |
| 失败 | `--sd-danger` `#D87979` / `#A63D33` | `--sd-danger-ink` `#D87979` / `#8E322A` | 浅色 **4.59** ⇒ **5.81** |
| 提示 | `--sd-info` `#8FA3BF` / `#4A5C77` | `--sd-info-ink` `#8FA3BF` / `#3A4A61` | 深色主题两者相同 |

深色主题下两档取值相同（淡底不会抬亮），所以 `-ink` 在 `:root` 里直接指向对应基色，只在浅色块里覆盖。
用法：**文字 → `-ink`；圆点/描边/实心块 → 基色**。

## 6. 旧色值迁移（已完成，2026-11-10）

`app.css` 原有 72 处硬编码色值，清理规则只有四条：

| 类别 | 旧写法 | 新写法 |
|---|---|---|
| 旧状态色 | `rgba(86,181,127,.3)` `rgba(79,179,199,.55)` `rgba(217,105,94,.4)` `rgba(139,127,245,.65)` | `color-mix(in oklab, var(--sd-ok/--sd-teal/--sd-danger) 30%, transparent)` |
| 白/黑遮罩 | `rgba(255,255,255,.05)` `rgba(0,0,0,.15)` | `color-mix(in oklab, var(--sd-text) 5%, transparent)` —— **必须跟文字色走**，否则浅色下白色叠加等于不可见 |
| 固定底色 | `#1d222a` `#1a1a26` `#16202a` `#c2cbd8` `#f0d3a9` 等 | `--sd-surface-2` / `--sd-teal` 混合 / `--sd-text-2` / `--sd-text` |
| 阴影 | `0 16px 44px rgba(0,0,0,.46)` | `--sd-shadow-3` / `--sd-shadow-2` / `--sd-inset-line` |

结果：**生效中的硬编码 = 1 处**（`.video-box video { background: #000 }`，视频黑边属于画面内容，与主题无关，故意保留）。
注释里仍留有历史色值说明（如「原来是陶土 `#c96442`」），那是迁移记录，不参与渲染。

**派生透明度一律用 `color-mix(in oklab, var(--sd-x) N%, transparent)`**，不要为每个透明度再开一个 Token —— 那会回到「72 处硬编码」的老路。

## 7. 主题切换机制

```html
<html data-theme="dark">   <!-- 或 "light" -->
```

- 默认值：跟随系统 `prefers-color-scheme`（首帧前由 `<head>` 内联脚本写入，防闪白）。
- 用户显式选择存 `localStorage.sd-theme ∈ auto|dark|light`。
- `color-scheme` 同步声明，让原生控件（滚动条、日期选择器）跟随。
- **不提供"半透明磨砂"层**：`backdrop-filter` 在深底上会与画面内容抢注意力，且在中低端笔记本 GPU 上掉帧。

## 8. 验收

1. 深浅两套下，所有正文/次要/元信息对比度 ≥ 4.5:1（脚本实测，不靠眼估）。
2. 浅色下不出现「深底白字卡片」（说明有硬编码漏网）。
3. 同屏金色元素 ≤ 3 处。
4. 切换主题不闪白、不重排（截图对比布局位置一致）。

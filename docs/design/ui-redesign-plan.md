# UI 重设计方案（Phase 3–4 执行蓝本）

> 原则：**每页有自己的内容组织方式，但共用同一套设计系统。**
> 所有数据源均为**已存在**的端点（见 `docs/architecture/current-api.md`）。标注 `[新]` 的是 Queue 4 才补的两个后端能力。
>
> **落地状态（2026-11-10）**：§0 全局框架、§1 Studio 首页、§3 项目驾驶舱 已完成；§6 分镜工作室的「提示词」部分已完成（六段式编辑 + 真规则校验），三栏布局仍待做。
> 首页额外补了一个只读端点 `/api/studio/cover`（挑海报图），原计划里没有它 —— 见 §1 注。

## 1. Studio 首页

**回答一个问题：我该继续做哪一步。**

| 区块 | 内容 | 数据源 |
|---|---|---|
| 继续创作 | 最近 6 个项目，大海报卡（2:3）+ 当前项目标阶段角标 | `/api/workspaces` `/api/studio/cover` **[新]** |
| 新建项目 | 单一入口卡（虚线描边，不用实心按钮堆） | `POST /api/projects/create` |
| 最近任务 | 5 条：类型 / 状态 / 耗时 / 结果 | `/api/jobs` |
| 通道状态 | 三通道灯：LLM / 本地 ComfyUI / RunningHub | `/api/connections` `/api/comfy/status` |
| 成本摘要 | 本月时间与钱两个数，标注来源 | `/api/studio/cost` |

**不做**：统计卡片墙（「共 12 个项目」这类数字对决策零价值）。
**空状态**：无项目时整屏变成「三步开始」引导，不显示一排空卡片。

## 2. 项目管理

- 视图切换：海报网格（默认）/ 紧凑列表。切换状态存本地。
- 卡片：封面（缺图 → 场记板占位）、剧名（衬线）、集数、当前阶段、最后更新时间、发布版数量。
- 排序：最近更新（默认）/ 名称 / 完成度。
- 操作：打开、在文件管理器显示、重新扫描。删除**不做**（要删去资源管理器，产品不提供）。

| 区块 | 数据源 |
|---|---|
| 阶段矩阵 | `/api/studio/workflow`（`nodes[]` 的 `id/stage/state/detail` + `stages[]` 的 `id/name/why`） |

## 4. AI 创作中心

三栏，**不是聊天窗口**：

```
┌ 创作任务 ┬─────────── 正文编辑区 ───────────┬ 参数与上下文 ┐
│ 灵感      │  Markdown 编辑（等宽可选）      │ 用途路由     │
│ 企划案    │  工具条：保存 / 预览 / 对比版本 │ 模型         │
│ 世界观    │                                 │ 关联资产     │
│ 角色      │                                 │ 历史版本     │
│ 分集剧本  │                                 │              │
└──────────┴─────────────────────────────────┴──────────────┘
```

| 能力 | 数据源 | 约束 |
|---|---|---|
| 读/写文档 | `/api/create/read` `/api/create/write` | **仍是 Markdown 落盘**，不转数据库 |
| 生成 | `/api/create/generate` | 生成结果进草稿区，用户点「确认落盘」才写 |
| 模板 | `/api/skills/*` | 装/卸模板不改项目数据 |
| 模型路由 | `/api/llm/purposes` | 显示「这个用途用哪个模型、花了多少 token」 |

**不做**：把 AI 输出直接当正文（那会毁掉用户的版本管理）。

> **落地状态（2026-11-10）**：三栏已实现。三处与上面草稿不同，都以真实代码为准：
>
> 1. **左栏不是「世界观 / 角色」，是四类真实产物**：企划案 / 资产库 / 分集剧本 / 导演手册（× N 集）。
>    `web/core/creation.py::STAGES` 只有这四类，没有「世界观」「角色」两个独立文档 ——
>    角色与场景写在 `02-资产库.md` 里。按方案画五个入口，等于给用户三个空文档。
> 2. **生成直接落盘，没有草稿区**。`POST /api/create/generate` 内部就调 `write()`，
>    并先备份 `.bak_<时间戳>`。草稿区要后端加一层暂存，属后续能力，不在 UI 层伪造。
> 3. **没有版本对比界面**。备份文件在磁盘上（`01-企划案.bak_<时间戳>.md`），但当前没有浏览/比对的入口。
>    这是这一页最明确的缺口，见 `docs/architecture/technical-debt.md`。

## 5. 视觉资产中心

> **落地状态（2026-11-10）· 角色档案**：#5 的「视觉化资产库」先落地了最要紧的一块 ——
> **同一角色的多套穿搭 / 时期归并成一张档案卡**。
>
> 依据是磁盘上已有的结构，不是新发明的东西：引擎早就把变体编码成 `P01@LOOK-B`，
> 产物名也是 `P01_Elena_LOOK-B_00.png`，层别（`turnaround/look/expression/state`）
> 在 `pack_spec.VARIANT_KINDS` 里就有。缺的只是「按角色聚起来读」。
>
> ```
> ┌ P01  Elena                    5/5 变体 · 5 图 ┐
> │ 24 岁，庄园佣人                                │
> │ 一致性锚点 ① 左肩疤 ② 右手茧 ③ 黑绳          │
> │ 三视图   1/1  [VIEW]                          │
> │ 造型     3/3  [LOOK-A] [LOOK-B] [LOOK-C]      │
> │ 表情     1/1  [EXP]                           │
> └────────────────────────────────────────────────┘
> ```
>
> 三个决定：
> 1. **不新增数据结构**：档案是派生视图（`GET /api/studio/characters`），
>    只读资产库 md + `04-资产/characters` + `refs.json`，不落盘、不建索引。
> 2. **不猜融合**：`VIEW` 在新规范里已含四宫格表情；旧项目的 `EXP` 是独立竖图。
>    两者都显示，不自动删 EXP —— 那是内容改动，交给人决定。
> 3. **图上直接标 `LOOK-B`**：那个 code 就是出片参考图的 key（`P01@LOOK-B`）。
>    档案不只是"看"，它是选参考图的地方。
>
> **2026-11-10 二次修订（用户定的形态）**：改成「一个角色一个框」——
> 框内上方是主形象大图（可滚动），下方一排**文字 tab** 切变体（★ 主形象、缺图标灰）。
> 三个理由：一屏能看清这个人长什么样；变体 code 本来就要读（它就是参考图 key）；
> 扫视时是「数人头」而不是「数图」。
>
> 同时把资产分类收敛为**只有角色 / 场景 / 道具**三类真实素材：
> `06-提示词/refs_h3` 是 `prepare_refs.py` 的瘦身副本（长边≤2048/JPEG），
> 把派生物做成并列分类会让同一张图出现两次、改原图副本也不更新；
> 「散图」是没归位的图，是待办不是类别。两者降级为诊断入口。
>
> 还没做的：场景 / 道具的档案化、按集过滤「这集用了哪几套造型」。
>
> **变体单张重出（2026-11-10 已完成）**：变体图区一行里加「重出这一张」。
> 走引擎既有的 `--only <key> --force --backup`，只重跑这一张；通道读
> `GET /api/studio/image-channel`（真源 `model-plan.json`），**不由界面选** ——
> 自定默认值会与确认单打架，被门禁拦成退出码 4，用户只看到「按钮没反应」。
> 旧图先备份到 `<目录>/_bak/<原名>.<ts>.bak`（`.bak` 后缀是必须的：
> `_scan_asset_images` 是 rglob，`.png` 备份会和真产物抢参考图）。
> 同轮发现并修掉一个阻断：`assets_from_pack()` 原本对 `rep.ok` 全量判断，
> 30 集旧格式提示词让 `SHOT019/020` 全红 → **任何项目都出不了资产图**。
> 现按错误码分级：资产级（PACK/ASSET/STYLE）阻断，分镜级（SHOT0xx）只打印。
>
> 还没做的：场景 / 道具的变体重出、备份的一键找回（现在要手动去掉 `.bak`）。

- 顶部：类型筛选（角色/场景/道具/服装/风格）+ 搜索 + 网格/列表切换 + 缺口提示。
- 网格：4:5 或 1:1 缩略图，悬停显示变体数与「被哪些镜头引用」。
- 详情抽屉：大图 + 提示词 + 变体列表 + 引用镜号 + 版本历史。
- 角色详情做成**角色档案页**：六维签名、外观锚点、出场集数；场景做成**美术设定集页**。
- 缺口：`/api/studio/asset-md` 的「声明了但没图」必须有独立入口，而不是混在正常资产里。

**纪律**：落点走 `studio.assets_dir(ws)`；`04-资产/{characters,scenes,props}` 是引擎口径，前端不拼。

## 6. 分镜工作室（最高优先级）

```
┌ 结构 ┬──────── 画布 / 预览 ────────┬ 属性面板 ┐
│ 集   │  [分镜图 9:16 大图]         │ 六段式   │
│ 场   │  上一镜 / 下一镜 / 播放     │ 提示词   │
│ 镜列表│                            │ 角色场景 │
├──────┴────────────────────────────┴─────────┤
│ 底部：镜头序列（缩略图条）+ 生产状态          │
└─────────────────────────────────────────────┘
```

| 区域 | 数据源 | 2.0 组件 |
|---|---|---|
| 镜列表 | `/api/studio/shots?ep=` | `.sd-row`（状态点 + 单行镜头号） |
| 画布 | `/media`（`final.mp4`） | `.sd-stage` / `.sd-video`，9:16 居中 + 细边线 |
| 提示词 | `GET /api/studio/prompt?ep=` | `.sd-p-text`（**整段** textarea）+ `.sd-p-secs` 只读结构 chip |
| 即时校验 | `POST /api/studio/prompt` | `.sd-lintbar` 摘要 + `.sd-lintbody` 展开，带 `H3-Exx` 编码 |
| 生产状态 | `/api/studio/workflow` | `.sd-stages` 局部切片 |

> **落地状态（2026-11-10）**：三栏布局、整段提示词编辑、校验摘要全部完成。
> 两处与最初方案不同，都是实测/用户裁决后的改动：
>
> 1. **提示词不拆段**。原方案用 `.sd-prompt-sec` 逐段编辑，实测使用后发现：
>    真实用法是把整段贴到模型里试，拆开之后每次都要自己拼回去。改为一个 textarea 装完整原文，
>    结构只做只读 chip 概览（缺段标红）。分段样式只留给 `design.html` 的结构对照。
> 2. **底部镜头序列条没做**。画布已能上一镜/下一镜，左侧列表本身就是序列；
>    再加一条缩略图条要额外拉 183 张缩略图，首屏代价大于收益。
>    真需要「一眼看全序列」时，正解是给列表加缩略图密度切换，而不是底部再放一份。

**校验必须调真规则**：`h3_prompt.normalize()` → `lint()` → `prompt_marks.find_bare()`，返回 `SHOT018/019/020/021`。前端不得自写正则做「假检查」。

## 7. 视频生产中心

- 上半：队列（待跑/在跑/失败），每行显示镜号、通道、模型、预计耗时、预计费用。
- 下半：结果预览墙（视频缩略图 + 时长 + 分辨率）。
- 右侧：本次批量参数（通道、模型、并发、是否续跑）。

**铁律**（与 CLI 同一套门禁）：
1. 默认通道 = 本地（¥0）。切云端需显式点选，且**不记忆**上次的付费选择。
2. 未过预检不许提交；未确认计费不许提交。
3. 失败退出码 3 → 显示「批次缺口 N 镜」并给 `--resume`，不显示「重试」。

## 8. 统一任务中心

| 列 | 内容 |

| 状态 | 六态点 + 文字 |

**不做**：把「取消」放在悬停才出现的图标里——取消是安全阀，必须始终可见。

## 9. 模型与通道管理

- 左：通道列表（LLM 供应商 / 本地 ComfyUI / RunningHub），右侧详情。
- 密钥只显示指纹（末 4 位 + 长度），永不回显明文。
- 每个通道一个「测试」按钮，5 秒超时，结论分四类：地址错 / Key 错 / 模型名错 / 额度不足。
- 工作流：列表 + 参数映射 + 校验 + 备份/还原（写操作要二次确认）。

拆 `connections.js`（945 行）为三个子组件后再动视觉（T7）。

## 10. 成本中心

两栏并置，永不合并：

```
时间（唯一稀缺）              钱（只在使用平台通道时非零）
本集 1h16m                    本集 ¥2.40（实付）
单镜均值 96.4s（12 次样本）   整季预计 ¥28.80（估算）
瓶颈：出片 78%                平台任务 12 次
```

**纪律**：金额总数只取 `inventory.spend`（按 taskId 去重）；`estimate.confidence` 必须显示（`measured`/`estimated`），不许把经验系数当实测。

## 11. 后期与发行

按集组织的流水线卡：

```
ep01  [母版✓] [放大✓] [字幕✓] [剪映工程✓] [发布版 ✓ Episode01.mp4]
ep02  [母版✓] [放大✓] [字幕✗] [剪映工程—] [发布版 —]   ← 卡在字幕
```

- 导出：只给「预览（干跑）」与「导出发布版（唯一出口）」两个按钮，后者必须展示将导出哪几集、被哪些门禁拦下。
- 版权资料：三入口 A/B/C 平铺，缺字段显示「待用户提供」，**不自动编造主体名/注册号**。
- 封面：只做「是否齐/规格是否对」校验，不提供生成（引擎侧已移除）。

## 12. 每页验收清单

| 检查 | 判据 |
|---|---|
| 数据真实 | 每个数字能追到接口字段 |
| 无假按钮 | 可点元素都有真实行为或明确禁用理由 |
| 三态齐 | 空/错/载都有，文案带下一步 |
| 门禁一致 | 与 CLI 同一判据；`rc=2` 显示为「缺 N 项」 |
| 深浅双主题 | 各自单独看成立 |
| 响应式 | 1440 / 1280 / 1024 / 768 四档不错位 |

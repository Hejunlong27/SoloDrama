# 画风库规范（形态 · 视觉 · 叙事 · 通道）

> 取代原《画风三轨规范》。旧文档把「形态 / 题材风格 / 叙事模式」三件事压进同一个 `sub_modes`
> 字典，换一个 look 会连带换掉资产规格与交付终点 —— 这就是「画风库和 3D/2D/真人半解说串在一起」
> 的根因。现在拆成四个正交维度，**改哪一维只影响哪一维**。

---

## 零、一句话

**画风不是一个选项，是四个维度。** 换 `look` 只换一串 prompt，资产可复用；
换 `track` 才动资产规格、单镜时长、分镜拓扑与交付终点。

---

## 一、四个维度

| 维度 | 真源 | 回答什么 | **禁止**承载 |
|---|---|---|---|
| **形态** `track` | `configs/tracks.json` | 单镜时长、资产规格、首帧锚、分镜拓扑、交付终点、渲染流菜单 | 题材风格 prompt |
| **视觉** `look` | `configs/looks.json` | 画面长什么样（纯 prompt + 标签） | `track` / `narrative` / `delivery_stop` / `narration_*` |
| **叙事** `narrative` | `configs/narratives.json` | 旁白配额、台词密度 | 任何视觉描述 |
| **通道** `channel` | `configs/channels.json` + `configs/capabilities/*.json` | 用哪条引擎（本地 / RH）、站点、工作流 ID | 任何画风信息 |

`looks.json` 的禁用字段由测试强制（`tests/test_style_gate.py` 的「look 不得承载轨道/叙事」），
不是口头约定。出现即失败。

### 1.1 形态（track）现在只有三条，但它们**不含题材**

| id | 名称 | 单镜 | 资产 | 首帧锚 | 分镜拓扑 | 交付终点 |
|---|---|---|---|---|---|---|
| `3d_manhua` | 3D 漫剧 | 6–10 s | 角色主卡 + 三视图；场景主卡 + 辅卡 | 强制，且角度必须匹配 | 一镜一张单帧 | 成片 |
| `2d_animation` | 2D 动画 | 4–10 s | 角色主卡；场景主卡 | 可选 | 一镜一张单帧 | 成片 |
| `live_action` | 真人写实 | 5–15 s | 角色主卡；场景主卡（绝对无人物） | 可选 | 一镜一张单帧 | 成片 |

轨道内的 `render_styles` 只放**渲染手法**（`guoman-3d-render` / `cel-anime` / …），
不放题材（`surreal-cinema` / `ink-wash-2d` 那类）。题材在 `looks.json`。

### 1.2 视觉（look）是跨轨的风格库

**共 13 条**，`surreal-cinema`（电影超现实）、`cel-shading`（日式赛璐璐）这些都在库里，
prompt 保持原始表述未改写。`recommended_for` 只是**推荐**，不是限制 ——
同一条 `surreal-cinema` 可以在三条轨上都设进去，这正是拆维度的验收标准（V0.7.32 已实测通过）。

| id | 名称 | 标签 | 来源 | 推荐轨 |
|---|---|---|---|---|
| `surreal-cinema` | 电影超现实 | 真人/超现实/文艺 | 官方 | live_action |
| `cinematic` | 电影超写实 | 真人/写实/电影感 | 官方 | live_action |
| `magical-realism` | 拉美魔幻现实 | 真人/魔幻/文艺 | 官方 | live_action |
| `jp-youth-film` | 日式青春胶片 | 真人/胶片/怀旧 | 官方 | live_action |
| `short-form-drama` | 短剧风格 | 真人/短剧/强情绪 | 官方 | live_action |
| `cel-shading` | 日式赛璐璐 | 二维/动画/赛璐璐 | 官方 | 2d_animation |
| `cn-anime-style` | 国漫二次元常用风格 | 二维/国漫/插画感 | 官方 | 2d_animation |
| `guoman-xianxia` | 国漫仙侠 | 仙侠/东方/玄幻 | 本地 | — |
| `urban-entitled-3d` | 都市豪门 | 都市/豪门/情感 | 本地 | — |
| `suspense-noir` | 悬疑暗调 | 悬疑/暗调/犯罪 | 本地 | — |

> 会被 `tests/test_style_gate.py` 的边界判据挡下。

### 1.2.1 渲染流（render_style）——**不是**风格库，别混

渲染流是「这条轨用哪种画法」，只能属于某一条轨；它和 look 是**拼装关系**，不是二选一：

| 轨道 | 渲染流 id | 名称 | 说明 |
|---|---|---|---|
| `3d_manhua` | guoman-3d-render | 国漫 3D 渲染流（默认） | 默认 |
| `3d_manhua` | pixar-disney | 皮克斯 Disney 流 |  |
| `3d_manhua` | semi-painterly-3d | 半厚涂 3D 写实流 |  |
| `2d_animation` | guoman-webtoon | 国漫 webtoon 流（默认） | 默认 |
| `2d_animation` | cel-anime | 日漫赛璐珞流 |  |
| `2d_animation` | light-color-webtoon | 轻彩漫 webtoon 流 |  |

拼装：`style_prompt = look.prompt + 该轨选中渲染流.prompt`。
真人轨没有渲染流，`style_prompt` 就等于 `look.prompt`。

### 1.3 叙事（narrative）默认对白驱动

| id | 名称 | 旁白/集 | 旁白总时长 | 台词密度 |
|---|---|---|---|---|
| `dialogue` | 对白驱动（**默认**） | ≤2 条 | ≤8 s | ≥10 句 / 60 s |
| `narration` | 旁白驱动（旧模式，非默认） | 不限 | 不限 | 0 |

对白驱动是 2026-10-28 的定稿。`narration` 保留但不再作为默认，
因为「旁白解说太单调」是当时的裁决理由。

## 二、怎么组合

```
style_prompt = look.prompt  +  track.render_styles[选中项].prompt
spec         = merge_spec(track, narrative)
```

- 真人轨没有 `render_styles`，`style_prompt` 就等于 `look.prompt`。
- `spec` 是 `style-plan.json` 里那个 `spec` 字段的来源：形态给时长/资产/拓扑/交付，
  叙事给旁白配额与台词密度。两者合并后**整集共用一份**，逐镜不再各自解释。

## 三、锁定时机

画风**必须在开工前确认，事后不可更换**。理由不是流程洁癖，是三个实打实的后果：

1. **资产作废**：换 `track` 改变三视图/辅卡要求，已出的角色卡与场景卡全部不符合新规格。
2. **提示词作废**：`style_prompt` 变了，已生成的 `h3_prompts.json` 里的风格块就是错的。
3. **成片不可混**：同一集里出现两种画风，平台判定为拼接内容。

门禁：`drama style require` 未确认时返回**退出码 4**（与 `model_gate` 的「等待用户确认」一致），
不是 2（硬失败）—— 它等的是人，不是等修 bug。

确认单落两处，`drama.json` 是真源、`style-plan.json` 是过渡期兼容：

```
<ws>/drama.json        format{track, look, narrative, aspect}
<ws>/style-plan.json   style{choice, look, narrative, sub_mode, spec, confirmed_at}
```

## 四、命令

```bash
drama style list                                    # 四维清单（轨道 / look / 叙事）
drama style set live_action --look surreal-cinema   # 换 look，资产不动
drama style set 3d_manhua --look guoman-xianxia --sub-mode guoman-3d-render
drama style set live_action --narrative narration   # 仅当确有旁白
drama style status                                  # 当前四维 + 合并后的 spec
drama style reset                                   # 撤销确认（改画风前必须）
drama style require                                 # 门禁：未确认返回 4
```

`--look` 可省略，但状态里会明确写「未指定 look」—— 空着等于让模型自己猜题材，不推荐。

## 五、常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 把「3D / 2D / 真人」当成画风 | 想换风格就得换轨道，资产跟着全部重做 | 换题材只换 `look` |
| 认为 look 绑死轨道 | 看到 `recommended_for: live_action` 就不敢用在水墨 2D 上 | 推荐不是限制，跨轨可用 |
| 改 look 期待改资产规格 | 规格在 `track`，改 look 只会改画面质感 | 要改规格就改 `tracks.json` 并重出资产 |
| 用 narrative 表达「风格」 | 旁白配额与视觉无关，混用会让两条判据互相干扰 | 视觉进 look，节奏进 narrative |
| 把站点/工作流 ID 写进 look | 换机器就失效，且同一 look 在不同通道表现不一致 | 通道在 `channels.json` / 能力卡 |

## 六、与旧文档的差异（旧文档已删除）

旧的《画风三轨规范》是「三轨 = 形态 + 题材 + 半解说叙事」三合一。逐条对照：

| 旧口径 | 现口径 |
|---|---|
| `sub_modes` 里既有 `guoman-3d-render`（渲染流）又有 `surreal-cinema`（题材） | 渲染流留 `tracks.json`，题材迁 `looks.json`，两者拼装使用 |
| 2D 交付止于「旁白交接」 | 2D 也是短剧，交付到成片 |
| 真人轨强制「1 片段 = 1 张三格时间分镜」 | 改为一镜一张单帧（三格拼版是实测雷同的源头） |
| `storyboard.json` + `half_narrated_check.py` 三类硬校验 | 分镜契约为 md 的 5 字段（见 `convert_storyboard.py`）；旁白配额进 `narratives.json` |
| 画风三轨「唯一真源」 | 四维各有真源，本文只描述它们如何组合 |

> ⚠ 遗留：`stages/production/scripts/half_narrated_check.py` 仍读 `05-分镜/storyboard.json`，
> 而该文件**当前无生成器**，因此这条校验不在主链路上（`drama halfcheck` 可调，但不会通过）。
> 它的去留（改造为读 md，或删除）待定，不在本次整改范围。

## 七、相关文件

| 文件 | 作用 |
|---|---|
| `configs/tracks.json` | 形态真源（含 `default`，新建项目默认取它，不取 `order[0]`） |
| `configs/looks.json` | 视觉真源（禁止轨道/叙事字段） |
| `configs/narratives.json` | 叙事真源 |
| `configs/channels.json` | 通道站点真源 |
| `configs/capabilities/*.json` | 通道能力卡（工作流 ID / 节点映射 / 已知坑） |
| `stages/production/scripts/style_gate.py` | 门禁与合并逻辑（`merge_spec` / `compose_style_prompt`） |
| `stages/production/scripts/drama_profile.py` | `drama.json` 读写唯一实现 |

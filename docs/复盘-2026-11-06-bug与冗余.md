## 1. 已修（本轮，含复现证据）

### B1 · `drama video plan --save-calibration` 必然 NameError（P0）

```
$ drama video plan --save-calibration
  File "drama.py", line 1091, in cmd_video_plan
    if cal and cal.get('fitted'):
NameError: name 'cal' is not defined
```

- **根因**：`cmd_video_plan` 读一个从未赋值的局部变量 `cal`；校准结果实际挂在
  `estimate_video()` 返回值的 `est['_calibrate']` 上。
- **为什么一直没被发现**：这条命令写在它自己的 `--help` 和 VERSIONS（V0.7.64）里，
  但单测只覆盖 `cost_model` 的纯函数，**没有任何用例真的把它跑起来**。
- **修法**：读 `est.get('_calibrate')`；另加分支——只给 `--save-calibration` 不给
  `--calibrate` 时明确提示两者要一起用（原来这种情况会静默走「样本不足」的 WARN，误导）。
- **守卫**：新增 `stages/production/scripts/tests/test_video_plan.py`（3 例，子进程真跑，
  判据是「退出码 0 且输出里没有 Traceback」）。

### B2 · 出图默认工作流有两套真源，指向**不同文件**（P0）

| 位置 | 指向 | 版本 |
|---|---|---|
| 执行器 `comfy_client.DEFAULT_WORKFLOW` | `workflow_qwen21_t2i_hq.json` | 11-02（turbo 融合，无 LoRA） |
| 预配置卡 `configs/presets/*.json → t2i` | `workflow_qwen21_t2i_hq.json` | 同上 |
| 界面 `generators.IMAGE_LOCAL_WF` | `workflow_qwen_image21.json` | 10-16（int8 + 4step LoRA） |

  让人去删告警，要么全绿而真跑缺件。和视频侧 2026-11-05 那次「核 A 跑 B」是同一个坑的另一半。
- **修法**：界面与预检改成 `workflow_qwen21_t2i_hq.json`（以执行器为准；预配置卡与
  `configs/capabilities/comfy.qwen21_t2i_hq.v1.json` 都指它，方向不会有歧义）。

  三处文件名必须相同，且预配置卡的 `t2i` 也要指同一份。
- **副作用**：`workflow_qwen_image21.json` 从此没有代码引用（仅 `settings.example.json`
  的注释文字提到）。**没删** —— 老项目的确认单里可能还记着它，删了会让那些项目打不开。

## 2. 待修（P1，静默做错事）

### B3 · `--resume` / `--concurrency` 在 local/cloud 通道被静默忽略 —— **已修（V0.7.70）**

- **现象**：`video run` 是**一个** parser，`--engine` 决定分支。但这两个参数只在
  RunningHub 分支被拼进 argv（`drama.py` `cmd_video_run_rh`）；`cmd_video_local` → `_run_batch`
  根本不传，`comfy_batch_video.py` 也没有 `--resume`。
- **为什么算 bug**：`cmd_video_plan` 的结尾文案在教用户
  「续跑同一批次（不重复扣费）：`video run --yes --resume <批次>`」——
  在默认（local）通道上，这句话是假的：参数被吃掉，批次号无效。
- **现状**：本轮已加**显式提示**（进 `cmd_video_local` 就打印「这两个参数只对 RH 生效；
  本机/云端的续跑 = 重跑同一条命令」）。**没有改行为** —— 因为 local 的「续跑」语义本来
  就是跳过已有产物，直接重跑即可。
- **建议下一步**：要么把提示降级成真实现（`--resume` 在 local 上等价于不带 `--force` 重跑，
  静默接受），要么在 argparse 层按 `--engine` 分叉、直接报错。二选一，别维持「接受但忽略」。

### B4 · RunningHub 轮询字段名未实测 —— **已加防御 + 转记 T2（V0.7.70）**

`stages/video/workflow/scripts/engine/runninghub_client.py:381`

```python
⚠️ TODO 字段名未实测。这里对 taskStatus / status / task_status，以及 …
```

- 三选一的兼容写法，说明作者当时没有拿到确定响应。RH 通道现在是「用户暂缓」状态，
  所以它**不是当下风险**；但哪天真要用，第一次提交就可能因为读错字段卡在「永远 pending」。
- **建议**：RH 恢复使用前，先用 `video.rh.sample`（1 段小样）跑一次，把真实响应结构
  记进该文件；在那之前把这条留在 `docs/待修清单.md` 里，别只写在代码注释。

避免下一个人以为两条链都要维护。

### R3 · 花费聚合有 4 套实现 —— **已收敛到 inventory（V0.7.70）**

`inventory.py`（按 taskId 去重聚合）、`studio.py`（按环节/集聚合 + 自己再写一遍汇率）、
`ux.py`（`spent_summary` 再包一层）、`ui.js`（前端再算一次）。同一个「花了多少钱」在
四个地方算，任何一处口径变动都会让两个页面数字不同。**建议**：只保留 `inventory`
作为唯一聚合层，其余三处改成读它的字段。

### R4 · 21 份题材模板 80% 是重复行

```
21 份 / 167,300 字符 / 6,592 行 → 去重后 1,321 行（重复率 80%）
```

模板是**给模型看的独立文件**（每份都要能单独灌进 prompt），所以重复本身是设计选择，
不是失误。但代价很实：改一条通用规则（今天刚改过 `<d>` 台词写法）要动 21 个文件、
21 处示例，漏一个就回到旧写法。
**建议**：抽一份 `_common.md`（骨架 + 硬规则），21 份只保留各自的人设/场景/示例；
组装时 `skills.compose_prompt()` 拼起来。**这会改变模板的加载方式，属于架构级改动，需你点头。**

### R5 · `video.local` 与 `video.run` 功能重叠 —— **已划清边界（V0.7.70）**

- `video.local` = `comfy_local_video.py` 直调（单镜调试，参数是提示词/参考图/秒数）
- `video.run --engine local` = 批次（按集、走 model_gate、写台账）

两者都能「出一段视频」，但前者**不过模型门禁**（`model_gate` 在 `drama.py` 里调，直调脚本绕开），
且它的占位文案还写着早已不是默认的 `workflow_h3_local.json`（本轮已改）。
**建议**：把 `video.local` 明确标成「调试用，不计费、不写台账、不过门禁」，
或直接收进高级工具页，避免和正式出片并列。

# 落点与命名事故复盘（2026-10-19 用户验收意见）

> **写入本文档的目的**：这两条不是引擎算错，是**产出方（AI 助手）的即兴发挥**造成的。
> 代码已修（见 V0.3），但代码只能拦住「已知路径」；**要防复发，必须把判据写成项目里的规则**。
> 任何人（或任何 AI 助手）在动手前读一遍本文，就不会再犯。

- 提出人：项目所有者（用户）｜记录：2026-10-19
- 严重度：**中（不改功能，但直接破坏交付物可用性与可维护性）**
- 现状：**已修复** —— 代码 + 门禁 + 文档三层都落地（见 §四）

## 二、事故一：发布版文件名「乱七八糟」

### 现象

同一部剧的发布版成片，实际出现过这些名字：

```
EP01_1080p_ES.mp4
ep01_拼接_11段_672x1216.mp4
ep01_西语硬字幕_11段_672x1216.mp4
ep01_预览_9段.mp4
ep01_预览_9段_h264.mp4
```

后果：上架时要逐个手工改名；集号是否连续、缺哪一集**无法用机器核对**；换个人接手不知道哪个才是发布版。

### 根因

1. **项目里没有任何发布版命名规则** —— 于是每次产出都由 AI 助手「当场起名」，名字里塞满了
   分辨率、段数、语言、是否预览等**过程信息**（这些信息属于元数据，不属于文件名）。
2. **「发布版」没有固定落点** —— 文件散落在 `07-成片/发布版1080p_es/`、`07-成片/交付/`、
   `07-成片/` 根下，靠人记哪个目录是最终交付。

### 修法（已落地）

| 层 | 落点 |
|---|---|
| 规则 | `docs/orchestration/生产流程总纲.md` **§3.7（2）**；`docs/distribution/发行资料清单.md` **§二** |
| 工具 | `stages/production/scripts/release_export.py`（唯一正确的导出方式，默认干跑） |
| 门禁 | `release_check.py`：目标目录**只允许** `^Episode\d{2,}\.mp4$`，出现杂名 → **退出码 2** |
| 常量 | `stages/_layout.py`：`RELEASE_EPISODE_PREFIX` / `RELEASE_EPISODE_DIGITS` / `RELEASE_FILENAME_RE` / `release_episode_name()` / `release_episode_dir()` |

**判据（以后照这个验）**

- 发布版一律在 `09-发行/剧集/`，文件名形如 `Episode01.mp4`（`Episode` + 至少两位数字，≥100 集自动加位）。
- 中间产物（`<ep>_master.mp4` / `<ep>_subbed.mp4` / `ep01_拼接_11段_672x1216.mp4`）**允许**保留原样，
  但**不许**直接当成发布版交付 —— 必须经 `release_export.py` 导出。
- 反例清单（出现即判未完成）：`EP01_1080p_ES.mp4`、`第一集.mp4`、`Episode1.mp4`（编号不足两位）、
  `Episode01_final_v2.mp4`（带额外后缀）、`最终版.mp4`。

## 三、事故二：资产跑到「成片」目录里

### 现象

人物资产（`char_01_Valeria Sarmiento.png` …）与场景资产（`scene_01_…png` …）**不在 `04-资产/`**，
而在：

```
07-成片/assets/characters/…            ← 新布局项目（out_dir 指向 07-成片）
video-pipeline/output/assets/…         ← 旧布局项目（out_dir=output，同一个坑的另一种表现）
```

后果：资产属于「前期素材」，却被埋在「后期成片」目录里；清理成片时容易连资产一起误删；
新人/AI 在 `04-资产/` 找不到图，会重复出图（**直接浪费钱**）。

### 根因

1. **一个 `out_dir` 承担了两种语义**：出片引擎的批次、`subs/`、日志都放 `<out_dir>`，
   而资产图也被统一写到 **`<out_dir>/assets/`**（4 个生成器都这么写）。
2. **脚手架把 `out_dir` 指到了阶段目录 `07-成片`** ⇒ 资产 = `07-成片/assets`。
   ⚠️ 旧的 `07-成片/assets` 说法就是这么来的；旧项目若 `out_rel=output`，则表现为
   `video-pipeline/output/assets` —— **同一个设计缺陷的两种外观**。
3. **错误被注释固化成"事实"**：`wire_new_assets.py` 里写着
   `OUT = OUT_ROOT / "assets"   # 资产出图落点（= 07-成片/assets）` ——
   注释把 bug 描述成了预期行为，后来者更不会怀疑。

### 修法（已落地）

| 层 | 落点 |
|---|---|
| 规则 | `docs/orchestration/生产流程总纲.md` **§3.7（1）**；目录规范 `04-资产/` |
| 真源 | `stages/_layout.py` 的 `assets_dir()`（`layout.json.assets_rel` → `config.local.json.assets_dir` → 阶段目录） |
| 脚手架 | `scaffold()` 自动建 `04-资产/{characters,scenes,props,refs}` 并回填 `assets_dir` |
| 改口 | 4 个生成器 + `wire_new_assets.py` + `episode_preflight.py` + 控制台 `web/core/inventory.py` |
| 迁移 | `stages/production/scripts/migrate_assets.py`（默认干跑、先备份、改写清单绝对路径） |
| 便捷访问 | `_ws.ASSETS` / `_ws.assets_dir(ws)` —— 新脚本**不要再自己拼 `<out>/assets`** |

**零迁移兼容（重要）**：老项目旧位置已有图、新位置为空时，`assets_dir()` **自动沿用旧位置**并打印迁移提示，
**不会**把资产劈成「一半在 04-资产、一半在 07-成片/assets」。迁移完成后再自动切到新位置。

**判据**

- 资产图**只允许**出现在 `04-资产/{characters,scenes,props}`；`07-成片/` 下**不得**有资产图。
- 参考图原图在 `04-资产/refs/`（瘦身后 → `06-提示词/refs_h3/`）；字典与清单在
  `04-资产/refs.json` 与 `06-提示词/data/*.json`。
- 检查命令：`drama.py status`（看「人物资产 / 场景资产」计数）、
  `migrate_assets.py --workspace <ws>`（干跑会列出所有待归位文件）。

## 四、防复发的三层（缺一层都会复发）

| 层 | 内容 | 为什么必须有 |
|---|---|---|
| **① 规则** | 总纲 §3.7 + 发行资料清单 §二 | 让「应该怎么做」有唯一出处，不依赖记忆 |
| **② 工具** | `release_export.py` / `migrate_assets.py` | 让「正确做法」比「即兴发挥」**更省事** |
| **③ 门禁** | `release_check.py`（命名）、`migrate_assets.py` 的干跑清单（落点） | 让「做错了」**当场报错**，而不是等用户发现 |

> **本项目的通用教训**：凡是「用户反复纠正同一件事」的，都不要只修那一次的输出 ——
> 要把它变成 **规则 + 工具 + 门禁**，否则下一次换个剧、换个助手，同样的错会再来一遍。
> （与 `SoloDrama_踩坑清单_2026-10-18.md` 的结论一致：「把对账做成固定关卡，比修任何单个 bug 都更值钱」。）

## 五、交付前自检 5 问（每次交付成片/发行资料前逐条过）

1. 发布版是否都在 `09-发行/剧集/`，且**只有** `EpisodeNN.mp4`？（`release_check.py` 退出码 0？）
2. 集号是否连续、缺号是否已知？（整季交付前必须补齐）
3. 人物/场景/道具资产是否都在 `04-资产/`？（`07-成片/` 下有没有残留资产图？）
4. 有没有「把过程信息写进文件名」的新文件？（分辨率/段数/语言/日期都不该进**交付物**文件名）
5. 我是不是在「临时起名 / 临时挑目录」？如果是 → **停下来用现成脚本**，或者先把规则补进 §3.7。

# Studio 实测缺陷清单（2026-11-01 · 基于 V0.7.45）

> 方法：起真服务（`web/` + 临时 venv，`127.0.0.1:8799`）→ 用 Node 直接跑
> `ui/studio/js/views/*.js` 的 `render(ctx)`（真后端、真 fetch）→ 接口全量巡检 →
> 按业务动作真调命令（走作业队列）。**没有靠读代码猜**。
>
> 结论一句话：**页面能开、数据是空的、按钮是死的**。三个问题都不是渲染问题，而是
> 「后端读错目录」+「命令 id 改过但前端没跟」+「判据重复求值拖慢首屏」。

## 一、性能：四个接口占了首屏的全部等待

| 接口 | 修前 | 修后 | 根因 |
|---|---|---|---|
| `/api/studio/workflow` | **21.7 s** | **1.1 s** | `node_state` 递归无缓存：23 节点算成 553 次调用、`cmd:` 判据真跑 **62 次**（每次一个 Python 子进程） |
| `/api/studio/overview` | **24.9 s** | **2.0 s** | 同上（内部调 workflow） |
| `/api/health/checks` | **29.0 s** | **1.0 s** | `env_check._bin_candidates` 用 `glob(recursive=True)` 扫整棵 `C:\Program Files`：52,776 次目录列举只为找 3 个 exe |
| `/api/studio/env` | **13.6 s** | **1.0 s** | 同上（调 env_check） |

修法：

- `nodes.evaluate` 传一份**局部**备忘录（`_memo`），每个节点一轮只判一次。
  ⚠ 备忘录**不挂在 `Ctx` 上** —— 挂了之后「改完文件再判一次」会拿到上一轮结论
  （`test_nodes.py` 的 B04 当场抓到过）。直接调 `node_state(ctx, node)` 永远重新读盘。
- `env_check` 的二进制查找改成「限深遍历 + 命中即停 + 目录名先筛」。
  三条结果（ffmpeg / ffprobe / whisper-cli）与修前完全一致。

## 四、口径变更（会影响后续代码）

1. **批次 = 内容，不是名字**。任何「扫批次」的地方都应调 `studio.batches()`，
   不要自己再写一遍 `^\d{8}_\d{6}$`。
2. **产物 = 前缀，不是全名**。`_subbed` 后面可能跟 `_1080p` / `_2k`，别写死。
3. **节点状态备忘录只在 `evaluate()` 里**。直接调 `node_state` 必须重新读盘。
4. **只读接口不许写工作区**。`release_check.py` 因此有了 `--no-write`；
   以后再加「检查类」脚本，请默认提供这条开关。

## 站点口径：测的站点 ≠ 花钱的站点（本轮最重要）

| 事实 | 值 |
|---|---|
| 界面保存的站点（`connections.json`） | `https://www.runninghub.ai` |
| 引擎实际使用的站点（`configs/channels.json`） | `https://www.runninghub.cn` |
| 测试连接原来打哪个 | `.ai`（界面那份） |
| 出片实际打哪个 | `.cn` |
| 两个站点的余额 | **13687 vs 32689 RH币** |

**这是两套账户**。原来「测试连接」显示已连接、余额 13687，而出片走的是另一个站
（余额 32689）—— 测通的和花钱的不是同一个，账单自然对不上，余额不足时也只会报「Key 无效」。

根因：连接中心把 `RUNNINGHUB_BASE_URL` 注进子进程环境，而引擎从 2026-10-29 起
**不再读这个变量**（真源 `_site.project_site`）。

修法（不改引擎，只把话说对）：

1. `connections._engine_site()`：直接问 `_site.runtime_site()` 拿「引擎实际站点 + 来源」；
2. `_test_runninghub()` 改成**测 effective**，并在结果里带
   `site: {used, source, stored, stored_ignored}`；
3. `overview()` 只对 runninghub 暴露 `effective` 块；
4. 页面：站点选择器改成「兜底值；引擎读 configs/channels.json」，
   下方直接显示「引擎实际使用：…（来源：…）」；「注入关系」卡片里
   「RH 站点 · 与 Key 一起带上」改为「由 configs/channels.json 决定」。

> 副作用提示：跑测试会把 `last_test/last_detail` 写进 `web/var/connections.json`
> （那里现在记的是 `.cn` 的余额，是**更正确**的值）。原文件备份在 `_scratch/connections.bak.json`。

## 二、参考图瘦身

**根因（功能本来就是废的）**：`drama.py refs` 调 `prepare_refs.py` 时**没传 `--workspace`**，
而那个脚本的默认工作区是「脚本所在目录的 video-pipeline/」——于是对任何项目都报
「找不到工作区 data/」。修法：`cmd_refs` 显式带 `--workspace str(WS)`。

**真跑验证**（`_scratch/refsproj`，造一张 6000×300）

写盘   → 06-提示词/refs_h3/char_big_00.jpg  2048×102，省 58.2%，原图不动

**页面**：资产中心右上「瘦身参考图…」→ 弹窗说明写盘范围 + 两个勾（改 characters.json / 确认写盘）

# Studio 实测缺陷清单（2026-11-01 · 基于 V0.7.45）

> 方法：起真服务（`web/` + 临时 venv，`127.0.0.1:8799`）→ 用 Node 直接跑
> `ui/studio/js/views/*.js` 的 `render(ctx)`（真后端、真 fetch）→ 接口全量巡检 →
> 按业务动作真调命令（走作业队列）。**没有靠读代码猜**。
>
> 结论一句话：**页面能开、数据是空的、按钮是死的**。三个问题都不是渲染问题，而是
> 「后端读错目录」+「命令 id 改过但前端没跟」+「判据重复求值拖慢首屏」。

## 一、性能：四个接口占了首屏的全部等待

| 接口 | 修前 | 修后 | 根因 |
|---|---|---|---|
| `/api/studio/workflow` | **21.7 s** | **1.1 s** | `node_state` 递归无缓存：23 节点算成 553 次调用、`cmd:` 判据真跑 **62 次**（每次一个 Python 子进程） |
| `/api/studio/overview` | **24.9 s** | **2.0 s** | 同上（内部调 workflow） |
| `/api/health/checks` | **29.0 s** | **1.0 s** | `env_check._bin_candidates` 用 `glob(recursive=True)` 扫整棵 `C:\Program Files`：52,776 次目录列举只为找 3 个 exe |
| `/api/studio/env` | **13.6 s** | **1.0 s** | 同上（调 env_check） |

修法：

- `nodes.evaluate` 传一份**局部**备忘录（`_memo`），每个节点一轮只判一次。
  ⚠ 备忘录**不挂在 `Ctx` 上** —— 挂了之后「改完文件再判一次」会拿到上一轮结论
  （`test_nodes.py` 的 B04 当场抓到过）。直接调 `node_state(ctx, node)` 永远重新读盘。
- `env_check` 的二进制查找改成「限深遍历 + 命中即停 + 目录名先筛」。
  三条结果（ffmpeg / ffprobe / whisper-cli）与修前完全一致。

## 四、口径变更（会影响后续代码）

1. **批次 = 内容，不是名字**。任何「扫批次」的地方都应调 `studio.batches()`，
   不要自己再写一遍 `^\d{8}_\d{6}$`。
2. **产物 = 前缀，不是全名**。`_subbed` 后面可能跟 `_1080p` / `_2k`，别写死。
3. **节点状态备忘录只在 `evaluate()` 里**。直接调 `node_state` 必须重新读盘。
4. **只读接口不许写工作区**。`release_check.py` 因此有了 `--no-write`；
   以后再加「检查类」脚本，请默认提供这条开关。

## 三、两个「看起来是 bug、其实是正确设计」的

1. `media.render` 在测试项目上**拒绝出片**，报「② 剧本台词没解析到」。这是 cues=0 守卫
   在起作用（宁可不出片也不用估算糊）—— 不是缺陷。
2. `/api/llm/complete` 对 `script.diagnose` / `script.review` 报「模板缺输入变量」。
   模板先校验变量、后调模型，所以这两次**没有产生费用**。错误信息列出了缺哪几个变量，
   照它补就行。

## 四、金额口径

真实调用回来了 `input/output tokens`，但 **`cost.usd` 是 null**（DeepSeek 不返回金额）。
`/api/llm/usage` 的 summary 如实写「供应商未返回金额，全部为未知」，页面显示「未知」而不是 ¥0
—— 这是对的（不猜金额）。代价是：**成本中心看不到 LLM 花了多少**，只能看 token 数。
要不要接价格表（按 token × 单价估算）是产品决定，我没动。

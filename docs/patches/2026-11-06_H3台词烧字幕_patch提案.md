# 2026-11-06 · H3 台词被烧成画面字幕：根因与源码改造方案

> 状态：**根因已实验确认，方案已在本机项目验证通过**；本文是拿去改 SoloDrama 源码的施工单。
> 验证项目：《我的双子座小狗女友》（3 集 × 240s，16:9，真人写实 + jp-youth-film，云端 4090 D / int8 编码器）
> 验证日期：2026-11-06 12:30–13:00
>
> **已施工（V0.7.66）**。落地时改了提案的三处判断，理由见文末「§11 施工记录」：
> ① 样板「口型对齐」不是全删，而是改成「`<d>` 本身即语音事件，不要另写口型对齐」；
> ② 转换层不只包 `口型对齐台词"…"`，还包「说话动词 + 冒号 + 引号」；
> ③ 招牌/标语类的引号中文**不自动包**（改成台词是另一种错），只由门禁告警。

---

## 0. 一句话结论

**台词必须写成 `<d>[Chinese] …</d>`。裸写在引号里的目标语言文本，H3 会当成「画面中应出现的文字」，直接烧成字幕。**

这不是工作流缺开关，是提示词写法问题；调工作流、加负向词、加「不生成任何字幕」全都无效（BasicGuider 等价 cfg=1，负向不参与引导）。

---

## 1. 现象与最小复现

| 项 | 内容 |
|---|---|
| 现象 | 成片在**有人开口的时间段**底部出现白字黑边字幕，文本与剧本逐字一致；同一镜的闭口段没有字幕 |
| 复现 | 任一镜，B 段写 `约束：时小满口型对齐台词"这个箱子周三之前不许开"；周叙闭口。` |
| 已验证无效的三种做法 | ① 提示词里加「不生成任何字幕、文字、水印」；② 换 steps / 分辨率；③ 在节点树里找 subtitle 开关（整份 canvas 工作流无字幕相关节点） |
| 有效做法 | 把该句改成 `时小满说：<d>[Chinese] 这个箱子周三之前不许开。</d>` |

## 2. 三组对照（同实例、同分镜图、同参考卡、固定 seed 123456）

| 组 | 提示词形态 | 字幕 | 对白（ASR 逐字） |
|---|---|---|---|
| A 基线 | 中文分段 + `口型对齐台词"…"` | **有**（贴底、白字黑边） | 准确 |
| B 官方六段式 | subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music，台词写 `<d>[Chinese] …</d>` | **无** | 准确 |
| C 最小改动 | 保留原中文分段，**只**把台词换成 `<d>` 标记 | **无** | 准确 |

- 抽帧核验点：2s / 3s / 5s / 7s（开口与闭口各有）
- ASR 结果：`这个箱子周三之前不许开。` / `今天周一。` / `一允许反悔。` / `二允许半夜出门。` / `第216条。`
- **结论：关键变量是 `<d>` 标记，不是六段式结构**。六段式里 `<d>` 也生效，但把整篇改写成英文长文对结果没有额外贡献。

依据（官方格式）：`<d>[语言] …</d>` 是语音事件标记，见 `h3-prompt-writing` 技能 `references/ref-en.txt` §5.4「Speakers, Audio Sources, and Dialogue」。

## 3. 根因

H3 的多参提示词里，「目标语言文本」有两种身份：

| 写法 | 模型的理解 | 结果 |
|---|---|---|
| 引号内裸文本 `"这个箱子周三之前不许开"` | 画面里应该出现的文字 | 渲染成字幕 |
| `<d>[Chinese] 这个箱子周三之前不许开。</d>` | 一个语音事件（谁说、说什么） | 驱动口型与配音，**不落到画面** |

当前仓库的创作模板**系统性地教了前一种写法**，所以只要用模板生成手册，就必然烧字幕。

### 5.3 转换层：`stages/import/md2pack.py` 加归一化（最重要的兜底）

老项目、以及别的 Skill 产出的手册不会立刻改，转换器需要把裸引号台词自动包成 `<d>`。

新增函数（放在 `parse_episode` 之前）：

```python
DIALOG_BARE = re.compile(r'(?P<who>[\u4e00-\u9fa5A-Za-z·]{1,12})\s*口型对齐台词\s*[：:]?\s*[“"](?P<line>[^”"]+)[”"]')
SPEAK_BARE  = re.compile(r'(?P<who>[\u4e00-\u9fa5A-Za-z·]{1,12})\s*说\s*[：:]\s*[“"](?P<line>[^”"]+)[”"]')

def normalize_dialogue(text: str, lang: str = "Chinese") -> tuple[str, int]:
    """把裸引号台词包成 <d>[lang] …</d>。已带 <d> 的句子不动（幂等）。"""
    n = 0
    def _wrap(m):
        nonlocal n
        line = m.group("line").strip()
        if "<d>" in line:
            return m.group(0)
        if not re.search(r"[。！？…]$", line):
            line += "。"
        n += 1
        return "%s 说：<d>[%s] %s</d>" % (m.group("who"), lang, line)
    out = DIALOG_BARE.sub(_wrap, text)
    out = SPEAK_BARE.sub(_wrap, out)
    return out, n
```

接入点（`parse_episode()` 里，构造 shot 字典之前）：

```python
board_prompt, _ = normalize_dialogue(a.group(1).strip())
vp, n_wrapped = normalize_dialogue(b.group(1).strip())
if n_wrapped:
    gaps.append({"shot": sid, "reason": "台词已自动包 <d> 标记（%d 句），建议回源修正" % n_wrapped})
```

注意三条：

1. **只在 `board_prompt` / `video_prompt` 上跑**，不要动 `dialogue` 数组（那是字幕对齐用的纯文本）。
2. **幂等**：二次转换不能变成 `<d><d>`。
3. `lang` 参数留给跨语种项目（西语项目应传 `Spanish`）。

### 11.2 三处偏离提案的判断

**① 「口型对齐」不是删掉，而是绑到标记上。**
提案 ① 建议改成「不写口型对齐」。但口型对齐本身是**想要的**效果，只是当时没有可靠的触发方式。
落地写法是「台词只写成 `<d>…</d>`，不加引号、不写『口型对齐』」，并在说明段点明
「`<d>` 是语音事件标记，模型据此配音并对齐口型」—— 既消掉了裸引号，也没丢掉口型意图。
（提案 C 组实测口型准确，但它保留了口型句；两种写法都成立，选信息更少的一种。）

**② 归一化不能只认 `口型对齐台词"…"`。**
提案的正则只覆盖模板教出来的那一种。实际手册里更常见的是 `周然笑着说："…"`。
但**不能**简单到「所有冒号后的引号都包」——`招牌写着："营业中"` 会因此变成台词，
那是把画面文字错误地转成语音，比原来更糟。所以只认两类高置信写法：
`X口型对齐台词"…"` 与 `说话动词（说/道/问/喊/念/冷笑/开口/低声说…）+ 冒号 + "…"`。

**③ 认不出的写法交给门禁，不交给自动改。**
`find_bare()` 比 `normalize_dialogue()` 宽：它连没有说话动词的引号中文一起报。
这样「可能是台词也可能不是」的句子由人判断，而不是被机器猜一个。

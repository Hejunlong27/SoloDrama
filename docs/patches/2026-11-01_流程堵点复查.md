# 流程堵点复查（2026-11-01 · V0.7.45）

> 目的：找出「节点永远过不去」的地方 —— 不是判据太严，而是**判据看错了地方**。
> 方法：① 静态查 23 节点的 reads/output/next 闭环；② 在空项目里造最小数据集，
> 逐个调 `check_node` 看它到底在哪儿找文件；③ 拿「母版/分段/数据文件明明存在」的现场
> 反证判据。所有结论都有可复现的命令。

## 一、根因：数据布局改了一半

`convert_storyboard` 从 V0.7.42 起把 data **按集分目录**（`data/ep01/shots.json`，
为了修「跑 ep02 覆盖 ep01」）。写侧改了，**读侧还有 5 处写死根目录**：

| 读侧 | 原写法 | 新布局下的症状 |
|---|---|---|
| `subtitle.episode_segments` | `data/shots.json` | 拼接阶段「一个段都没有」，missing 全部镜头 |
| `drama.py`（status / 资产缺口 / 出片计划） | `DATA / 'shots.json'` | `drama status` 显示「分镜 0 段」，而文件就在 `data/ep01/` |
| `ingest_check.py` | `W.data_dir(ws)` | 报「缺 shots.json / h3_prompts.json」→ `prompt.contract` 永不过 |
| `episode_preflight.py` | `DATA / "shots.json"` | 单集体检直接抛 FileNotFoundError |
| `script_continuity.py` | `06-提示词/data/h3_prompts.json` | 报「找不到产物」→ `script.continuity` 永不过 |

**统一修法**：加三个解析函数，读侧一律走它们（有集目录用集目录，没有就是老布局，
老项目零迁移）：

- `_ws.data_ep(ws, ep)` —— 本集数据目录
- `_ws.data_file(ws, name, ep)` —— 找一个数据文件（含「各集里最新的那份」兜底）
- `subtitle.data_ep_dir(ws, ep)` —— 字幕管线专用（不依赖 `_ws`，Skill 包能单独跑）

## 二、七个真堵点（都会让链路卡死）

| # | 节点 | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | `edit.master` / `edit.upscale` / `edit.subtitle` | 母版明明在 `07-成片/subs/ep01/ep01_master.mp4`，判据说「找不到 *_master.mp4」 | 判据只找 `07-成片/ep01/`（那一层根本不存在，批次段在 `07-成片/<时间戳>/`） | `_out_hits()`：依次 `<out>/<ep>/` → `<out>/subs/<ep>/` → 全 out 递归（文件名须含集号） |
| 2 | `video.batch` / `video.audit` | 「没有分段成片」 | 同理，段在 `<out>/<批次>/<shot>/final.mp4`，没有 `<out>/ep01/` | `_ep_segments()`：读本集 `shots.json` 的 shot_id，按 `<批次>/<shot>/final.mp4` 找（复刻字幕管线语义） |
| 3 | `edit.subtitle`（下游） | 拼接时 missing 全部镜头 | `subtitle.episode_segments` 读死根 `data/shots.json` | `data_ep_dir()` + 两处读取容忍缺失 |
| 4 | `prompt.contract` | 「缺 shots.json / h3_prompts.json」 | `ingest_check` 读根目录 | `W.data_ep(ws, --ep)` |
| 5 | `script.continuity` | `argument --ep: invalid int value: 'ep01'` | 该脚本 `--ep` 是 `type=int`，节点没声明 `ep_style` | 节点加 `"ep_style": "int"` |
| 6 | `script.continuity` | 「找不到产物」（即使 data 齐全） | 只认 `06-提示词/data/`，不认 `<data>/` 与 `<data>/<ep>/` | `_pick()`：三种摆法都认 |
| 7 | `drama status` | 显示「分镜 0 段」 | 读死根 data | `data_f()`（同 data_file 语义） |

## 三、四个坑（不卡链路，但会误导人）

| # | 现象 | 影响 | 处理 |
|---|---|---|---|
| 1 | `drama do <手写节点> --dry-run` 打印 `[DRY-RUN] （手写：模板见…） --workspace …` | 看着像能跑，真跑什么都不执行 → 人以为命令坏了 | `_print_plan` 改为 `[NO-CMD]` + 说明 |
| 2 | `drama do script.episode` 打印「产物：03-剧本/ep01.md」，实际文件是 `ep_01.md` | 以为文件放错地方 | `ep_path()` 剧本类节点优先返回 `ep_script()` 找到的真实文件 |
| 3 | `drama init` 后 `asset.roster` 立刻通过 | 名册里还是「主角姓名 / LEAD」占位，下游拿占位角色出图 | 新增 `roster` 判据：名字或身份仍是模板文案的不算数 |
| 4 | 新项目 Studio 里「调研」环节显示 done | 三个调研节点都是 optional，全 skipped 被算作完成 | **未改**（展示层口径），需与「可选节点」的语义一起定 |

## 四、复查方法（可复现）

```bash
# 1) 造一个空项目
python stages/production/scripts/drama.py init --workspace _scratch/newproj --episodes 12

# 2) 看全链状态：只有「剧本还是骨架」该失败，其余应是上游阻塞
SOLODRAMA_WORKSPACE=_scratch/newproj python - <<'PY'
import sys, pathlib; sys.path.insert(0,"stages/production/scripts")
import nodes as N
ctx = N.Ctx(pathlib.Path("_scratch/newproj").resolve(), "ep01")
for n in N.NODES:
    st = N.node_state(ctx, n); print("%-18s %-8s %s" % (n["id"], st["state"], st["detail"][:50]))
PY

# 3) 反证：把产物放到标准位置，看判据认不认
mkdir -p _scratch/newproj/07-成片/subs/ep01
#   放一个 ep01_master.mp4 → edit.master 必须通过（修前：永远「找不到」）
```

**判据自检的口径**：`全链状态里不该出现「产物明明存在却判不过」**。
一旦出现，先查它找的目录，而不是查产物。

## 五、仍然存在的（不属堵点，属设计）

- `script.gate` / `asset.roster` / `asset.prompt` / `board.script` / `video.audit` 五个节点
  的 `run` 是说明文字，不是命令 —— `drama do` 会走「判据本身就是执行」或「TODO」分支。
  这是 V0.7.42 定的「手写节点」，不是缺陷；现在 dry-run 也会如实说明。
- 调研三节点默认 optional，新项目全 skipped。若希望「新项目不算做过调研」，
  需要改的是**环节聚合口径**（skipped 算不算 done），不是节点判据。

### 1.1 补充：前置条件从 7 项扩到 9 项（用户当日追加要求）

用户补充：「前置条件里面把工作流 API、账号 API Key 的需求加上，必须向用户确定使用哪个工作流 API、
哪个账户的 API Key」。这不是加两行菜单，而是补上两个**选错不会报错**的开关：

| 新项 | 为什么必须问到具体值 | 机器判据 |
|---|---|---|
| **6 工作流 API** | 同名工作流在平台上可以有多份（不同分辨率/步数/LoRA），换错 `workflowId` = 换了一个模型，8 段跑完才发现风格漂移，钱已花 | `kind + ref(workflowId/appUrl/comfyUrl) + site` 三元组齐全；站点只接受 `.ai` / `.cn`，写错退出码 2；可从 `model-plan.json` 的执行依据**推断**（不必抄两遍） |
| **7 账号 API Key** | 决定了花谁的额度、出图带谁的水印。实测事故：确认时装 A 账号、跑时环境变量被换成 B 账号，钱算 A、水印是 B，无法追溯 | 登记 `别名 + 指纹(sha256前8…后4) + 来源(环境变量名)`，**Key 本体永不落盘**；`require()` 与 `pipeline run` 每个计费环节前比对当前环境 Key 指纹，不一致 → 退出码 4 并明示「会花错账号的钱」 |

配套：`drama.py setup accounts` 列出本机可用账号（含 `<ws>/keys.json` 多账号清单，只显示指纹与站点）；
`--account-source <环境变量名>` 支持多账号切换；`pipeline plan` 的开工预告新增「工作流 API / 账号」两行。

> 两项按通道**条件化**：全本地或闭源时自动标「无需」不拦；只要有一条 RunningHub 通道即变硬性必填。

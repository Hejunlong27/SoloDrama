## 二、P0 逐条：根因与改动

### P0-2 探针会真的建任务
- **根因**：`POST /openapi/v2/run/workflow/{id}` 非幂等；脚本把「能不能连」和「能不能跑」混为一谈。
- **改动**：`rh_doctor.py` 新增 `probe_readonly()`，只用 `POST /openapi/v2/query {"taskId": "0"}`，
  按 `code==0 / 500 / msg 命中「API Key不存在」/「任务不存在」` 四类判据输出
  `ok | bad_key | route_missing | network | unknown`（认不出就如实回显，不猜）。
  新增 `--probe-readonly`、`--matrix`；启动横幅与文件头都写明禁令；契约文档 §五 同步。
- **验证**：`test_feedback_20261020.t_probe_readonly`（打桩 5 种响应）；
  真实调用需网络，未在本机对生产站点发请求（见 §五「需要你确认」）。

### P0-3 默认剧名污染交付物
- **根因**：`cost_ledger.py:598 DRAMA_DEFAULT = '七大姑催婚'`，且 `drama.py cost` 不透传剧名。
- **改动**：`_ws.py` 新增 `drama_name(ws)`（`brief.json` → `project.json` → 目录名）；
  `cost_ledger` 默认值改为 `drama_name(WS)`；`drama.py cost` 总是显式传 `--drama` 并打印来源。
- **验证**：`t_drama_name` 三例；用真实工作区跑 `drama.py cost` 不再出现旧剧名。

### P0-5 工作区 README 的路径参考系错位
- **根因**：README 由 `_layout.scaffold` 生成，写的是**引擎仓库内**的相对路径；落进工作区后参考系变了。
- **改动**：`_layout.py` 新增 `ENGINE_REPO_ROOT` 与 `_stage_readme_text()`，
  README 顶部写「引擎仓库根（绝对路径）」+ 一句参考系声明；`scaffold` 对缺标记的旧 README **幂等重写**。
- **验证**：`t_*`（README 内容断言）+ 真实项目 `09-发行/README.md` 重跑 scaffold 可见修复后内容。

### P0-6 发行门禁只有两态
- **根因**：五类产物被当同一批次并列项，任缺即整体 `blocked`，于是「物料齐、只差成片」也被判不合格。
- **改动**：拆 `fails`（物料）与 `downstream`（成片）；`_verdict()` 三态；
  `release-manifest.json` 增 `material_fails` / `downstream` / `verdict_cn`；
  人读输出把五类拆成「已备 / 需 / 缺」，成片单独标「← 属下游依赖，不是物料缺项」；
  新增 `--material-only`（连载期增量验收，物料齐则退出码 0）。
- **验证**：`t_release_verdict`；`test_release_check.py` 15/15 未回归；
  真实项目实测输出 `[WAIT] 物料已备，仅缺下游成片 1 项`。

### P0-7 提交后被杀 → 静默漏镜
- **根因**：续跑判定只看「本地有没有 `final.mp4`」。任务已提交（钱已花）、进程在轮询中被杀
  → 无产物、无记录 → 既不进完成集也不进失败集。引擎的 `state.json` 虽记了 `video_task_id`，
  但**没有任何机制保证「提交成功」这件事一定落盘**，也没有收尾对账。
- **改动**：
  1. 新模块 `engine/inflight.py`：`<批次>/inflight.json`，提交成功立刻写、拿到终态才删（原子写）；
  2. `main.reconcile_inflight()`：`--resume` 启动时逐条 `query`——
     `SUCCESS` 补下载并标成功（不重提）、`FAILED` 清账待重跑、非终态则恢复 `RUNNING` 让后续走「复用 taskId 只轮询」；
  3. 收尾硬校验：`summary.gaps` 记录 `missing_state`（状态表里没有）与 `success_without_artifact`（说成功但文件不在），
     有缺口**默认退出码 3**（`--allow-gaps` 放行），不再混进 `pending` 静默通过。
- **验证**：`t_inflight_pending`（写入/移除/去重）；预演跑 `--dry-run` 确认 `gaps` 为空时不误报、`--limit` 不误判。

## 七、追加：封面引擎收编（P1-9/10/11 的真正修法）

**为什么先被判成「属技能侧」**：`cover_forge.py` 原本只存在于 WorkBuddy 用户级技能
`drama-cover-forge/scripts/` 下 —— 不进 git、不进 `manifest.sha256`、不随仓库分发。
在那里面修，等于只有一台机器好，换机/交接/新会话就退回旧行为。所以正确处理不是「就地改」，
而是**收编**：仓库成为唯一真源，技能只留转发壳。

**收编内容（2026-10-20）**

| 原位置（技能） | 新位置（仓库真源） |
|---|---|
| `scripts/cover_forge.py` | `stages/production/scripts/cover_forge.py` |
| `references/size-specs.md` | `stages/production/references/cover/size-specs.md`（新增 **§3.3 竖/横底图分开生成**） |
| `references/style-presets.md` | `stages/production/references/cover/style-presets.md` |
| `references/copywriting.md` | `stages/production/references/cover/copywriting.md` |

| 原实现与 `references/` | 备份 `scripts/_backup_20261020/`、归档 `_archive_20261020/`（勿再改） |

**三个缺陷的实际修法**

1. **P1-9 色条压降部**：删掉 `字号 × 1.12 em` 的经验值，改用 `draw.textbbox()` 的**真实底边**
   + `0.16 em` 间距（`band_y()`）。实测同一张 9:16：
   `y_title=1187 / bbox_bottom=1303 / 新色条=1319 / 旧公式=1302` —— 旧值比字形底边还高 1px，
   正好压在逗号尾巴上；新值让色条整体下移 17px，逗号完整。
2. **P1-10 副标溢出**：`_sub_font()` 取 `sub1/sub2` 中较长一行做一次 `fit_font()`（两行同字号）；
   `--check` 预先算出「会溢出多少、需缩到多少 px」。实测 900×1600 档：53px → 49px，右侧不再裁字。
3. **P1-11 竖版底图转 16:9**：`--check` 对「源图比例 < 目标比例 − 0.02 且目标为 wide」主动告警，
   并明确指向「这一档单独出横版底图」；规范同步补在 `size-specs.md §3.3`。

**顺带得到的两个能力**

* `--workspace`：spec 未写 `out_dir` 时默认落 `<工作区>/<发行目录>/封面/`（读 `layout.json` 的
  `stages.release`，缺省 `09-发行`），不再依赖人记路径；

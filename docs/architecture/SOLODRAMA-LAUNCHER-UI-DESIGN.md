# SoloDrama Launcher UI 与交互设计

## 1. 产品原则

- 普通用户只需双击图标。
- 正常启动显示短暂原生启动画面，健康后直接进入工作台。
- 首次启动或启动失败时展示完整状态和诊断。
- 高级用户可从工作台主动打开 Launcher 控制中心。
- Launcher 不拥有任务生命周期，不取消或接管云端任务。
- Provider、ComfyUI、GPU 调度和任务恢复继续隐藏在现有系统中。

## 2. 路由与进入方式

### 正常启动

```text
原生启动动画
  -> Server 就绪
  -> WebView
  -> 首次启动：/launcher 向导
  -> 后续启动：/hello 或 /home
```

### 首次启动

满足以下条件进入 `/launcher`：

- 桌面端。
- `launcherOnboarded` 未完成。
- 已完成过旧 `helloCompleted` 的用户不会被重新拦截。

### 高级入口

工作台顶部菜单提供“启动控制中心”按钮，进入 `/launcher`。

### 停留控制中心

设置 `autoOpenWorkspace=false` 后，后续启动不会直接进入工作台，而是显示 Launcher。

## 3. 控制中心信息架构

左侧导航：

- 运行概览。
- 本地服务。
- 云端连接。
- 运行日志。
- 启动设置。
- 关于 SoloDrama。

底部操作：

- 打开日志目录。
- 退出 SoloDrama。

## 4. 运行概览

真实状态：

- 桌面环境。
- 数据目录。
- 本地后端。
- 创作 WebView。
- 独立数据库配置状态。
- 本地/局域网 ComfyUI 配置状态。
- 云端实例在线/离线数量。
- 统一任务运行中/待恢复数量。
- 应用版本、PID、平台、端口。

启动步骤不使用定时器伪造进度，全部由状态 API 的真实检测结果派生。

## 5. 本地服务

展示：

- 核心后端。
- 创作界面。
- 项目数据服务。
- 统一任务运行时。

支持：

- 重新检测。
- 复制状态详情。

不在 Launcher 中显示可误操作的未知 PID，也不无确认结束进程。

## 6. 云端连接

状态直接读取 Cloud Hub：

- 已配置实例。
- 在线/降级实例。
- 离线实例。
- 最近检测时间。
- 任务数量。

支持：

- 重新检测。
- 打开 `/cloudCompute` 页面。

Launcher 不重新实现 ComfyUI 协议，也不取消云端任务。

## 7. 日志

API 读取 `app.log` 尾部，并进行二次脱敏：

- Bearer/Basic Token。
- URL 查询参数。
- API Key、Token、Password、Authorization、Cookie、Secret。
- URL 内嵌凭据。

前端支持：

- 关键字搜索。
- INFO/WARN/ERROR 过滤。
- 复制错误详情。
- 打开日志目录。
- 导出诊断 JSON。

## 8. 启动设置

已实现真实设置：

- 启动后自动进入工作台。
- 启动时检查更新。
- Windows 开机自启动。

设置写入 `settings.launcher`，开机自启动写入当前用户 Windows Run 项。

未实现：

- 最小化到系统托盘。
- 关闭窗口时驻留托盘。
- 托盘菜单。

原因：本次环境的 Electrobun SDK 投影未成功生成，无法可靠调用和验证托盘 API。没有用假托盘或空按钮替代。

## 9. 首次启动向导

首屏显示：

- 欢迎说明。
- 当前数据目录。
- 真实环境、数据、后端和前端检查。
- “继续进入 SoloDrama”按钮。

不要求首次配置 ComfyUI，也不要求云端平台。

## 10. 关闭和任务

- Launcher 不直接操作媒体任务。
- 云端任务状态由现有 `mediaTasks` 和 ProviderTaskData 持久化。
- 退出应用只关闭本地连接和服务，不向上游发送取消。
- 下次启动后，统一 Task Runtime 可继续恢复任务状态。

## 11. 数据保护

- 程序文件、用户数据和日志分域。
- 新用户数据位于系统 AppData。
- 已有安装目录数据优先复用。
- 安装和升级不删除项目、工作流、Provider 配置、Token、素材和日志。
- 卸载时只有用户明确勾选才删除用户数据。

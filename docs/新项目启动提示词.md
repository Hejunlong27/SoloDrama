# 新项目启动提示词（复制给 AI 助手即可）

> **这份文档解决一个问题**：怎么跟 AI 助手说话，才能让它**用上当前版本（V0.3.1+）的规则**，
> 而不是按老习惯把资产丢进 `07-成片/`、把发布版起成 `EP01_1080p_ES.mp4`。
>
> 使用者不必懂代码；把下面代码块整段复制给助手即可。**规则真源永远在仓库里**，本文只是"怎么说"。

---

## 一、最短版（一句话）

```text
用 D:\编程\SoloDrama 帮我做一部新短剧。开工前先读这三份并复述你读到的硬规则：
docs/orchestration/生产流程总纲.md 的 §3.3 和 §3.7、docs/patches/2026-10-19_落点与命名事故复盘.md、
stages/production/references/pitfalls.md 的 §F、docs/creation/剧本改编四段法.md。
```

> 只要助手**真的读了** §3.7，两条最容易犯的错（资产落点、发布版命名）就不会再发生。
> 所以这句话的核心不是"做什么"，而是**"先读哪几份"**。

## 二、完整版（推荐：新项目开工就发这一段）

```text
用 D:\编程\SoloDrama 帮我做一部新的 AI 短剧。

【第 -1 步 · 环境自检（不做完不许开工）】
先跑 `python tools/env_check.py --json`，把结果报给我：
- `ok: true` → 继续下一步；
- `ok: false` → **停下来**，逐个说清「缺什么 / 当前用的是哪个解释器 / 哪个解释器已经装好了」，
  然后按报告里的 A（用已装好的解释器）或 B（给当前解释器补装）让我选，别自己直接装。
必需项只有四个：**Python 3.10+ / Pillow / ffmpeg / ffprobe**。

【第 0 步 · 先读规则，再动手】
开工前请先读下面五份，并用 5 行以内复述你读到的硬规则，确认后我才让你继续：
1. docs/orchestration/生产流程总纲.md —— 重点 §3.3「留存结构 + **改编四段法**」、§3.7「落点与命名硬规则」、§3.8「角色差异化」、§二 目录规范、§四 门禁
2. docs/patches/2026-10-19_落点与命名事故复盘.md —— 两条硬规则为什么定，含「交付前自检 5 问」
3. stages/production/references/pitfalls.md —— 重点 §F 落点与命名
4. docs/assets/角色差异化设计规范.md —— **出任何人物图之前必读**：六维签名 + 六条硬规则；
   人物形象一律先跑 `stages/assets/scripts/character_design.py plan`，不许逐角色自由手写长相
5. **docs/creation/剧本改编四段法.md** —— **写剧本之前必读**：诊断（A/B/C，未 `--confirm` 不许写正文）
   → 骨架 + 结构审查（`review`）→ 正文 → 观众验收（`audience`）；
   `plan` 的句库默认值只是占位，正式大纲必须用 `--from-outline` 人工拆解表覆盖
（另见 docs/distribution/发行资料清单.md：发行资料 = 剧集 + 封面 + 文案 + 发布清单 + 版权资料）

【故事】
<把你的故事/小说粘在这里>

【规格】
平台：竖屏（TikTok / 红果风格）
集数：30 集，每集约 60 秒（默认口径）；单镜 5–10 个

【硬性要求（不许自行发挥）】
- 资产（人物/场景/道具）一律落 04-资产/{characters,scenes,props}，**禁止**出现在 07-成片/ 下；
  不要自己拼 <out>/assets 路径。新项目用 creation.py scaffold 会自动建好这些目录。
- 发布版成片一律命名 EpisodeNN.mp4（Episode01…Episode40）并落 09-发行/剧集/，
  只用 stages/production/scripts/release_export.py 导出，**不要手工改名**；
  也不要把分辨率/段数/语言/日期写进交付物文件名。
- 不要临时起名、临时挑目录。§3.7 里没有规定的落点或命名，先告诉我要补什么规则，不要自己发明。
- 每一集交付前，跑一遍自动对账（零费用）：
  drama.py preflight → ingest_check.py → script_timing_check.py → drama.py cost --checkpoint
- 所有要花钱的动作（云端出图、云端出片）先报价给我，我同意后再执行；
  出片先做 1 段小样给我看。
- 中途失败/中断一律用 --resume 续跑，绝不重复提交、不重复花钱。

【交付时请给我】
1) 成片（09-发行/剧集/EpisodeNN.mp4）；
2) 成本台账；
3) 一句话说明：哪些文件落在哪个阶段目录（我按你的说明去核对）。
```

## 三、为什么"说这句话"就够用（三条机制）

| 机制 | 说明 | 你要做的 |
|---|---|---|
| **① 规则在仓库里** | §3.3（改编四段法）/ §3.7 / §3.8、复盘文档、pitfalls §F、角色差异化规范、剧本改编四段法都是仓库文件，任何 Agent 读仓库就能拿到，不依赖它的训练记忆 | 提示里**点名让它读这几份**（第一节那句话） |
| **② 工具代替手工** | `release_export.py`（发布版 `EpisodeNN.mp4`）、`migrate_assets.py`（资产归位 `04-资产`）、`release_check.py`（门禁）都是现成命令，正确做法比即兴发挥更省事 | 告诉它"用现成脚本，不要手工改名/手工挑目录" |
| **③ 技能层已加指针** | `short-drama-production` 与 `drama-cover-forge` 的正文顶部已写入"规则真源在 SoloDrama 仓库，冲突以仓库为准" | 无需操作（2026-10-19 已加） |

> ⚠️ **技能层不会自动跟随仓库更新**：技能是方法论与提示词资产，仓库才是规则真源。
> 因此「点名读仓库」这一步不能省 —— 这也是本文件存在的意义。

## 四、老项目：开工前先做两件"归位"（各一条命令）

老项目的资产可能躺在 `07-成片/assets/` 或 `video-pipeline/output/assets/`，
发布版可能叫 `EP01_1080p_ES.mp4`。**两条命令都是默认干跑，看清楚再加 `--apply`**：

```powershell
# ① 资产归位：07-成片/assets（或 video-pipeline/output/assets） → 04-资产
python stages/production/scripts/migrate_assets.py --workspace "<工作区>"            # 干跑：打印清单
python stages/production/scripts/migrate_assets.py --workspace "<工作区>" --apply    # 真搬（自动先备份）

# ② 发布版改名：任意来源 → 09-发行/剧集/EpisodeNN.mp4
python stages/production/scripts/release_export.py --workspace "<工作区>" --all              # 干跑
python stages/production/scripts/release_export.py --workspace "<工作区>" --all --apply      # 真写

# ③ 收尾核验（两条都应通过）
python stages/production/scripts/release_check.py --workspace "<工作区>"   # 退出码 2 = 发行资料不齐/命名不规范
python stages/production/scripts/drama.py status                            # 看「人物资产 / 场景资产」计数是否正常
```

给 Agent 的说法：

```text
帮我检查 <工作区> 的资产和发布版有没有落在新规矩的位置上：
先跑 migrate_assets.py 和 release_export.py 的干跑，把清单发我确认，我同意后再加 --apply。
```

## 五、想确认"我的文件已经是最新"时

```powershell
# 仓库是否最新（本地 HEAD 应等于远端 main）
cd D:\编程\SoloDrama
git fetch "https://gh-proxy.com/https://github.com/Hejunlong27/SoloDrama.git" main:refs/remotes/origin/main
git log --oneline -1 origin/main

# 版本号与本次变更
# README.md 文末「版本记录」表（当前基线 V0.3.1，2026-10-19）
```

> 判断依据不是"助手说它是最新的"，而是 **README 版本记录里的提交号 == `git log -1` 的提交号**。

## 六、常见追问 → 一句话说法

| 你想要的 | 就这么说 |
|---|---|
| 只要封面/发行资料 | 「准备发行资料。先读 `docs/distribution/发行资料清单.md`，封面按 §三 抓马度六抓手（≥5/6），发布版按 §二 用 release_export.py 导出成 EpisodeNN.mp4」 |

| 检查有没有违规 | 「跑 release_check.py 和 migrate_assets.py 干跑，把不合规项列给我」 |
| 想改规则 | 「规则改动请写进 `docs/orchestration/生产流程总纲.md` §3.7 与对应文档，再动手」 |

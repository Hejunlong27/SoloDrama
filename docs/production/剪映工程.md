# 剪映工程（`edit.draft`）—— 机制、边界与验证

> 2026-11-10 新增。这是**并行产物**：让一集成片除了 `EpisodeNN.mp4` 之外，
> 还留下一个能打开、能改、能举证的可编辑工程。
> 口径真源是 `stages/edit/scripts/edit_draft.py`；本文解释「为什么这么做」和「怎么验」。

## 一、为什么加这一层

剪辑链原来是黑箱：`subtitle.py --stage master` 拼母版、`upscale.py` 放大、
`--stage render` 烧字幕、`release_export.py` 出片。它能保证交付规格，但**只交结果、不交过程**：

| 场景 | 只有成片 | 有工程 |
|---|---|---|
| 平台问「这片子怎么做的」 | 只能给 ffmpeg 参数（审核员读不懂，也证明不了） | 逐镜时间轴 + 素材台账 + 字幕对齐来源 |
| 想改一句台词 | 回改配置、整集重跑 | 剪映里改一个文本片段 |
| 想换一段 BGM | 重新混音、重编码 | 拖一段音频 |
| 出片顺序错了 | 查 `_concat.txt` 猜 | 时间轴一眼看到 |

**它不是替代品**：剪映 7+ 已隐藏导出控件，`pyJianYingDraft` 的自动导出只支持剪映 6 及以下，
本仓库不接这条脆弱链路 ⇒ MP4 仍由 ffmpeg 链产出。两者必须一致，不一致等于没有。

## 二、架构与数据来源

```
<成片>/<ep>/<批次>/<shot>/final.mp4 ─┐
<成片>/subs/<ep>/cues.json ──────────┤
09-发行/封面/cover_9x16*.png ────────┼→ edit_draft.py → _draft/<ep>_剪映工程/
<成片>/subs/<ep>/<ep>_bgm-plan.json ─┤                   ├ draft_content.json
configs/edit-draft.json ─────────────┘                   ├ draft_meta_info.json
                                                          ├ draft_manifest.json（清单）
                                                          └ report.json（自检报告）
```

全部**复用现成真源**，不另算一套：

| 内容 | 真源函数 |
|---|---|
| 逐镜片段与顺序 | `subtitle.episode_segments()` |
| 字幕条目 | `<成片>/subs/<ep>/cues.json`（对齐产物，不重算） |
| 画布/帧率/样式 | `subtitle.load_config()` + `configs/subtitle-styles.json` |
| 封面片头时长 | `subtitle.cover_lead_seconds()`（**唯一真源**） |
| BGM 铺排 | `bgm.plan_path / load_library / track_file` |

## 三、四条不可协商的约束

1. **字幕时间必须对齐封面片头**。
   `cues.json` 的起点从第一段画面算起，母版前面还有 `master.cover_seconds`（默认 0.8s）。
   工程里字幕整体后移这个量（记在 `draft_manifest.json::cue_offset_us`）。
   同一偏移也必须加进 ASS 与渲染自检，否则工程与成片差 0.8 秒 —— 送审时「对不上」比没工程更糟。
2. **一律用微秒整数，不碰 `trange`**。
   `pyJianYingDraft.trange(0.2, 1.6)` 返回 `0 → 2` 秒（浮点被四舍五入），
   亚秒偏移与时长会被静默吃掉。本模块只用 `Timerange(start_us, duration_us)`。
3. **自检不过就不许当成材料**。
   `verify()` 读回 `draft_content.json` 逐项核：**画面轨非空**、画布/帧率、每段视频起点与时长、
   每条字幕起点、素材文件是否仍在、总时长、**缺镜清单**。任一项不符 → 退出码 2，节点判不过，门禁不放行。
   两个具体后果（都是实跑踩出来的，不是假想）：
   - **一段画面都没有 ⇒ 直接拒绝生成**（退出码 3），不落空壳草稿。
     实测场景：工作区只搬了 `07-成片`、没有 `shots.json` ⇒ 段列表为空，却造出
     「视频 0 段 / 字幕 9 条」的工程，`verify()` 还报「自检通过」。空工程在剪映里打开就是一片黑。
   - **缺镜 ⇒ 草稿仍落盘，但判不合格**。人要打开看缺在哪、时间轴从哪儿开始错；
     但一份 19/20 镜的工程不能顶着 `pass` 送去平台，那是自证素材不全。
4. **不伪造时间轴截图**。
   机器能产四张结构板，但不能替人证明「我打开过」。第 5 张由人在剪映里截
   （命名 `draft-shot-01-<ep>.png`），门禁对缺它**只告警**。
   四张板末尾都印「这一页证明什么 · 怎么核对」——只写可核对的事实与命令，
   不写承诺（与权利声明页同一套措辞纪律）。

## 四、用法

```bash
# 生成（落 07-成片/<ep>/_draft/）
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01

# 直接进剪映：自动探测草稿位置，生成完启动剪映首页就能看到（推荐）
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01 --to-jianying

# 只看时间轴，不写盘
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01 --dry-run

# 手工指定草稿目录（--to-jianying 探测失败时用）
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01 \
  --drafts-dir "D:/Program Files (x86)/JianyingPro Drafts"

# 工程可整体搬走（素材拷进草稿目录，体积翻倍）
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01 --copy-media

# 版权资料四类板（含工程板）
python stages/production/scripts/copyright_kit.py --workspace "<剧目录>" edit-draft

# 节点 / 门禁
python stages/production/scripts/nodes.py do edit.draft --workspace "<剧目录>" --ep ep01
python stages/production/scripts/release_check.py --workspace "<剧目录>"
```

常用开关：`--no-cover`（工程视频轨不加封面帧）、`--no-draft-cover`（不生成首页缩略图）、
`--no-bgm`（不加 BGM 轨）、`--no-replace`（同名草稿不覆盖）、
`--allow-empty-subtitles`（本集确实无字幕时放行）、`--canvas 1080x1920` / `--fps 30`。

`--to-jianying` 不写死路径：它读
`%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\root_meta_info.json`，
对各草稿的 `draft_root_path` **取众数**当草稿根目录。
不取 `root_path` 字段 —— 那个值在用户改过草稿位置后不会跟着变
（本机实测：`root_path` 指 C 盘默认位置，35 条草稿全在 `D:\Program Files (x86)\JianyingPro Drafts`）。

## 五、产物怎么读

| 文件 | 用途 | 谁读 |
|---|---|---|
| `draft_content.json` | 剪映的时间轴本体（明文 JSON） | 剪映 / 需要程序化核对时 |
| `draft_meta_info.json` | 首页卡片的**名称 / 时长 / 缩略图** | 剪映首页列表 |
| `draft_cover.jpg` | 首页卡片缩略图（首段画面中段抽帧） | 剪映首页列表 |
| `draft_manifest.json` | **人读的对照表**：每段素材路径 + sha256 + 字节 + 逐条字幕 | 审核追问 / 版权板 / 门禁 |
| `report.json` | 自检结论、跳过项、汇总数字 | 排障 |

`draft_manifest.json` 与 `report.json` 落**两处**：`07-成片/<ep>/_draft/`（节点判据只认这里）
和草稿目录内（草稿被整体搬走时证据跟着走）。
`draft_manifest.json` 里的 `verdict` 是节点判据的唯一来源：
目录存在但 `verdict.pass=false` 的工程，节点判 **failed**，因为那份时间轴是错的。

**首页信息必须补**：`pyJianYingDraft` 拷的是空白 `draft_meta_info.json`
（`tm_duration=0`、`draft_cover` 指空），不补的话剪映首页就是「00:00 + 黑块」——
送审时对方第一眼看到的是空壳。本机实测：补上之后卡片立刻从 `00:00 + 黑块`
变成 `01:01 + 真实画面`。

## 六、验证

```bash
python stages/edit/scripts/tests/test_edit_draft.py
```

59 例，全部离线（依赖 ffmpeg 造素材、`pyJianYingDraft` 写草稿；缺任一项相关用例 SKIP 并明确点名）。
覆盖：亚秒精度、封面偏移、dB→线性音量、空 cues 拒绝、**空画面拒绝生成**、
**缺镜判不合格**、端到端生成、**自检能抓到篡改与断链**、**首页时长被改要判不合格**、
`--copy-media`、`--no-draft-cover`、**草稿根目录探测（`draft_root_path` 众数）**、
BGM 轨、dry-run 不写盘、ASS 偏移。

## 七、本机实测记录（剪映专业版 10.8.0.14162 · 2026-11-10）

装在哪、怎么被识别，都是实际跑出来的，不是推测：

| 事项 | 实测结果 |
|---|---|
| 安装目录 | `D:\Program Files (x86)\JianyingPro`（版本目录 `10.8.0.14162`，另存 10.6/10.7 旧版） |
| 草稿索引 | `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\root_meta_info.json` |
| **真实草稿根目录** | `D:\Program Files (x86)\JianyingPro Drafts`（**不是**索引里的 `root_path`，那个还指 C 盘默认位置） |
| 剪映自己写的草稿文件 | `draft_content.json` 与 `draft_meta_info.json` 都是**加密串**（base64 样式），不是明文 |
| 剪映能否读明文 meta | **能**。补写 `tm_duration` / `draft_cover` 后，首页卡片时长与缩略图立即正确 |
| 剪映会不会自动发现新草稿 | **会**。把草稿目录放进草稿根目录，启动剪映 3 秒内自动注册进索引（35→36 条），无需手改 `root_meta_info.json` |
| 索引里 `tm_duration=0` 的含义 | 只是「meta 没写时长」，不代表内容解析失败 —— 别拿它当「剪映读不了明文」的证据 |

⚠ **还没验证的一件事**：双击打开后时间轴是否完整。
这需要人在桌面点一下（脚本所在会话没有交互桌面，不能模拟点击）。
没验证前不要对外声称「工程一定能打开」——只能说「剪映已把工程列出来，时长与缩略图正确」。

## 八、已知边界（不要假装已解决）

| 边界 | 现状 | 影响 |
|---|---|---|
| 剪映字号单位与 ASS 像素不同源 | `configs/edit-draft.json` 给近似值 + 首集目视校对 | 工程字幕字号可能与成片有肉眼差异 |
| 工程存绝对路径 | `--copy-media` 可缓解 | 换机器需重链 |
| 无法自动导出 MP4 | 不接 GUI 自动化（依赖剪映 ≤6.8 + `uiautomation`） | 工程就只是工程 |
| 「能打开」必须人确认一次 | 已确认「被列出 + 时长/缩略图正确」，未确认「时间轴完整」 | 首集打开看一眼，有问题回报现象 |
| 剪映新版本可能改格式 | 现网 10.8.0.14162 实测可用；升级后需重测 | 打开失败时先核对版本 |

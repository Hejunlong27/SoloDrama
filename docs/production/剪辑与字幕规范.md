# 剪辑与字幕规范（v1 · 2026-11-01）

> 本文是**剪辑环节的唯一口径**。顺序、产物名、字幕参数一旦与这里不符，一律以本文为准。
> 对应节点：`edit.master → edit.upscale → edit.subtitle → edit.release`（`nodes.py`）。

## 一、三步顺序（不可换）

```
母版拼接  →  高清放大  →  字幕生成与烧录  →  剪映工程（并行）  →  发布版导出
（封面+片段+BGM）   （RH / Topaz / 跳过）    （对齐→cues→ASS→烧）   （逐镜+字幕+BGM）      （EpisodeNN.mp4）
```

> **剪映工程是并行产物，不是替代品**（2026-11-10 新增，`edit.draft`）。
> 它把「母版拼接」这一步的内部结构摊开成可编辑时间轴，用于版权举证与返工；
> **MP4 仍由第 1–3 步 + 发布版导出产出**，两轨必须一致（`edit_draft.verify()` 逐项核）。
> 详见 `docs/production/剪映工程.md`。

**为什么不能换**：

| 换序 | 后果 |
|---|---|
| 先烧字幕再放大 | 放大模型会把字幕当纹理重绘，描边发糊、字被拉花 |
| 先放大再混 BGM | 要再重编码一次容器；且 `_mix` 与 `_master` 谁是母版说不清 |
| 先混 BGM 再拼接 | 每段单独混会把 BGM 切碎，接缝处音乐断句 |
| 封面放在最后叠 | 会被字幕/归一化裁切，且首帧不是封面（平台抓封面抓到第一镜） |

## 二、第 1 步：母版拼接（`edit.master`）

一条命令产出 `<ep>_master.mp4`，内部固定三段：

```bash
python stages/subtitle/scripts/subtitle.py --stage master --ep ep01
```

| 组成 | 来源 | 缺省行为 |
|---|---|---|
| **① 首帧封面**（可选） | `09-发行/封面/cover_9x16*.png` → 退 `subs/<ep>/<ep>_cover.png` | 找不到就**跳过并告警**，不阻塞出片 |
| **② 视频片段** | `07-成片/<批次>/` 里按 `shot_id` 排序的段 | 逐段做 120ms 音频淡入淡出再拼（`audio.edge_fade_ms`，设 0 关闭） |
| **③ BGM**（可选） | `subs/<ep>/<ep>_bgm-plan.json` | 没有计划就跳过；有就混完覆盖回 `<ep>_master.mp4` |

- 封面片头默认 **0.8s**（`master.cover_seconds`），无音轨时补静音轨，编码参数按**第一段实测值**生成（同 codec / pix_fmt / fps / SAR），否则 `-c copy` 拼不上。
- ⚠ **封面片头会推后整条时间轴**：`cues.json` 从第一段画面算起，母版前面还有这 0.8s。
  所以 ASS、剪映工程、渲染自检三处都必须用 `subtitle.cover_lead_seconds()` 拿到同一个偏移量。
  2026-11-10 之前三处都没加 ⇒ 有封面时**每条字幕早 0.8 秒**，而所有断言都过（它们只比较 cues 自己）。
- 拼接后**必检帧数**：拷贝拼接丢帧 >2% 时改用 concat 滤镜重编码（crf 16）。坏母版比慢更贵 —— 下游放大直接崩。
- 中间文件 `_cover_lead.mp4` / `_fade_NN.mp4` / `_concat.txt` 都留在 `subs/<ep>/`，统一收尾清理。

## 三、第 2 步：高清放大（`edit.upscale`）

```bash
python stages/subtitle/scripts/upscale.py --ep ep01            # 后端由配置决定
python stages/subtitle/scripts/upscale.py --ep ep01 --backend rh
python stages/subtitle/scripts/upscale.py --ep ep01 --backend off
```

| 后端 | 命令 | 成本 | 说明 |
|---|---|---|---|
| `topaz`（默认） | 同上 | 免费 | 本地 GPU，整集约 3–8 分钟，画质最稳 |
| `off` | `--backend off` | 0 | 母版已是交付规格时才用；落 `skipped` 报告，节点据此放行 |

- 产物名 **如实写分辨率**：`<ep>_master_1080x1920.mp4`。旧名 `_master_2k` 只读不写。
- RH 通道节点 4/5 是**短边/长边**，不是宽/高：竖版给 `4=1080 / 5=1920`，给反输出 598×1080。
- RH 输出会按源宽高比吸附（672×1216 → 1062×1920），脚本下载后自动 crop 到精确目标，不补边。

## 四、第 3 步：字幕生成与烧录（`edit.subtitle`）

```bash
python stages/subtitle/scripts/subtitle.py --stage render --ep ep01
```

内部顺序：**对齐（真 CTC/ASR）→ cues → ASS → 交付规格归一化 → 烧录 → 自检**。

- 时间必须来自真对齐（`method ∈ ctc-*/asr-*`）；`script_estimate` 一律重建。
- 交付规格 = **1080×1920 / SAR 1:1 / yuv420p**，crop-to-fill，绝不 pad。
- `cues = 0` 时**拒绝出片**（否则会烧出一条无字幕视频，还叫 `_subbed.mp4`）。

## 五、三语字幕规范（锁死，`configs/subtitle-styles.json`）

改这一份，全部剧集、全部集数同步。基准画布 **1080×1920**，其它画布按 `min(W/1080, H/1920)` 等比缩放。

| 语言 | 字体 | 字号 | 每行 | 两行块高 | 描边/阴影 |
|---|---|---|---|---|---|
| 中文 `zh` | Microsoft YaHei | **58px** | 12 字 | 140px | 3 / 1 |
| 英语 `en` | Arial | **52px** | 26 字符 | 126px | 3 / 1 |
| 西语 `es` | Arial | **50px** | 26 字符 | 120px | 3 / 1 |

**三语共用的位置**：文字块中心 = `0.6 × H`（1080×1920 上 **y=1152**，距顶 6 : 距底 4），
用 `{\an5\pos(W/2, y)}` 逐条定位 ⇒ 一行与两行同线、折行不跳、换分辨率不漂移。

**安全区（平台硬性）**：距底 ≥200px、文本框 ≤70% 画面宽（1080 宽 ⇒ 756px，左右各让 162px）。
上表三语的实际占用：`12×58=696` / `26×0.52×52=703` / `26×0.54×50=702`，都在 756 以内。

**两条硬规则**：

1. 一行字宽超出安全区 ⇒ **报错**，不静默缩字。缩字才是「同一份规范在不同剧里长得不一样」的根因。
2. 落点进 UI 区 ⇒ **报错**，不静默上顶。上顶后 `qa_safe_area` 会按上顶值判过，偏差被藏起来。

改字号时要同时改 `font_px` 与 `max_line_chars`，保证 `font_px × max_line_chars × char_width_em ≤ 756`。

## 六、第 4 步：发布版导出（`edit.release`）

```bash
python stages/production/scripts/release_export.py --apply --ep ep01
```

严格落 `09-发行/剧集/EpisodeNN.mp4`（补零两位）。`release_export` 默认拦不合格成片（规格 / 黑边 / 字幕证据链）。

## 七、常见失败与定位

| 现象 | 原因 | 处理 |
|---|---|---|
| 母版比预期短 0.8s 以外 | 封面没找到，按跳过处理 | 看 `① 首帧封面：跳过 ——` 那行 |
| 母版帧数不足 | 段参数不一致，`-c copy` 丢段 | 脚本已自动重编码；仍不足则查源段 |
| 放大报 805 / moov 缺失 | 输入是 hevc Main10 或坏母版 | RH 分支自动转 h264；Topaz 分支先重拼母版 |
| 字幕偏上/偏下 | 画布与 ASS 的 PlayRes 不等 | `qa_safe_area` 会报；归一化后必须重写 ASS |
| 字幕字号与表不符 | 样式表没被找到（回退旧百分比） | 看报告 `font_size_by` 是否为 `locked(...)` |
| 字幕整体早/晚 0.8s | 封面片头被算/没算进偏移 | 看 `③.0 封面片头` 那行；工程里看 `cue_offset_us` |
| 剪映工程自检不过 | 字幕没加封面偏移 / 片段被改 / 素材被挪 | `stages/edit/scripts/edit_draft.py --dry-run` 先看时间轴再重跑 |

## 八、并行产物：剪映工程（`edit.draft`，2026-11-10）

```bash
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01 --dry-run   # 只看时间轴
```

| 项 | 口径 |
|---|---|
| 落点 | `07-成片/<ep>/_draft/<ep>_剪映工程/`（`draft_content.json` + `draft_meta_info.json`） |
| 清单 | `_draft/draft_manifest.json`（每段素材绝对路径 + sha256 + 字节数 + 逐条字幕） |
| 报告 | `_draft/report.json`（自检结论、跳过项、尺寸汇总） |
| 三轨 | 视频（封面 + 逐镜 `final.mp4`）｜字幕（`cues.json` 逐条）｜BGM（`<ep>_bgm-plan.json`） |
| 画布 | 1080×1920 @ 30fps（`configs/edit-draft.json`，项目可用 `video-pipeline/config.edit.json` 覆盖） |
| 字幕落点 | 文字块中心 `0.6 × H` ⇒ 剪映 `transform.y = -0.2`（与三语规范同一条线） |
| BGM 音量 | 计划里的 `gain_db` 按 `10^(dB/20)` 转线性后 clamp 到 1.0 |
| 不做什么 | **不自动导出 MP4**（剪映 7+ 控件已隐藏）；**不伪造时间轴截图** |

**三个坑（都已写进代码注释，改之前先读）**：

1. `pyJianYingDraft.trange(0.2, 1.6)` 得到的是 `0 → 2` 秒 —— 浮点被四舍五入成整秒。
   本模块一律用 `Timerange(start_µs, duration_µs)`，不碰 `trange`。
2. 工程里的素材是**绝对路径**，换机器即断链。要整体搬走用 `--copy-media`。
3. BGM 库文件必须是**纯音频容器**：带视频轨的 mp4 改名成 `.m4a` 会被
   `AudioMaterial` 直接拒绝（`音频素材不应包含视频轨道`）。

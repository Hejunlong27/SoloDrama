## 零、一页纸

三个判断：

**① 问题不是某个模块坏了，是四件事被绑在同一个开关上。**
「画风」这一个选择现在同时决定：视觉 look、资产规格、叙事模式、交付终点。换一个 look 就连带换掉叙事与交付 —— 这是"3D/2D/真人半解说和画风库串到一起"的根因。

**② 冗余本身就是「串」的来源。**
同一个动作有多套实现时，人（和 Agent）每次都要重新选一遍，选错就串。现状：47 份文档、88 个引擎脚本、81 个 Studio 命令、17 个 `drama.py` 子命令 + `workflow.py` + `pipeline.py` + `project_setup.py` + `model_gate.py` + `style_gate.py` 六个编排入口、三套环节编号、六个状态文件。

**③ 调度器要稳，必须让「下一步」由产物推导，而不是由对话或记忆推导。**
所以引入 Loop：节点状态机 + 四层环 + 变体哈希防抖。LLM 只负责"这一节点怎么写"，**不负责"下一步做什么"**。

整改后：**四维正交 → 一个 `drama.json` → 七环节 23 节点 → 每节点一条命令、一条判据、一条回流边 → 一张能力卡**。

## 二、目标架构

### 2.1 四维正交

```
track     形态：3d_manhua | 2d_animation | live_action
          → 只决定：资产规格 / 单镜时长区间 / 首帧要求 / 分镜拓扑
look      视觉：cinematic | surreal-cinema | cel-anime | guoman-3d-render | ...
          → 只决定：一条 prompt 串。可被任一 track 引用
narrative 叙事：dialogue（默认）| narration
          → 只决定：台词密度 / 旁白配额 / 字幕策略
channel   通道：image{local_comfyui|runninghub} × video{local_h3|rh_h3}
          → 只决定：分辨率 / 时长上限 / 槽位 / 成本。挂能力卡
```

**硬约束（写进校验）**：`looks.json` 条目中禁止出现 `track / narrative / delivery_stop / narration_*`。出现即校验失败。

### 2.2 单一 profile：`<ws>/drama.json`

取代 `style-plan.json` + `model-plan.json` + `project-setup.json`。

```jsonc

  "format": {
    "track": "live_action",
    "look": "surreal-cinema",
    "narrative": "dialogue",
    "aspect": "9:16"
  },
  "episodes": { "count": 30, "seconds": 60, "shots": [5, 10] },
  "channel": {
    "image": { "engine": "local_comfyui", "capability": "comfy.qwen21_t2i_hq.v1" },
    "video": { "engine": "runninghub",    "capability": "rh.h3.multiref.v1" }
  },
  "delivery": { "resolution": "1080x1920", "subs": "burn", "upscaler": "topaz.iris-2" },
  "loop":     { "l0": 2, "l1": 3, "l2": 1, "budget_coins": 2000 },
  "confirmed": { "format_at": "...", "channel_at": "..." }
}
```

## 四、七环节 23 节点（触发 · 判据 · 接替 · 回流）

### 4.1 节点契约格式

每个节点是一张卡，五个字段**缺一不可**：

```
触发     drama do <node-id> [--ep NN]        —— 唯一入口，重复执行结果相同
判据     <机器可判，二值>                     —— 只有通过/不通过，没有"大概"
接替     → <下一节点>（消费 <字段>）           —— 交接靠文件，不靠对话
不过     L1×N → L2: <上游节点> ｜ 人工        —— 回流边白名单，不许自由跳
产物     <落点，唯一，见附录 D>                —— 别处不再生成
```

其中「读」= 接替列里「消费」的那些字段，即上一节点的产物。下表只列 触发 / 判据 / 接替 三个高频项，「不过」按环节统一说明，「产物」见附录 D。

### 4.2 环节 1 · 调研 `research`

| 节点 | 触发 | 判据 | 接替 ↓ |
|---|---|---|---|
| `research.market` | `drama do research.market` | ≥3 市场、每市场 ≥20 条 | `research.breakdown`（消费 `market-data.json`） |
| `research.breakdown` | `drama do research.breakdown` | 每部 ≥5 组「钩子—反转—付费点」 | `research.topic`（消费 `breakdown.md`） |
| `research.topic` | `drama do research.topic` | 七维评分齐全；题材→look 有推荐值 | `script.blueprint`（消费 `position-card.md` + `brief.json`） |

| 节点 | 触发 | 判据 | 接替 ↓ |
|---|---|---|---|
| `script.blueprint` | `drama do script.blueprint` | 每集 ≥1 卖点词；**EP01 卖点词命中 ≥3 行**；单集独立空间 ≤2；每集镜数与字数预算已分配 | `script.episode`（消费 `blueprint.json` 的 `selling_point / shots / words_budget`） |

| `script.continuity` | `drama do script.continuity --all` | 0 硬失败（`[SC-nn]` 编号、台词指纹、E006/E009） | `asset.roster`（消费 HEADER 的 `CHAR: 代号: 身份`） |

**本次新增的两条硬规则**：
1. **卖点词前置**：EP01 必须出现 ≥3 次标题承诺的词。挡的是「标题写契约婚姻、正片 0 次契约」。
2. **字数预算前移**：`blueprint` 阶段按镜分配 `words_budget`，`lint` 只比对"是否超出分配"。现规则 `words > est_sec*3.8` 在 `check` 时才拦，4 秒镜必然判死（19 词 > 15），是个不可满足的规则。

## 五、Loop 调度（调度器稳定性的机制）

### 5.1 为什么要有 loop

短剧生产天然是环：文案生成 → 校验 → 不过 → 改 → 再校验。现在的做法是**人在环里传话**，于是：
- 每次"下一步"靠对话推理，会漂
- 同一个错误被修两遍（改产物 vs 改源）
- 失败静默（EP03 少一段仍交付）
- 反复重跑已通过的东西，白花钱

Loop 的目标：**把环写死，让调度器自己转，转不动就停在一个明确的位置。**

### 5.2 节点状态机

```
absent   无产物
stale    有产物，但输入 sha 与记录不符（上游改过）
failed   最后一次 attempt 不过判据
passed   判据通过
skipped  显式 skip 且留痕（`drama do <node> --skip --reason`）
blocked  前置未 passed/skipped
```

判定顺序（**只看磁盘，不看内存**）：

```
1  有 skip 记录 且 前置全过            → skipped
2  无产物                              → absent
3  input_sha ≠ _done/<node>.input_sha  → stale
4  judge() 通过                         → passed
5  否则                                 → failed
```

`next()`：

```
按拓扑序遍历：
  若 state ∈ {passed, skipped} → 跳过
  若任一上游 ∉ {passed, skipped} → 返回 {node, blocked=true, reasons=[上游]}
  否则 → 返回 {node, blocked=false}
全部 passed → done
```

### 5.3 四层环

| 层 | 名称 | 触发 | 动作 | 预算 | 耗尽 |
|---|---|---|---|---|---|
| **L0** | retry | 瞬时错误：网络 / 上传 / 显存 / 进程超时 | 同节点、同参数重跑，退避 5s→15s | 2 次 | 进 L1 |
| **L1** | repair | 判据不过 | 同节点，**必须变一个变量**（`repair_plan` 给 variant） | 3 次 | 进 L2 |
| **L2** | reflow | L1 耗尽 | 回到白名单上游节点，重跑到本节点 | 1 次 | `blocked_human` |
| **L3** | batch | 集级 | 逐集独立跑；单集 blocked 不阻断他集 | 集数 | 全局 blocked，`edit.release` 不放行 |

**L1 的"必须变一个变量"是硬约束**，靠 `variant_hash` 强制：

```
variant = repair_plan(node, diag)        # 例如 {prompt_tweak: "收紧景别", seed: 新值}
if hash(variant) == last_variant_hash:
    → stuck，跳过 L1，直接进 L2（不浪费一次失败重跑）
```

### 5.4 收敛与反抖动

| 现象 | 机制 |
|---|---|
| 同一件事修三遍 | `variant_hash` 去重，重复即 `stuck` |
| 上游反复被回流 | L2 每节点每集只允许 1 次；第二次直接人工 |
| 重跑已通过的东西 | `input_sha` 未变 → 直接 `passed`，不执行 |
| 计费节点重复花钱 | 计费节点先写 `_spend/<node>.json`（task_id + 金额），重入先比对，已花不重花 |
| 判据宽松导致假通过 | 判据必须二值且可复算（`ingest_check` 已具备），不接受"人工看过了" |

### 5.5 终止条件与退出码

| 码 | 含义 | 谁产生 |
|---|---|---|
| 0 | passed / done | 判据通过 |
| 2 | 判据不过（L1+L2 用尽） | 节点 |
| 3 | 预算超限 | `video.resolve` / 每个计费节点前 |
| 4 | 等待人工确认（format / channel 未 confirmed） | `next` |
| 5 | stuck（variant 无变化） | L1 入口 |
| 6 | 环境或能力卡不满足 | `caps check` / `doctor` |

**停机只有一个理由**：L2 耗尽或退出码 ≠ 0。不停在"看起来差不多"。

### 5.6 幂等与断点

每个节点跑完写 `_done/<node>.json`：

```jsonc
{ "node": "board.frame", "ep": "ep02",
  "artifact": ["05-分镜/boards/ep02/shot_001.png", "..."],
  "artifact_sha": "…", "input_sha": "…",
  "variant_hash": "…", "attempt": 2, "at": "2026-11-01T12:30:00+08:00" }
```

- 重入时 `input_sha` 一致 → `passed`，跳过
- Ctrl-C 后 `drama resume` 从 `next()` 继续，不需要记"跑到哪了"
- 任何节点都可以单独 `drama do <node>` 重放

### 5.7 调度器三不变量

1. **单向**：只按拓扑序前进；回退只能走 §4.9 的 19 条白名单边。
2. **可重放**：一次 `do` 的结果只取决于 (inputs, capability, variant)，与历史无关。
3. **可停止**：任意时刻中断，状态由磁盘产物推导，不依赖进程内存或对话记录。

### 5.8 LLM 在环里的位置（关键）

| 谁 | 决定什么 | 不决定什么 |
|---|---|---|
| 调度器（确定性代码） | 下一步是哪个节点、能不能进、回不回 | 内容写什么 |
| LLM | 这一节点**怎么写**（剧本正文 / 分镜描述 / 提示词装配 / 修复变体） | 下一步做什么、跳过哪一步、要不要计费 |

一句话：**流程归代码，内容归模型。** 这是调度器能稳的唯一办法 —— 一旦让模型每次自己推流程，就一定会漂。

内容节点（`script.episode` / `board.script` / `asset.prompt`）的 LLM 调用也走命令：`drama do <node>` 内部读提示词原文 → 调网关 → 落 `llm-drafts/` → 判据过了才 `confirm` 写产物。

### 5.9 一个完整的 loop（真实场景）

EP03 的 `shot_008`（钩子镜）放大失败，成片 58.87s 而剧本 66s —— 现状是**照样交付**。新机制下：

```
L3  batch      : 逐集跑，ep03 进入
     video.batch  : 8/8 提交，shot_008 返回 805
     video.audit  : 发现 7/8，判据不过 → failed
L1  repair     : attempt1 = {重试该镜, 原参数}
                 attempt2 = {重试该镜, 降 megapixels 0.8→0.6}
                 attempt3 = {换 src 时长 9→8.5s}
                 仍不过 → variant 用尽
L2  reflow     : → video.batch（白名单边 audit→batch），只补 shot_008
                 补跑成功 → 8/8 → passed
L2  若仍失败    : blocked_human，退出码 2，**edit.* 不启动**
```

对比现状：`upscale_rh.py` 把失败写进 summary 但不让进程失败，`pipeline_ep.py` 不校验 → 拿 7 段拼了一集。**新机制里这条路径不存在。**

## 七、出片改造：分镜图 + 角色 + 场景

### 7.1 分镜图 ≠ 站位图

| | 站位图（已弃用） | 分镜图（本次） |
|---|---|---|
| 形态 | 俯视平面图 / 黑白线稿 | 与成片同构的 9:16 摄影画面 |
| 给模型的信息 | 调度（提示词已能写清） | **构图（提示词写不清）** |
| 风险 | 模型会复刻平面图 | 无 —— 与目标视频同模态 |
| 增益 | 双人镜实测无增益 | 直接锚定每镜机位与画面密度 |

上次"站位图对成片无增益"的结论**只对俯视平面图成立**。这次解决的是另一个问题：多参只给角色卡和场景卡时，两者的构图都不是本镜的构图，模型每镜都在重新猜机位。

### 7.2 契约：四文件 → 五文件

```jsonc
// 新增 06-提示词/data/boards.json
{ "shot_001": "../05-分镜/boards/ep01/shot_001.png" }

// shots.json 每镜
{ "shot_id": "shot_001",
  "board_refs": ["shot_001"],          // 新增
  "character_refs": ["char_pruitt"],
  "scene_refs": ["scene_ward"],
  "ratio": "9:16",
  "crop": { "rows": 1, "cols": 1 } }
```

### 7.3 槽位顺序（不可逆）

`分镜图 → 角色(1..n) → 场景`，`<Picture n>` **机械注入**：

```
<Picture 1> the composition of this shot — board only, no faces, no text
<Picture 2> ELLE — identity
<Picture 3> KANE — identity
<Picture 4> the location only, empty
```

`ingest_check` 新增断言：`<Picture n>` 最大编号 == 实际发送图片数，不等即 FAIL。

### 7.4 分镜图提示词要点

- 人数按 `CHAR` 动态生成，**不写死 1**
- 必须显式禁拼版：`a single frame, not a storyboard sheet, not a contact sheet, not a 3x3 grid`
- 负向：`text, letters, numbers, signage, labels, watermark, multiple panels, split screen, border`
- 耗时 ≈50s/张（本地 2MP）

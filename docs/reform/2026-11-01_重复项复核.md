> 用途：把「同一个功能有几份实现」列清楚，由 Owner 按编号决定删/并/留。

> 判定口径：重复 = 同一件事有两处可执行入口，或同一事实有两处维护。

`web/core/adapters.py` 仍然指向 **已删除的 `workflow.py`**：

```

adapters.workflow_status() → run_json("workflow", ["status", ...])     → {"ok": false, "reason": "script_missing"}
```

实测（fixture 工作区）：`ok=False / reason=script_missing / stages=0`。
调用方 5 处：`app.py::/api/overview`、`assistant.py` 4 处、`pipeline.py::plan`、`studio.py::overview`。
⇒ **Studio 的「流程总览 / 助手上下文 / 流水线推进」三块全部静默失效**（UI 显示"未接入"，不报错）。

## D5 · 两套流程模型（★ 已造成 Studio 失效，优先级最高）

| 模型 | 真源 | 状态 |
|---|---|---|
| 7 环节 23 节点 | `nodes.py`（`drama next/do/nodes`） | 现行，一直在维护 |
| 11 环节 S1–S11 | ~~`workflow.py`~~（已删） | **Studio 仍在用**（`adapters.workflow_status`） |

- 后果见文首：Studio 三块功能静默失效，且"下一步该做什么"在 CLI 与 UI 上是两套答案。
- `web/core/pipeline.py` 按 11 环节连跑，`drama next` 按 23 节点推进 —— 同一问题两个答案。
- 建议（三选一）：
  1. **接回真源**：`adapters.workflow_status()` 改调 `nodes.py status --json`，把 23 节点按 `stage` 分组渲染成 7 个环节；
     `pipeline.py` 的推进单位从环节改为节点。工作量中等（adapters + pipeline + 3 处 UI 字段），风险低。
  2. **只读降级**：Studio 流程总览改为只显示 `drama nodes` 的 23 行清单，不做"S1–S11 环节"叙事。工作量小。
  3. **删掉视图**：移除流程总览与流水线推进两块，Studio 只留资产/集数/成本/发行。工作量最小，但功能缩水。
- 我的建议：**方案 1**（一次修到位，之后 UI 与 CLI 只有一个答案）。

## D8 · 字幕视觉参数两份（★ 本轮 V0.7.43 引入）

| 位置 | 内容 |
|---|---|
| `configs/subtitle-styles.json` | 三语 font/font_px/max_line_chars/margin_lr_px/outline/shadow（**真源**） |
| `stages/subtitle/assets/config.subtitle.example.json` 的 `languages.*` | 同名字段各一份（zh/es 两段，共 20 个值） |

- 运行期是"styles 覆盖 languages"，不会打架；但同一事实两处维护，改字号要改两处才不会让回退路径失真。
- 收敛的代价：`config.subtitle.json` 里那些字段是**旧百分比回退算法**的输入（无 styles 时用）。
  删掉它们 = 删掉回退路径 = 没有 styles 就跑不了。
- 建议：**保留回退，但把 example 里的视觉字段标成 `_deprecated` 注释掉的形态**（JSON 不支持注释，可改名为
  `font_size_pct_legacy`）；或直接删回退分支，让「找不到 styles」= 明确报错。二选一，需 Owner 定。

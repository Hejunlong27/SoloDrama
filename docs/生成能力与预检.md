## 2. 为什么「预检」是这次的主要产出

批量生成的失败方式不是「崩」，而是**每镜各失败一次**：8 镜 ×（上传参考图 + 等 400）
足够耗掉半小时，最后只得一句「8 项无产物」，而真因是少一个 `.safetensors`。
所以判据要在**提交前**给出，并且点名到文件。

### 判据（六项，缺一不可）

| 检查 | 来源 | 失败时说什么 |
|---|---|---|
| 出网守卫 | `_netguard.would_allow` | 域名没点名 → 给可直接复制的 `SOLODRAMA_TRUSTED_HOSTS` |
| 在线 | `GET /system_stats` | 「启动 ComfyUI」或「实例没开机 / 8188 未映射」 |
| 版本 | 同上 | 要求 ≥ 0.42.1（`convrot` 量化格式下限） |
| 节点类 | `GET /object_info` | 点名缺哪个 `class_type` |
| 模型文件 | Loader 的 `enum` | 点名缺哪个文件（**不是** `node type missing`） |
| 必需输入 / 映射 | `object_info` + sidecar map | 连线缺口、映射指向不存在的节点 |

★ 映射只在**存在 sidecar map** 时校验：没有映射文件时 `load_map()` 会回落到视频侧内置默认，
拿它去查图像工作流必然「images → #24 不存在」——那是假阳性，会把可用判成不可用。

## 3. 三个入口（同一份判据）

```bash
# ① 只看不跑（最常用；不需要集号）
python stages/production/scripts/gen_preflight.py --workspace "<剧目录>"
python stages/video/comfyui/comfy_batch_video.py --check --workspace "<剧目录>"

# ② 体检总表里的一段（deps / gen / rh / engine / config / dryrun）
drama preflight --only gen

# ③ 真跑时自动跑
drama assets --engine local --submit    # 出图前自动预检（--skip-check 可跳过）
drama video run --engine local --ep 01 --yes   # 出片前自动预检（同上）
```

判据链：`gen_preflight` → `cloud.health.probe` → `/system_stats` + `/object_info`。
三处入口都调同一条链，**没有再实现第二份**（两份判据迟早分叉，那时人会先信错的那份）。

## 4. 本次修掉的六处「口径错误」（都不是跑不动，而是说错）

| # | 问题 | 之前的后果 | 现在 |
|---|---|---|---|
| 1 | 图像工作流被**视频**内置映射误判 | 可用被判「缺文件 / 映射错误」 | 无 sidecar 不校验映射 |
| 2 | 生成通道页 `VIDEO_LOCAL_WF` 指向旧 `workflow_h3_local.json`，而真跑是 `canvas` | 页面核 A、实跑 B | 与 `comfy_local_video.DEFAULT_WORKFLOW` 同源 |
| 3 | 通道页不应用 `_substitute` | 报缺「原始文件名」，而实际有量化版 | 应用替换后再核对 |
| 4 | 通道页对图生图的描述是「未内置工作流」 | 让人去重导一份已存在的文件 | 改为「客户端支持、批量入口未接」 |
| 5 | **批量出片完全不预检** | 每镜各失败一次 | 提交前预检，`--skip-check` 可跳过 |
| 6 | 出图批量只查「在线」 | 缺模型时每张图各失败一次 | 提交前跑完整预检 |
| 7 | `drama preflight` 只看 RunningHub | 本地/云端缺件时体检全绿 | 新增【1/6】生成通道路段 + `--only` |
| 8 | 通道页没有云端两行 | 看不出「云能不能用」 | 确认了云端就出现 `image.cloud.t2i` / `video.cloud.i2v` |

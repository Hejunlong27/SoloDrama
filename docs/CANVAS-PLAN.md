# 画布：设计方向与落地方案

> 目标不是「做一个 ComfyUI」，是**让一集 60 秒的镜头在屏幕上变成可看、可点、可拖的东西**。

## 一、先定边界：不做通用节点编辑器

通用节点编辑器（自由加节点、自由连线、写表达式）在这个项目里会失败，理由是具体的：

1. **节点类型是领域固定的**。一条短片只有四类东西：参考图、提示词、生成任务、产物。
   允许自由加节点，用户会拼出「两张参考图接一个文本节点再接到视频」这种跑不通的图，
   而报错要到提交给 ComfyUI 时才出现。
2. **连线不是自由的**。镜头的参考图顺序就是 `cast` 数组顺序，改了它等于改提示词里的
   `{{Mixed n}}` 图号 —— 那是必须成套改的，不是拖一根线。
3. **本项目零构建**（`web/ui/studio/js/` 全是 ES module，没有打包器）。引入 React Flow
   这类库要上构建链，代价远大于收益。

**所以做三个"专门的画布"，而不是一个通用的。** 每个画布只表达一种结构，用户不需要学。

## 二、三个画布

### 2.1 剧集画布（Series Canvas）—— 横向时间，纵向集数

```
       镜1    镜2    镜3    镜4    镜5    镜6    镜7    镜8
 ep01  ●───   ●───   ◐───   ○      ○      ○      ○      ○
 ep02  ●───   ●───   ●───   ●───   ◐───   ○      ○      ○
 ep03  ○      ○      ○      ○      ○      ○      ○      ○
```

- `●` 出片完成 · `◐` 有分镜图没出片 · `○` 空
- 一格 = 一镜。点开进「镜头画布」
- 一眼看出「哪几集还没动」「哪一批卡在同一镜」
- 缩放到很小时，一格退化成一条色块，看见的是整季的密度

**它解决什么**：现在想知道「30 集做到哪了」要翻四个目录。这张图一屏答完。

### 2.2 镜头画布（Shot Canvas）—— 一个镜头的四段链

```
[参考图 P01]──┐
[参考图 P02]──┼──▶ [提示词 shot_003] ──▶ [生成 6s] ──▶ [产物 final.mp4]
[场景 S01  ]──┘                                      └▶ [首帧 shot_003.png]
```

- 节点固定在一条主链上，**位置可以拖但拓扑不变**
- 点节点开右侧属性面板（复用现有 `field` 组件），改完立刻回写
- 参考图节点上直接显示缩略图；产物节点上显示视频首帧（`<video preload=metadata>` 取帧）
- 缺失的节点用虚线框 + 「缺什么」文案，不是红色警告块

**它解决什么**：一镜出问题（人物不像 / 时长不对 / 参考图串景）时，
现在要分别打开 4 个 json 对照。这里一屏看到四段的关系，且能直接改。

### 2.3 管线画布（Pipeline Canvas）—— 从灵感到成片的七段

```
[灵感] → [企划案] → [资产库] → [剧本] → [导演手册] → [制作包] → [出片]
```

- 节点是「创作页」已有的七段，这个画布是它的**空间版**：可以拖成自己的习惯顺序
- 每段上显示真实进度（企划案 440 字 / 30 集已导入 / 8 镜已出片）
- 点节点打开对应面板，不是跳页

**它解决什么**：现在的流水线条是横排小圆点，只能表达"做了/没做"。
画布能表达"我把它拖成两列，左边创作右边执行"，这是使用者的空间记忆。

## 三、技术选型

| 项 | 选择 | 为什么 |
|---|---|---|
| 渲染 | **DOM + `transform: translate/scale`** | 单画布节点数 < 200，DOM 够用；Canvas 2D 要自己实现命中测试/文字换行/输入框，而输入框在画布上必须能直接打字 |
| 拖拽 | Pointer Events（`pointerdown/move/up` + `setPointerCapture`） | 不用库；触屏/笔/鼠标一套代码 |
| 缩放 | `wheel` + `ctrl` 修饰，`0.35× – 2.5×` | 低于 0.35 文字不可读，高于 2.5 没有信息量 |
| 连线 | SVG `<path>` 覆盖层（`pointer-events:none`） | 线不参与命中测试，避免挡住节点 |
| 布局持久化 | `<ws>/canvas.json`（每个画布一份坐标） | 放工作区而非浏览器 localStorage：换机器/换浏览器位置还在 |
| 网格 | CSS `background-image` 两向 `linear-gradient` 画 24px 点阵 | 不引图片，缩放时跟着 `background-size` 走 |

## 四、视觉规范（在现有基础上收紧，不重做）

现有 token 已经符合要求：深石墨底（`#0d0f12`）、低对比面板（`#14171c/#191d23`）、
细线（`#232830` 1px）、圆角统一 3/4/6/8/10、阴影只给浮层。**沿用。**

新增/调整四处：

| 项 | 值 | 理由 |
|---|---|---|
| 创作链强调色 | `--create: #8b7ff5`（蓝紫） | 琥珀已承担「品牌 + 花钱/注意」，换掉会让存量页面失去「花钱=琥珀」的约定。创作是另一条流水线，给它独立身份 |
| 节点面 | `--bg-card` + 1px `--line`，选中时 `--create-line` | 不做玻璃拟态、不加渐变、不加外发光 |
| 节点状态 | 完成 `--ok` / 进行中 `--create` / 空 `--txt-disabled` | 三种就够；加第四种（警告）会让人开始研究颜色而不是内容 |
| 画布底 | `--bg-inset` + 24px 点阵 | 比页面更深一档，让画布"凹"进去 |

**明确不做**：大圆角卡片、模块级渐变背景、发光边框、彩色阴影、装饰性图表。
高级感来自比例、留白、信息层级 —— 这些是排版问题，不是配色问题。

图标沿用现有 `ICONS`（`web/ui/studio/js/ui.js`），不引入 Lucide 依赖（现有图标集
已经是 Lucide 风格的单线图标，再引一套会不一致）。

## 五、数据从哪来

**不需要新后端。** 三个画布读的都是已有契约：

| 画布 | 数据源 |
|---|---|
| 剧集画布 | `06-提示词/<ep>/shots.json`（镜数与 shot_id）、`07-成片/<ep>/<shot>/final.mp4`（是否出片）、`04-资产/boards/<ep>/`（有无分镜图） |
| 镜头画布 | `shots.json` 的 `cast` / `board_ref`、`h3_prompts.json` 的 `prompt`/`duration`、`characters.json`+`scenes.json`（参考图路径） |
| 管线画布 | `/api/create/state`（已有）+ `/api/studio/overview` |

只新增一个接口：`GET /api/canvas/series?ws=`，把上面三处的状态聚合成一张格子表
（避免前端发 30×8 个请求）。

## 六、分期

| 期 | 内容 | 验收 |
|---|---|---|
| **P1** | 剧集画布（只读）+ 镜头画布（只读，点节点看详情） | 打开一集能看到 8 个格子的真实状态；点格子看到四段链和参考图缩略图 |
| **P2** | 拖拽 + 缩放 + 布局持久化 + 管线画布 | 拖过的位置关掉浏览器再开还在；滚轮缩放跟手不抖 |
| **P3** | 镜头画布可编辑（改提示词/时长/参考图顺序，回写 `shots.json`）+ 批量操作（选多镜重跑） | 改一个镜头的时长，磁盘上的 `h3_prompts.json` 跟着变，且 `ingest_check` 仍然通过 |

**P1 只读是刻意的**：画布第一版最容易犯的错是先做编辑。只读版能让人立刻判断
「这个空间结构对不对」，改结构比改交互便宜十倍。

### 已落地（2026-11-04）

剧集画布 P1 已实现：`web/core/canvas.py` + `#/canvas`，口径见 `web/STUDIO.md` §16。

落地时改了方案里的三处，理由都是实测：

| 方案 | 实际做法 | 为什么 |
|---|---|---|
| 半格 ◐（左半边填满）表示「有分镜图」 | 淡青底 + 中心小方块 | 8 列 × 30 行时半格会和相邻虚线格拼成条纹，整片像条形码 |
| 缺口统计放表格底部 | 放表头第二行（吸顶） | 30 行时底部那行永远看不见，而它正是最该一眼看见的 |
| 集号轴 = 已有集 | 已有集 ∪ 目标集数（`drama.json`） | 只画已有集，等于把「哪 27 集还没动」又丢回目录 |

**镜头画布**（P1 的另一半）目前以**抽屉**形式给出：点一格看到参考图缩略 → 提示词原文 →
时长/画幅 → 成片可播的四段链。空间版（节点位置可拖、SVG 连线）留在 P2 一起做，
因为拖拽与缩放是同一套坐标系，分开做要写两遍。

## 八、P2 落地记录（2026-11-04）

剧集画布（全季网格）留在 `#/canvas`；**节点画布**做在 `#/graph`，两者共用 `web/core/canvas.py`
与 `graph.py` 的同一套磁盘口径。

与本文原方案的差异，都是实测后改的：

| 方案 | 实际 | 为什么 |
|---|---|---|
| 三个画布（剧集/镜头/管线） | 两个页面：全季网格 + 节点图（镜头信息进节点抽屉） | 「镜头画布」的四段链在抽屉里已经能看全；单独做一个只装一镜的画布，使用频率撑不起一个页面 |
| 拓扑分层自动排布 | 语义列（创作 / 导入资产 / 分镜图 / 出片 / 剪辑） | 本图是 18 节点 17 条边的链，拓扑分层会排成 4500px 一行，缩到 35% 才能看全 |
| 自由连线 | 允许，但**不改变执行顺序**（虚线=意图） | 让画布改依赖 = 白烧 GPU 的坑重新挖开 |
| 布局存 `<ws>/canvas.json` | 同 | 换机器位置还在（已实现并测试） |

未做：缩放后的节点文字重排（当前是靠 `-webkit-line-clamp` 截断）、多选框选批量重跑（P3）。

## 九、P3 落地记录（2026-11-04）

单镜可编辑（时长 / 提示词 / 参考图顺序）+ 批量重跑，验收标准「改完时长 `ingest_check`
仍通过」已达成（真实项目 ep01 实测：13 镜门禁通过）。

与本文原方案的差异：

| 方案 | 实际 | 为什么 |
|---|---|---|
| 相机画布可编辑，回写 `shots.json` | 回写 `h3_prompts.json`；`shots.json` 只在改顺序时同步 `cast` | 顺序的真源是提示词里的「上传顺序」行，`shots.json` 的两张分表已经丢了顺序（实测 shot_002：提示词 P02,S01,D11，分表拼出来 P02,D11,S01） |
| 参考图顺序用拖拽 | 上移/下移按钮 | 抽屉只有 560px 宽，3–6 项的列表用两个按钮就够；拖拽要处理滚动容器内的自动滚屏 |
| —— | 第 1 项（分镜图）锁死 | 它固定在 `<Picture 1>` 槽位，挪它是换槽位不是调顺序 |

**没做的**：跨集批量重跑。出片引擎按集跑（单例锁也按工作区），跨集没有「一次跑完」的语义；
界面在选中跨集时说明原因。

三个实测踩到的坑，都写进了 `web/STUDIO.md` §16.5：
备份时间戳只到秒会互相覆盖、写盘没沿用 CRLF 会让 diff 变成整文件、`str.replace` 改图号
会连正文里的数字一起换掉。

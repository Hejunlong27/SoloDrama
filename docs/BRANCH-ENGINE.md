# 分支 `feat/pack-engine`：引擎只做批量执行

> 建立于 2026-11-02，从 `main` 分出。目标：把 SoloDrama 从「创作 + 执行的全链路引擎」
> 收敛成「**只负责批量出图、批量出片、剪辑交付**的执行引擎」，创作能力全部交给可插拔的
> 创作 Skill（示例：`tianchong-manju` 总裁甜宠 AI 漫剧）。

## 一、为什么分叉

`main` 上的 SoloDrama 同时承担两件事：

1. **创作**：选题打分、爆款拆解、剧本四段法、剧本门禁、角色差异化设计、分镜转换、提示词装配。
2. **执行**：批量出图、出分镜图、出视频、字幕、放大、剪辑、交付校验。

这两件事的演进速度不同、用户不同、失效方式也不同：

- 创作靠审美与题材判断，迭代以「天」计，且**同一套规则不适用于所有题材**。
  把甜宠的节奏规则写进引擎，做悬疑时就成了负担。
- 执行靠平台约束与成本控制，迭代以「周」计，且**换题材不会变**。

`main` 把两者焊在一起，结果是每接一个新题材，都要改引擎里的剧作代码。
本分叉把创作整体外移，引擎只保留一份**稳定的输入契约**。

## 二、能力边界

### 2.1 保留（执行层）

| 环节 | 能力 | 入口 |
|---|---|---|
| 导入 | 制作包校验 → `data/` 契约 | `stages/import/pack_import.py` |

| 分镜图 | 每镜一张 9:16 首帧 | `gen_boards.py` |
| 入厂门禁 | 五文件完整性 + 图实体校验 | `ingest_check.py` |
| 视频出片 | 本地 ComfyUI 出片 | `stages/video/comfyui/` |
| 剪辑 | 母版拼接（帧数校验） | `subtitle.py --stage master` |
| 剪辑 | 高清放大（Topaz） | `upscale.py` |
| 剪辑 | 字幕对齐 / 生成 / 烧录 | `subtitle.py --stage align/cues/ass/render` |
| 交付 | 交付规格归一（crop-to-fill） | `delivery_spec.py` |

### 2.3 判定依据

一个能力属于哪一层，只问一句：

> **换一个题材（甜宠 → 悬疑 → 出海西语），它要不要改？**

- 要改 → 创作层，移出引擎。
- 不改 → 执行层，留在引擎。

按这条线，`FFS 格式`、`五锚连续性`、`台词密度 ≥10 句/60s`、`旁白 ≤2 条/集`
全部是创作层规则——它们对甜宠成立，对默片式悬疑不成立。

## 三、流程对比

### 3.1 旧流程（`main`，七环节 24 节点）

```
调研 → 剧本 → 资产 → 分镜 → 提示词 → 出片 → 剪辑
  ↑      ↑      ↑      ↑       ↑
  └──────┴──────┴──────┴───────┴── 引擎内的创作代码
```

### 3.2 新流程（本分支，五环节）

```
        ┌───────────────── 引擎之外 ─────────────────┐
        │  创作 Skill（可插拔）                        │
        │  选题 / 剧本 / 资产设计 / 导演 / 分镜 / 提示词 │
        └───────────────────┬────────────────────────┘
                            │ 制作包（PACK-SPEC v1）
        ┌───────────────────▼────────────────────────┐
        │  ① import   校验 + 翻译成 data/ 五文件        │
        │  ② asset    批量出资产图                      │
        │  ③ board    批量出分镜图（每镜首帧）           │
        │  ④ video    批量出视频段                      │
        │  ⑤ edit     拼接 → 放大 → 字幕 → 交付 → 发布   │
        └────────────────────────────────────────────┘
```

**边界只有一个：制作包。** 包内是 JSON（或按模板写的 Markdown），包外引擎不读任何创作文档。

## 四、工作区目录

保留编号，删除 `01-调研` / `02-选题`：

```
<剧项目>/
├── pack/                     ← 创作 Skill 的产出（只读，引擎不改）
├── 03-剧本/                   ← Skill 的剧本原文（只读，字幕取文本用）
├── 04-资产/                   ← 出图产物 characters/ scenes/ props/ boards/ refs/
├── 05-分镜/                   ← Skill 的导演手册原文（只读，留档）
├── 06-提示词/                 ← data/ 五文件（引擎输入契约，导入生成）
├── 07-成片/                   ← 批次产物、母版、2K、字幕成片
├── 08-合规/                   ← 发布前预检、整改记录
├── 09-发行/                   ← 剧集/EpisodeNN.mp4、封面、文案、版权资料
└── video-pipeline/            ← 引擎技术目录（config / ledger / logs）
```

规则不变：同一份产物只在一个阶段目录里；阶段之间靠引用衔接。

## 五、旧项目怎么办

`main` 上已跑过的项目**不需要迁移就能继续出片**：

- `data/` 五文件已有 → 直接进 ②③④⑤ 环节，跳过 ①。
- `03-剧本` / `05-分镜` 留着不动，引擎不读它们。
- `01-调研` / `02-选题` 变成普通目录，引擎不再创建也不再检查。

只有「想在新分支里从头做一部剧」时，才需要制作包。

## 六、不做什么

- **不内置任何题材规则**。引擎不知道「甜宠」和「悬疑」的区别。
- **不猜提示词**。`prompt` 字段逐字提交，空就是空，缺就是缺。
- **不做画风切换**。`style_lock` 一次定死，换风格 = 新项目。
- **不做字幕文案生成**。字幕文本来自剧本或 ASR，引擎只做时间对齐。
- **不做发布文案**。标题、简介、话题标签都在 Skill 的发布包里。

## 七、验收标准

| # | 标准 | 判定 |
|---|---|---|
| 1 | `stages/creation/` 不存在 | `ls` 为空 |
| 2 | 引擎代码里不出现题材词（甜宠/悬疑/霸总/女频） | `grep` 零命中 |
| 3 | 一个制作包能导入成合法 `data/` 五文件 | `pack_import --dry-run` 退出码 0 |
| 4 | 总裁甜宠 Skill 的 Markdown 能经通道 C 转成制作包 | 端到端干跑通过 |
| 5 | 离线测试全绿 | `pytest` 32 个 `test_*.py` 全过 |
| 6 | 已有项目的 `data/` 不改也能出片 | 旧项目 `ingest_check` 通过 |

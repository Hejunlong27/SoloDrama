# 标准作业流程（11 环节）· 单一真源

- 版本：v1.0 ｜ 日期：2026-10-21
- 地位：**本文档规定「一部剧从头到尾按什么顺序做」，机器真源是同目录的
  `stages/production/scripts/workflow.py`（`STAGES` 常量）**。两者不一致时以代码为准，并回来改本文。
- 与 `生产流程总纲.md` 的关系：总纲管「硬规则 / 门禁 / 落点」，本文管「顺序 / 前置条件 / 无人值守」。
  总纲的 16 环节是**功能分解**，本文的 11 环节是**执行顺序**，映射表见 §四。

---

## 一、为什么需要「顺序」这一层

2026-10-20 / 10-21 两轮端到端实跑，最大的浪费不是某个脚本报错，而是**顺序失控**：

| 事故 | 根因 |
|---|---|
| 出了 10 张角色图才发现画风锁错（3D 锁 + 真人提示词） | 画风没在**任何产出之前**确认 |
| 提交了 8 段任务才发现提示词没转换（`data/` 四文件缺） | 转换门禁在计费之后才跑 |
| 烧了字幕才发现没放大到 1080P | 后期三环节顺序靠人记 |
| 发行资料与成片互等，卡在"物料齐、只差成片" | 五类产物被当成同一批次并列项 |

共同点：流程只写在文档里，**没有可执行的产物判据**。所以本流程给每个环节配了
「判据（产物存在性 + 最少条数）+ 门禁（前置未完成即退出码 4）」，
命令是 `workflow.py status / check / skip`。

## 二、11 环节（顺序不可调）

| # | 环节 | 类型 | 落点 | 完成判据 | 标准命令 |
|---|---|---|---|---|---|
| **S1** | 调研 | 内容 | `01-调研/` | `market-data.json` | `creation.py market` / `breakdown` |
| **S2** | 剧本 | 内容 | `02-选题/` + `03-剧本/` | 定位卡 + `blueprint.json` + `ep_*.md` ≥ 集数 | `creation.py topic` → `script_rewrite.py diagnose/plan/review` → `audience --check` |
| **S3** | 资产设计 | 内容 | `04-资产/design/` | `character-bible.json` + `prompts/**/*.txt` | `character_design.py plan` → `check` → `asset_md.py` |
| **S4** | 资产生成 | 自动 | `04-资产/{characters,scenes,props}` | 图 ≥1 + `refs.json` | `drama.py assets --engine <local\|rh> --submit` + `refs --apply` |
| **S5** | 视频提示词 | 内容 | `05-分镜/` + `06-提示词/` | 分镜 md + `data/{shots,h3_prompts}.json` | `convert_storyboard --apply` → `ingest_check` → `script_continuity --all` |
| **S6** | 视频生成 | 自动 | `07-成片/<批次>/` | `final.mp4` ≥ 镜数 | `drama.py video plan` → `video run --yes` |
| **S7** | 发行资料准备 | 内容（**可选**） | `09-发行/` | 封面 + 文案 + 发布清单 + 版权资料 4+4 | `cover_prompt.py` → 出图 → `release_check --material-only` |
| **S8** | 视频拼接 | 自动 | `07-成片/subs/<ep>/` | `*_master.mp4` ≥ 集数 | `subtitle.py --stage master` |
| **S9** | 视频放大 | 自动 | 同上 | `*_master_2k.mp4` ≥ 集数 | `subtitle.py --stage upscale` |
| **S10** | 字幕烧录 | 自动 | 同上 | `*_subbed.mp4` ≥ 集数 | `subtitle.py --stage ass` → `--stage render` |
| **S11** | 定稿输出 | 自动 | `09-发行/剧集/` | `EpisodeNN.mp4` ≥ 集数 | `release_export --all --apply` → `release_check` |

**三条纪律**

1. **顺序不可调**：`workflow.py check --stage S6` 会在前置环节未完成时返回退出码 4。
2. **跳过必须留痕**：只有用户明确要求才允许 `workflow.py skip <ID> --reason "..."`，
   写进 `<ws>/workflow-state.json`；下游独立门禁（`ingest_check` / `release_check`）仍会各自拦。
3. **判据以产物为准**：手工 `done` 只对内容环节有意义；自动环节必须真有产物，
   否则 `pipeline` 会报「跑完但判据未满足」。

**S7 为什么是可选的**：封面/文案/版权资料属内容生产，可以和出片并行；
但 **S11 之前必须齐**（`release_check.py` 会独立拦，不在这里假装通过）。

## 三、开工前置条件（9 项，全部拍板后才开工）

> 真源：`<ws>/project-setup.json`；门禁：`project_setup.py require`（未齐 → **退出码 4**）。
> 交互清单：`drama.py setup ask`（可直接照它问用户）；查可用账号：`drama.py setup accounts`。

| # | 项 | 取值 | 说明 |
|---|---|---|---|
| 1 | **画风** | `3d_manhua` / `2d_animation` / `live_action`（+ 子模式） | 写 `style-plan.json`；**不可事后更换**，换了已出素材全部作废 |
| 2 | **集数** | 默认 30 | 影响预算与工期预告 |
| 3 | **每集时长** | 60 / 70 / 90 秒 | 决定 `E006` 校验档位，混用会把老项目判死 |
| 4 | **生图模型** | `local_comfyui` / `runninghub` / `closed_source` | 写 `model-plan.json`；执行依据必须齐 |
| 5 | **视频模型 + 功能选项** | 通道 + `steps` / `megapixels` / `voice` / `concurrency` | 见 §3.1 |
| 6 | **工作流 API** | `workflowId`（或 AI 应用地址 / 云端 ComfyUI 地址 + 工作流文件）+ **站点** | 见 §3.3；**必须问到具体哪一条工作流** |
| 7 | **账号 API Key** | 账号别名（+ 自动登记 Key 指纹与来源） | 见 §3.3；**必须问到具体哪个账号** |
| 8 | **画面分辨率** | 交付 `1080x1920`（平台下限）+ 源像素 | 源 0.8MP 只够 39% 的 1080P，**必须超分** |
| 9 | **流水线模式** | `on` / `off`；`on` 必须给**预算上限** | 见 §四 |

> 第 6、7 项按通道**条件化**：全本地/闭源时自动标「无需」，不拦；只要有一条 RunningHub 通道，
> 两项都变成硬性必填。

### 3.1 视频功能选项的实测默认值（可直接沿用）

| 选项 | 默认 | 依据 |
|---|---|---|
| `steps` | **4** | 工作流带 4 步 turbo LoRA；20 步全量在短剧上性价比极低 |
| `megapixels` | **0.8** | 9:16 下 ≈ `672×1216`；实测 **31–34 RH币/段**（旧口径 145 偏高 4–5 倍） |
| `voice` | **h3** | H3 自带音轨；但**语音位置由模型自决**（实测偏差 −6.3s），字幕必须走 ASR 校时 |
| `concurrency` | **2** | 标称 ≤5 但按 5 提交必被 `421 api queue limit reached` 拒；改 2 后 8/8 零失败 |

`voice` 三选一（写进 `h3_prompts.json` 的每条提示词）：
`h3` 模型发声 / `external` 另配 TTS / `mute` 全后配。**这是显式约定，不能靠猜**。

### 3.2 一次性写单

```powershell
python stages/production/scripts/drama.py --workspace "<ws>" setup set `
    --style live_action --episodes 30 --ep-seconds 60 `
    --image-model local_comfyui --video-model runninghub `
    --workflow-api runninghub_workflow --workflow-id <id> `
    --site https://www.runninghub.ai --account "主账号 A" `
    --resolution 1080x1920 --pipeline on --budget-coins 9000
```

### 3.3 为什么「工作流 API」和「账号 Key」必须问到具体值

**① 工作流 API：选错不会报错，只会整体跑偏**

平台上一个 workflowname 可以存在多份（不同分辨率 / 不同步数 / 加了不同 LoRA）。
拿错 `workflowId` = 换了一个模型：8 段跑完才发现风格不一致，钱已经花了。
所以第 6 项要落到**可核对的三元组**：`类型 + 具体 ID/地址 + 站点`。

| 通道 | 必填 | 备注 |
|---|---|---|
| RunningHub 工作流 | `workflowId` + `site` | API 导出的 `*_api.json` **不是** workflowId，需先在工作流页保存/运行一次 |
| RunningHub AI 应用 | `appUrl` + `site` | — |
| 云端 ComfyUI | `comfyUrl` + 工作流 API 文件 | 二者缺一即拦 |
| 本地 ComfyUI | 无（可选工作流文件） | 默认 `127.0.0.1:8188` + 仓库内置 Qwen-Image 2.1 → **不拦** |
| 闭源模型 | 无 | 人工出图后落盘 |

**② 账号 API Key：决定花谁的额度、带谁的水印**

实测事故：确认时装的是 A 账号，跑的时候环境变量被改成 B 账号 —— 钱算在 A、
产物带 B 的水印，事后极难追溯。两个机制防它：

1. **只登记指纹，不登记 Key**：`<ws>/project-setup.json` 里存
   `别名 + sha256 前 8 位…后 4 位 + 来源（环境变量名）`，**Key 本体永不落盘、不进日志**。
2. **真跑前比对**：`require()` 每次都读当前环境的 Key 算指纹，与确认值不一致 →
   **退出码 4**，报「会花错账号的钱」；`pipeline run` 在每个计费环节**之前**再比对一次
   （流水线跑几小时，中途换 Key 也能拦住）。

多账号（`<ws>/keys.json` 里列了多把）时，用 `--account <别名> --account-source <环境变量名>`
指定用哪一个；`drama.py setup accounts` 会列出所有可用账号的指纹与站点，**不显示 Key**。

> ⚠️ 站点必须成对：`RUNNINGHUB_BASE_URL` 不显式设成 `https://www.runninghub.ai` 时，
> 上传会报「API Key 不存在」。所以 `--site` 只接受 `.ai` / `.cn` 两个值，写错直接退出码 2。

## 四、流水线模式（一次确认，跑完整部剧）

> 真源：`stages/production/scripts/pipeline.py`。

**用户视角的三步**

1. 确认 9 项前置条件（§三）；
2. `drama.py pipeline plan` —— **先告诉用户预计完工时间与预计花费**（不花钱、不改产物）；
3. 用户点头后 `drama.py pipeline run --yes` —— 一路跑到 `09-发行/剧集/EpisodeNN.mp4` + 发行资料，
   **中途不再逐步确认**。

**预告口径（实测）**：30 集 × 60 秒 ≈ **机时 7.6 小时 + 内容制作约 2.5 小时**
（出片 11 分/集 + 后期 4 分/集 + 资产 6 分），花费 ≈ **7,650 RH币 ≈ ￥19**。

**为什么会有「停点」**

调研结论、剧本正文、资产设计、H3 提示词、封面文案都是**内容生产**。仓库里没有、也不该有
「凭空生成内容」的脚本（提示词写死 = 把整部剧做成模板）。所以流水线把它们标成 `agent`：

- `auto` 环节 → 直接调既有脚本，无人值守；
- `agent` 环节 → 停下来打印**作业单**（要做什么 / 硬约束 / 产物判据 / 命令），
  由 Agent 在同一轮里补齐，然后 `pipeline.py mark S3` 继续。
- 对用户来说仍是"一趟水"：**不需要用户再确认**，Agent 自己推进。

**退出码**

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 本次推进完成（或全剧已交付） | — |
| **3** | **预算熔断**（已花 + 预估 > 上限） | 提高上限或缩小范围，不会跑一半才发现钱不够 |
| **4** | 停在需要 Agent 产出内容的环节 | 按作业单补齐后 `mark` |
| 其它 | 子脚本真实失败 | 看日志，修好后 `run --from <环节>` 续跑 |

**预算核对口径**：`<video-pipeline>/ledger/runs/*.json` 的 `attempts[].usage.consumeCoins`，
**只累加 SUCCESS**（失败任务平台不计费）。它只用于熔断闸门；正式成本报表用 `drama.py cost`。
每个计费环节**之前**核对，不是跑完再算。

## 六、常见误解（都踩过）

1. **「S7 可选」不等于「可以不做」** —— 缺发行资料 `release_check` 直接退出码 2，不可发行。
2. **「S9 放大」不是可选项** —— 0.8MP 源达不到平台 1080P 下限；`style_gate` 会在交付前拦。
3. **「S10 字幕时间」不能用剧本时间窗** —— H3 语音位置自决，必须 ASR 校时（文本用剧本、时间用 ASR）。
4. **「手工 done 一个自动环节」无效** —— `pipeline` 执行后仍复核判据，产物不在就会停。
5. **跳过的环节记得告诉下游** —— `skip` 只解除顺序门禁，不改变产物判据。

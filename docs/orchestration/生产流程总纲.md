## 零、开工三步（★ 2026-10-21 新增，顺序不可调）

> 完整口径见 **`docs/orchestration/标准作业流程.md`**（11 环节真源）。这里只列"开工前必须先做的三件事"。

| 步 | 做什么 | 命令 | 不过的后果 |
|---|---|---|---|
| **① 前置条件 9 项** | 画风 / 集数 / 每集时长 / 生图模型 / 视频模型+功能选项 / **工作流 API** / **账号 API Key** / 分辨率 / 是否流水线 | `drama.py setup ask` → `setup set ...` → `setup require` | **退出码 4**，不许开工 |
| **② 确认怎么做** | 逐环节做，还是流水线一次跑完 | `drama.py workflow status` / `pipeline plan` | `pipeline plan` 会先给**预计完工时间与花费** |
| **③ 按 11 环节推进** | 调研→剧本→资产设计→资产生成→视频提示词→视频生成→发行资料→拼接→放大→字幕→定稿 | `drama.py workflow check --stage S6` / `pipeline run --yes` | 前置环节未完成 → **退出码 4**；预算超限 → **3** |

**三条硬约束**

1. **顺序不可调**：跳过必须 `drama.py workflow skip <ID> --reason "..."` 留痕（用户明确要求才允许）。
2. **前置条件只拍一次板**：九项写进 `<ws>/project-setup.json`，之后不再逐步问；
   **画风仍以 `style-plan.json` 为真源**，通道仍以 `model-plan.json` 为真源（本单只做汇总与门禁）。
   ⚠️ **工作流 API 与账号 Key 必须问到具体值**：选错 workflowId 只会整体跑偏不报错；
   换账号会花错额度、带错水印 —— 所以确认单里登记的是**可核对的指纹**（不是 Key 本体），
   `require()` 与 `pipeline run` 在每个计费环节前都比对，不一致即停。
3. **流水线模式 = 一次确认跑到底**：确认后不再逐步征求同意，但**每个计费环节之前**核对预算上限，
   超限立即停（退出码 3），不会"跑到一半才发现钱不够"。

## 二、工作区分阶段目录规范（`layout.json` v1）

```
<剧项目>/
├── model-plan.json       通道确认单（生图/视频 + 执行依据）
├── project.json          创作层状态
├── layout.json           ← 目录布局声明（本规范的可执行形式）
├── 01-调研/              市场数据 · 多市场对比 · 爆款拆解
├── 02-选题/              候选池 · 七维评分 · 定位卡 · brief
├── 03-剧本/              集数规划 · ep_XX.md · 圣经(bible) · 台词时长审计
├── 04-资产/              资产卡（人/场/道）· refs.json · **characters/ scenes/ props/（出图产物）** · refs/（参考图原图）
├── 05-分镜/              分镜脚本（11 字段）
├── 06-提示词/            H3 六段式 md + **data/ 四文件**（出片引擎唯一输入契约）+ refs_h3/
├── 07-成片/              <批次>/ · subs/<ep>/ · logs/ —— **工作产物**（发布版另见 09-发行/剧集/）
├── 08-合规/              合规预检记录 · 整改说明 · 申诉材料
├── 09-发行/              剧集/（EpisodeNN.mp4）· 封面/ · 文案/ · 版权资料/ · 发布清单.md
└── video-pipeline/       引擎技术目录（config.*.json / ledger / runs）
```

**三条纪律**

1. **不重叠**：同一份产物只在一个阶段目录里写。阶段之间靠**引用**衔接（例如 `06-提示词/refs.json` 指向 `04-资产/` 的图片，不复制）。
2. **技术目录不参与创作**：`video-pipeline/` 只放引擎配置、台账、日志；**不要**往里面放剧本或提示词。
3. **向后兼容**：没有 `layout.json` 的旧工作区仍按
   `video-pipeline/data` + `video-pipeline/output` 解析，**行为完全不变**。
   解析链（`stages/_layout.py`，唯一真源）：
   `<engine_root>/config.local.json` 的 `data_dir`/`out_dir` → `<ws>/layout.json` → 旧默认。

> 新建项目：`python stages/creation/scripts/creation.py scaffold --workspace <ws> --slug <s> --title <t>`
> 会自动建全部阶段目录、写 `layout.json`、并把 `data_dir`/`out_dir` 回填进 `config.local.json`。
> 查询当前布局：`python stages/_layout.py --workspace <ws>`。

## 三、硬规则台账（不可调优，改配置只为显式声明）

### 3.0 画风三轨规格（★ 最先锁，不可事后更换）

来源：MiniMax 官方半解说短剧技能族。**完整规格见 `docs/styles/画风三轨规范.md`**，此处只列会被机器校验的硬值。

| 项 | 3D 漫剧 | 2D 动画 | 真人写实 |
|---|---|---|---|
| `visual_style_lock` | `3D-manhua-cel` | `2D-cel-webtoon` | 无（摄影真实感） |
| 单镜时长 | 6–10s（动作 4–6s） | 4–10s | 5–15 整数秒 |
| 旁白字数上限（普通/情绪/大段） | 28 / 32 / 36 | 32 / 36 / 40 | 60 / 70 / 80 |
| 旁白/对白最小间隔 | 0.30s | 0.20s | 0.20s |
| 尾缓冲 | 0.30s | 0.20s | 0.20s |
| 角色资产 | 主卡 **+ 三视图** | 主卡 | 主卡（16:9 纯白，左脸特写 + 右三视图半身） |
| 场景资产 | 主卡 **+ 辅卡** | 主卡 | 主卡（16:9 纯白，**无人物**） |
| 道具卡上限 | 1 | 1 | 0 |
| 重置锚周期（主角/配角/场景） | 4 / 6 / 5 | 3 / 5 / 4 | 不设 |
| 首帧锚点 | **强制 + 角度必须匹配** | 可选 | 单格干净图 |
| 分镜拓扑 | 逐镜 | 逐镜 | **1 片段 = 1 张三格时间分镜** |
| 交付终点 | 无旁白成片 + 独立旁白包 | **旁白交接（不出成片）** | 成片 + 旁白 + 可选字幕 |

**半解说结构四件套（三轨共用，可机器校验）**
① 旁白承担背景/时间跳转/内心；② 对白承担冲突/揭示/反转；③ **旁白与对白零重叠**；④ 结尾留悬念或收束。

```powershell
python stages/production/scripts/drama.py style status                  # 画风门禁
python stages/production/scripts/drama.py halfcheck all                 # 三类硬校验（读 05-分镜/storyboard.json）
```

### 3.1 平台硬限

| 规则 | 值 | 出处 / 后果 |
|---|---|---|
| RunningHub 单账号并发 | **≤ 5** | 平台硬限；超限提交被拒（退避重试，仍失败降并发到 1） |
| H3 图片槽 | **≤ 6** | 改不了；超了末尾图被丢弃并**错位** |
| 单段参考图 | **≤ 6** | 同上 |
| 参考图上传有效期 | 约 24 小时（缓存 20h） | 过期需重传 |
| 视频单次生成时长 | 4–15 秒 | H3 口径 |
| 字幕安全区 | 距底 **≥200px**、文本宽 **≤70%** | 竖屏字号须由「行宽 ÷ 每行字数」反向压住 |
| 语速区间 | zh `[2.0, 8.5]`，硬上限 12 | 超生理上限（zh 20 / es 40）中止 |

### 3.2 创作口径

| 规则 | 值 |
|---|---|
| **默认集数** | **30 集**（2026-10-20 由 40 下调） |
| 单集时长 | **60 秒**（lint 口径 60–80 秒）；单镜 4–15 秒；每集 **5–10 镜**。老项目 70 秒档（70–95 秒 / 5–12 镜）仍按各自 `ep_seconds` 校验 |
| **台词折算语速** | **4.2 字/秒**（含正常停顿） |
| 单元容量 | 30s→上限 100 字 / 目标 60–90；15s→55/25–50；10s→35/18–32 |
| 超载判定 | `>上限` 超载；`< 45 字`（30s 单元）偏轻 |
| 爆点节拍 | 中型每 **4** 集、大型每 **10** 集（与 60 集口径的 6/15 **密度一致**） |
| 选题候选数 | 8–12 个；同批主赛道重合度 ≤40% |
| 七维评分 | 权重 `20/12/15/13/12/13/15`；总分 `Σ(维度分×权重)×10`；S≥85 / A 75–84.9 / B 65–74.9 / C 55–64.9 / D<55 |
| 一票否决 | `合规 ≤3` → 强制 D；`独特性 ≤3` → 总分封顶 **74.9** |
| 七维真源 | `stages/creation/references/scoring-model.md`（**唯一真源**，Skill 侧仅基线快照） |

### 3.3 留存率导向的剧本结构（★ 2026-10-16 新增）

> 背景：用户实测几部剧「内容吸引度不够」→ 把留存要求升级为**可机器校验的硬结构**。

**每集四件套（缺一即返工，`script_rewrite.lint` 会拦）**

| 字段 | 含义 | 硬要求 |
|---|---|---|
| `cold_open` | 开场钩子 | 前 **3–5 秒**内必须出现「异常 / 冲突 / 悬念」之一 |
| `core_conflict` | 核心冲突 | 明确「谁 vs 谁 vs 什么」 |
| `reversal` | 一次反转 | 必须**改变力量对比或信息格局**（仅情绪起伏不算） |
| `hook` | 集尾钩子 | 类型**不得与前两集连续重复** |

**留存三段**

| 段 | 集数 | 要求 |
|---|---|---|
| 拉新攻坚 | EP1–3 | 三连强钩子链（身份悬念→危机逼近→秘密揭露）；**禁止铺垫集、禁止慢热** |
| 留存活口 | EP4–10 | 每集至少一次「小爽」落点；中段不得连续两集无爆点 |
| 转化与收束 | EP11+ | 按爆点节拍推进；**收尾前 2 集必须再拉一次强钩子** |

**EP1 = 黄金 3 秒**：把全剧最高冲突前置到开场，禁止背景铺垫开场。

**▶ 改编四段法（★ 2026-10-20）**：④ 不是「一次写完 30 集」，而是四段带门禁的流水线，真源
`docs/creation/剧本改编四段法.md`。

| 段 | 产物 | 门禁（退出码） |
|---|---|---|
| ① 诊断 A/B/C（选题诊断 / 改编策略 / 故事主线） | `03-剧本/diagnosis.json` | `diagnose --check` 2；未 `--confirm` 则 `build --emit` **4** |
| ② 骨架 D 分集大纲 | `03-剧本/blueprint.json` | `review --write-fixes` **2** |
| ③ 正文 FFS | `script/ep_XX.md` | `lint --ep N` + `cli.py check` |
| ④ 观众视角七问 | `03-剧本/audience-review.md` | `audience --check` **2** |

两条判据：**plan 的句库默认值只作占位**（`review` 会报「句库残留」并把表面 OK 降级为待人工复核）；
**题材不同、底线不同**（`references/genre-profiles.json` 的 `must_check` 把 WARN 升为 FAIL）。

**▶ 往下游交什么（同一份内容贯穿到分镜与 H3 提示词，★ 2026-10-20）**

| 锚 | 剧本侧 | 分镜 / H3 侧 | 校验口径 |
|---|---|---|---|
| 镜头号 | `[SC-nn]`（**是镜头，不是场次**） | `shot_id` / `epNN_scMM_prompt.txt` 的 `MM` | 镜数对齐（丢镜 FAIL，拆镜 ≤2×） |
| 台词 | `DIALOG` / `VO` 引号内文本 | H3 的 `Staging` / `<d>` / 对白列 | **逐字**（前 24 字指纹，容忍标点） |
| 人物 | `CHAR` 代号，**必须在 HEADER `# CHAR:` 登记** | `Picture N = … (Character)` | 代号可映射（重音归一） |
| 时长 | `DUR` | `duration` / `N-second` | 合计偏差 ≤10% |
| 剧情节点 | blueprint `plot_points`（`EPnn-P1..P4`） | 首镜落 `cold_open`、末镜落 `hook` | 实义实体共享 ≥1 |

门禁：`script_continuity.py --workspace <ws> --all`（**退出码 2 = 割裂**）。
跨语种（blueprint 中文、剧本外语）无法逐字比对时**降级为告警**，不假装通过。

### 3.4 合规红线（发布前必过）

| 规则 | 值 |
|---|---|
| 发布前三问 | ①方法是否出现 ②主体是否出现（含背景/倒影/屏幕）③身份是否歧义（校服/童装风）—— **全「否」才可发布** |
| AIGC 标注 | AI 用于真实还原人物或场景时**必须明确标注**（未标注 = 降流） |
| 受限集数占比 | **≤ 10%**；`余量 = ceil(0.1 × 总集数) − 已受限` |
| 通用安全拍法 | 死亡情节一律「**镜头外发生 → 事后发现 → 以调查与对白推进**」 |
| 整改三硬标准 | 主体不出现 / 方法不出现 / 身份不歧义 |

> 可机器执行部分：`python stages/production/scripts/compliance_precheck.py --workspace <ws> --ep ep01 --q1 no --q2 no --q3 no`

### 3.6 发行资料（★ 2026-10-18 新增）

> 触发语：用户说「**准备发行资料**」即按本节执行。**完整口径见 `docs/distribution/发行资料清单.md`（单一真源）**，
> 此处只列会被机器校验与人工否决的硬值。

**发行资料 = 剧集 + 封面 + 文案 + 发布清单 + 版权资料，五类缺一不可**

| 类 | 硬要求 |
|---|---|
| **剧集** | 发布版成片严格 `EpisodeNN.mp4` 落 `09-发行/剧集/`（详见 §3.7 与 `docs/distribution/发行资料清单.md` §二） |
| **封面** | 多尺寸成组：`cover_9x16` + `cover_3x4` **必备**（`16x9` / `1x1` 建议）；比例与档位误差 ≤2%；**必须具备「抓马度与视觉冲击」**：单主体大特写（主体占幅 ≥45%）、强明暗对比、**可指认的冲突物**、大字标题（中文 ≤6 字 / 西语 ≤3 词）、悬念留白、情绪色高饱和撞色 —— 六抓手命中 **≥5/6** 才可发行，`cover_spec.json` 须填 `reviewer` |
| **封面禁区** | 四宫格/九宫格拼贴、纯文字无人物、低对比灰调、把剧情**结果**画在封面、主标题压住脸部或落入右下角/下方 20% 安全区；四视图设定板**必须先切分**再送引擎 |

### 3.7 落点与命名硬规则（★ 2026-10-19 新增，两条都不许自行发挥）

> 背景：用户实测反馈两条重复出现的问题 —— ①发布版文件名「乱七八糟」；
> ②人物/场景资产跑到「成片」目录下，找不到。两条都固化为**机器可判**的规则。

**（1）资产一律落 `04-资产/`，不进 `07-成片/`**

| 项 | 规定 |
|---|---|
| 人物 / 场景 / 道具出图产物 | `04-资产/characters/`、`04-资产/scenes/`、`04-资产/props/` |
| 参考图原图 | `04-资产/refs/`（瘦身后进 `06-提示词/refs_h3/`） |
| 资产字典 / 清单 | `04-资产/refs.json`；`06-提示词/data/{characters,scenes,char_assets_manifest,scene_assets_manifest}.json` |
| **禁止** | 任何资产图出现在 `07-成片/` 下（`07-成片` 只放批次、母版、`subs/`、日志） |
| 落点真源 | `stages/_layout.py` 的 `assets_dir()`（读 `layout.json` 的 `assets_rel` / `config.local.json` 的 `assets_dir`） |
| 老项目迁移 | `python stages/production/scripts/migrate_assets.py --workspace "<ws>"`（默认干跑，`--apply` 才动，先备份） |

```powershell
python stages/production/scripts/migrate_assets.py --workspace "<ws>"            # 干跑：打印搬迁清单
python stages/production/scripts/migrate_assets.py --workspace "<ws>" --apply    # 真搬（自动备份 + 改写清单路径）
```

**（2）发布版成片严格 `EpisodeNN.mp4`**

> 用户原话：「发布版剧集的命名，严格以 `Episode+**` 的格式，如 Episode01、Episode02、Episode03。
> 不要每次输出之后，发布版文件名字都是乱七八糟的。」

| 项 | 规定 |
|---|---|
| 文件名 | **`Episode` + 至少两位编号 + `.mp4`**：`Episode01.mp4` … `Episode40.mp4`（≥100 集自动加位 `Episode100.mp4`） |
| 落点 | **`09-发行/剧集/`**，并随包生成 `剧集清单.json` |
| **禁止** | `EP01_1080p_ES.mp4`、`ep01_拼接_11段_672x1216.mp4`、`第一集.mp4`、`最终版.mp4` 之类即兴命名 |
| 中间产物 | `07-成片/` 下的 `<ep>_master.mp4` / `<ep>_subbed.mp4` 等**不是**发布文件名，只是工作产物 |
| 导出命令 | `release_export.py`（默认干跑；自动探测来源目录，同集取「最接近可发布」的那份） |

```powershell
python stages/production/scripts/release_export.py --workspace "<ws>" --all              # 干跑
python stages/production/scripts/release_export.py --workspace "<ws>" --all --apply      # 导出到 09-发行/剧集/EpisodeNN.mp4
python stages/production/scripts/release_export.py --workspace "<ws>" --from "<已编码发布版目录>" --all --apply
python stages/production/scripts/release_check.py  --workspace "<ws>"                    # 命名与集号连续性门禁
```

> 目标目录里一旦出现不符合命名的文件，`release_check.py` 与 `release_export.py` **都直接报错（退出码 2）**，
> 不静默通过 —— 这样「乱七八糟的名字」不会再流到发布包。

### 3.8 角色差异化（★ 2026-10-20 新增：同一部剧里，谁都不该长得像谁）

> 完整规范见 **`docs/assets/角色差异化设计规范.md`**（五根因 · 六维签名 · 六条硬规则 · 提示词三件套）。

人物图撞脸的根因不在模型，在提示词：**统一风格锚 + 关键维度缺失 + 全员同一批形容词**。
实测两部在跑项目：一部 **10 人里只有 2 人写了脸型、7 人是「浓眉」、3 人没有任何识别锚**；
另一部 **5 人里 0 人写脸型**，全靠服装区分 —— 换掉衣服就是同一个人。

| 项 | 规定 |
|---|---|
| 时机 | **画风锁定之后、任何一张人物图生成之前**（出图后改骨相 = 已产出素材全部作废） |
| 设计入口 | `character_design.py plan --roster <roster.json> --out 04-资产/design` |
| 门禁 | `character_design.py check --bible 04-资产/design/character-bible.json`（**退出码 2** = 不过） |
| 设计文件落点 | `04-资产/design/`（`character-bible.json` / `角色差异化矩阵.md` / `prompts/char/`） |
| 提示词去向 | `资产提示词_角色段.md` 并入「一、角色资产库」，直接喂 `gen_char_assets.py` / `asset_md.py` |
| 出图产物落点 | 仍为 **`04-资产/{characters,scenes,props}`**（见 §3.7），不因设计文件而改变 |

**六条硬规则（不予放宽）**：R1 任意两角色面部七槽 ≥4 槽不同｜R2 主角 vs 其他 ≥5 槽不同｜
R3 跨阵营色相间隔 ≥30°、中性色对明度差 ≥0.10｜R4 识别锚全局唯一｜R5 主演/配演发型不重复｜
R6 文案不得含「俊美/精致/白皙无瑕」这类评价性美颜词。

**提示词三件套（缺一不可）**：① 识别锚前置（一处、非对称、跨镜可见）；
② 反默认（写清「不要哪种脸」，且随骨相与族裔走）；③ 差异对照（把最像的那位写进同一段 prompt）。

老项目无需重跑全部：先 `character_design.py audit --md 资产提示词.md` 体检，
按「维度覆盖率」补脸型/眉形/识别锚，再重出撞得最凶的那几张。

| 交接 | 契约 | 校验命令 |

**三条不可违反的接线规则**

1. `<Picture N>` 对**全部 Subject 顺序编号**，`character_refs[i]` 顺序喂第 i 个槽 —— **缺一号后面全错位**；不能把场景图追加到末尾蒙过去。

3. `data/` 四文件是**只读契约**；缺关键字段**报错让人补，不猜不编**。

## 六、失败处置（口径固定，不得临时发明）

| 失败类型 | 处置 |
|---|---|
| 出片「工作流运行失败」 | 先按 transient：`video run --yes --resume <批次> --only <段>`，**别改提示词/配置** |

| 清理文件 | **绝不用通配符**（曾误删 7 个交付成片）；批量删除分批 ≤10 |

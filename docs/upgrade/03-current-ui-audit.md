# 03 · 当前 UI 审计

> 对象：`web/ui/studio/`（现行 Studio）。`web/ui/`（旧控制台 `/ui/`）单列在 §7。
> 判据：**读代码 + 实际结构**；页面观感结论需在 Phase 1 后用浏览器实拍复核，本文只写可证事实。

## 1. 应用外壳（`studio/index.html`，105 行）

| 区块 | 实现 | 备注 |
|---|---|---|
| `<aside class="nav">` | 252px（折叠 64px） | 品牌位 + `#nav`（JS 渲染）+ 折叠按钮 + 旧版入口 |
| `<header class="topbar">` | 60px | 项目切换器 / 健康点 / 资源监视 / 只读徽标 / 引擎徽标 / 刷新 |
| `<main id="view">` | 路由容器 | 视图按需 `import()` 动态装载 |
| `#drawer` / `#modal` / `#toasts` / `#loadbar` | 全局浮层 | 全站共用一套，页面不各造弹窗 |

外壳设计是**对的**：一个容器 + 浮层 + toast，页面只产出 HTML 片段。2.0 应沿用，不要改成每页自带布局。

## 2. 导航（`main.js` `NAV`，15 项 / 2 组）

```
全局   ：工作台 · 任务中心 · 系统中心 · 系统设置
当前项目：助手(浮窗) · 项目详情 · 画布 · 创作 · 创作模板 · 资产 · 分镜 · 视频 · 剪辑 · 发行 · 用时
```

现状问题（2.0 要解，不是审美问题）：

1. **一级导航 15 项平铺**，其中 11 项挂在「当前项目」下，信息架构等于「全部功能列表」。
2. 「创作」与「创作模板」并列 → 用户分不清「写东西」和「装模板」。
3. 「分镜」「视频」「剪辑」三个一级项，实际是同一条制作链的三段，却没有视觉上的阶段感。
4. 「用时」是项目属性，占一级位；「成本」散在别处（`studio.cost`），二者本应同屏。
5. 2.0 要求收敛为五个工作空间，与现结构**没有一项可无损映射**，需重排。

## 4. 设计系统审计（Phase 1 的直接输入）

### 4.1 存在**两套互相冲突的配色**

| 来源 | 主色 | 证据 |
|---|---|---|
| `css/tokens.css` | 琥珀 `--accent: #e0a458` ＋ 蓝紫 `--create: #8b7ff5` | tokens.css:28 / :46 |
| `css/app.css` 按钮段 | 炭 `#30302e` ＋ 陶土 `#c96442` ＋ 象牙 `#faf9f5` | app.css:207-215 / 242-252 注释直接引「§2 Dark Surface」「§4 Brand Terracotta」「§6 Level 2 Ring」 |

按钮的注释引用的是一份**外部设计规范的分节号**（§2/§4/§6），说明按钮样式来自另一个项目/另一份规范，与 `tokens.css` 不是同一套语言。

后果：主按钮是陶土橙，强调徽标是琥珀金，创作链是蓝紫 —— **同屏三种暖色/彩色**，品牌识别必然糊。

**Phase 1 必须先合并成一套**，且合并方式只能是「tokens.css 为唯一来源，app.css 只引用变量」。

### 4.2 Token 命名漂移（会误导后续开发）

```css
--fs-11: 12px;   /* 名字 11，值 12 */
--fs-12: 13px;
--fs-13: 15px;
--fs-14: 16px;
--fs-16: 18px;
--fs-20: 24px;
--fs-26: 32px;
```

历史上做过一次「整体上调一档」（tokens.css:52 注释），改名成本高就没改。2.0 换语义化命名（`--fs-caption` / `--fs-body` / `--fs-title`…）并保留旧名做别名，避免 22 个视图同时崩。

### 4.3 间距不是 4px 基数

`--sp-1: 2px`、`--sp-3: 6px`。2.0 要求 4px 基数，需在保留旧变量的前提下新增 `--space-*` 阶梯。

### 4.4 双主题：**完全缺失**

```
$ grep -c "prefers-color-scheme|data-theme" web/ui/studio/css/*.css
（0 命中）
```

`app.css` 内有 **72 处硬编码色值**（含 5× `#c96442`、4× `#30302e`、3× `#faf9f5`，以及大量 `rgba(79,179,199,…)` / `rgba(86,181,127,…)` 派生透明度）。这些不改成变量，浅色主题必然出现「深底白字浮在浅底上」。

**量化结论**：浅色主题不是加一段 `[data-theme=light]` 就能完成，需要先把 72 处硬编码收敛进 Token（预计 1 个阶段的工作量，不算 UI 重设计）。

### 4.5 已有且必须保留的基础

| 项 | 状态 |
|---|---|
| 响应式断点 | 11 处（1500/1240/1024/900/860/720px） |
| 减少动效 | 4 处 `prefers-reduced-motion: reduce` |
| 键盘焦点 | 3 处 `:focus-visible`（偏少，需补） |
| ARIA | 导航 `aria-label`、浮层 `role=dialog` + `aria-modal`、toast `aria-live` |
| 图标 | 内联 SVG 精灵 + `data-ico`，无外部图标字体（好） |

## 5. 交互机制审计（值得保留的几个「踩过坑」的实现）

| 机制 | 位置 | 为什么不能动 |
|---|---|---|
| 静态资源版本查询串 | `index.html:21-22, 103` | 无构建时防止 Chrome 启发式缓存；改样式不生效的事故补丁 |
| 200ms 延迟进度条 | `main.js:92-97` | 快请求不闪；闪一下比没有更烦 |
| 渲染序号丢弃旧结果 | `main.js:227-255` | 快速切页时旧结果覆盖新页 |
| API 12s 短缓存 | `api.js` | 每个接口背后是一次 Python 子进程 |
| 空闲预取 4 项 | `main.js:113-125` | workflow/setup 各 0.5s 起 |
| 主按钮指针流光 | `main.js:130-140` | 只对 `.btn.primary`，高频小组件不做 |

## 6. 明确的功能空洞（不是样式问题）

| # | 空洞 | 影响 |
|---|---|---|
| H1 | 提示词只能看整段纯文本 | 六段式无法分块编辑，用户看不出「哪段是动作、哪段是镜头」 |
| H2 | 提示词无写回接口 | 改一个字也要回编辑器改文件，Studio 无法闭环 |
| H3 | 无「生成前预检」聚合视图 | 预检脚本存在，但页面没有一眼可见的通过/失败列表 |
| H4 | 无「当前阶段 + 下一步动作」单一推荐 | 用户要自己从 15 项里判断该干什么 |
| H5 | 发行/版权资料仅部分覆盖 | `copyright_kit.py` 三入口未在 UI 完整暴露 |

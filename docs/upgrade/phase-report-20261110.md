## 12. T2 收尾（同日追加）

**目标**：`app.css` 的硬编码色值全部收敛进 Token，让浅色主题不出现「深底浅字 / 浅底浅字」。

**做法**：先用脚本把 61 处命中逐条打到「选择器 + 属性」上，再按四类规则替换（每处断言命中次数，少一处就整体不写入）：

| 类别 | 规则 |
|---|---|
| 旧状态色 | `rgba(86,181,127,.3)` 等 → `color-mix(in oklab, var(--sd-ok) 30%, transparent)` |
| 白/黑遮罩 | `rgba(255,255,255,.05)`、`rgba(0,0,0,.15)` → `color-mix(… var(--sd-text) 5% …)`，**必须跟文字色走** |
| 固定底色 | `#1d222a` `#1a1a26` `#16202a` `#c2cbd8` `#f0d3a9`… → 语义 Token |
| 阴影 | `0 16px 44px rgba(0,0,0,.46)` → `--sd-shadow-3` |

**结果**：46 组替换 + 滚动条 3 处；生效中的硬编码 **72 → 1**（唯一保留的 `.video-box video { background:#000 }` 是视频黑边，属画面内容）。

**过程中实测发现并修掉的真问题**（不是猜的，是量出来的）：

| 组件 | 问题 | 浅色实测 | 修法 | 修后 |
|---|---|---|---|---|
| `.badge.ok` | 淡绿底 + 绿字 | 3.91 | 新增 `--sd-ok-ink` #22693F | 4.97 |
| `.badge.live` | 淡青底 + 青字 | 3.60 | `--sd-teal-ink` #2A6A64 | 4.86 |
| `.badge.warn` | 淡金底 + 金字 | 3.46 | `--sd-warn-ink` #7A5518 | 5.34 |
| `.gn-hint` | 底用了模态遮罩 `--sd-overlay`，浅色下变灰块 | 1.95 | 改 `--sd-elevated` 92% | 6.22 |
| `.mtile-ph` | 占位文字用 disabled 档 | 2.09 | 改 `--sd-text-3-strong` | 5.20 |

**验证工具**：新建 `web/ui/studio/design-probe.html`（保留，不是临时文件）。它把每个组件在两种主题下的**真实计算色**打出来，用 canvas 把 `oklab()` 转 sRGB、逐层 alpha 合成，再算对比度，底部给 `LOW(<4.5)` 清单。

两个必须知道的坑（已写进探针注释）：

1. 探针里必须 `transition: none`，否则切主题瞬间读到的是 120ms 插值中间态，会把 4.34 读成 8.21。
2. 半透明底不能直接拿 `backgroundColor` 算比值，必须逐层合成到不透明底。

**当前探针结论**：`LOW(<4.5)` 只剩 `light:c19 btn primary = 4.34` —— 即你拍板的「浅色强调色严格用 `#9B7145`」，属已知取舍，不再改动。

2. **`system`（模型/通道/环境）留在全局**。它回答「这台机器能不能干活」，与项目无关；放进项目工作空间会在「还没选项目」时整块变灰，用户就配不了模型。页签条右侧给了「模型·通道·环境」直达。

**兼容**：`VIEWS` 注册表与所有 hash 路由 unchanged，旧书签（`#/boards` `#/storyboard` …）照常打开。

### 13.3 顺带补的一个后端能力

海报需要封面，而 `/api/workspaces` 不带图。两条路：

- 前端逐个调 `/api/artifacts?dir=` —— 但**资产目录名来自 `layout.json`，用户可改名**，前端硬编 `04-资产` 会在自定义布局的项目上直接取不到；

## 14. Phase 3 第二步：项目驾驶舱（2026-11-10）

**目标**：用户打开一部剧，就能回答「现在到哪一步、下一步做什么、为什么卡住」。

### 14.1 先说一个发现：口径写错了

页面副标题原来写「7 环节 23 节点」，`web/core/adapters.py` 的 docstring 也这么写。
实测引擎是 **5 环节 13 节点**（`nodes.py` 的 `STAGE_DIRS` 5 条 + `NODES` 13 条）。已改。

这不是文案洁癖：口径错了会让人按错的规模估算工作量，也会让后来者以为有一份 23 节点的模型存在。

### 14.2 阶段矩阵怎么渲染

引擎里**只有环节有中文名**（导入/资产/分镜图/出片/剪辑），节点只有契约 id（`video.batch`）。
所以：

- 分组头 = 环节名 + `完成数/总数`，数据来自 `stages[]` 的 `name` / `why`；
- 组内 chip = 节点 `id` + 六态着色，数据来自 `nodes[]` 的 `id/stage/state/detail`；
- **不给节点自造中文名**。前端抄一份映射，引擎改名后 UI 会继续说旧名字 —— 这类漂移最贵。

为防这条被破坏，加了测试 `test_overview_does_not_hardcode_node_ids`。

### 14.3 「下一步」与一个真实的矛盾

「下一步」= 拓扑序第一个非 `passed/skipped` 的节点，原样显示引擎的 `detail`（含「上游未通过：X」），
`video.*` 额外标注「计费节点」。

实测项目 `D://剧本//海外剧//7` 时暴露了一个真问题：

| 来源 | 说法 |
|---|---|
| 节点判据 | `import.bind` = `absent`（缺 `_done/import.bind.ep01.json`），下游 8 个节点全部 `blocked` |
| 集列表 | 30 集已有母版，`Episode01.mp4`… |

两个口径打架。处理方式不是隐藏，而是**在页面上明说**：

> 判据与产物不一致：`07-成片` 里已有 30 集的母版，但节点 `import.bind` 的产物文件缺失。
> 引擎以判据文件为准，**不会**因为成片存在而跳过该节点。

### 15.2 B · T5 定源：结论是「不存在双份」

### 15.3 新增 `stages/import/prompt_edit.py`

| 模式 | 作用 |

## 16. 分镜页三栏 + 提示词改回整段（2026-11-10）

### 16.1 用户裁决：提示词不拆段

第 15 节做完逐段编辑器之后，用户的实际反馈是：

> 「提示词不要拆了，不方便复制粘贴做测试。」

这句话推翻的是我上一版的判断。当时我按「结构可见性优先」把六段做成六个输入框，
理由写在代码注释里：看得见哪段空了、能分别校验。但真实使用路径是**把整段贴到模型里试**，
拆开之后每次都要重新拼回六个段头再复制 —— 结构可见的收益小于这次拼装的成本。

处置：编辑区改成一个 `textarea` 装完整原文（含段头），保存走 `text` 整段写回。
结构信息改成**只读**一行 chip（段名 + 字符数，缺段标红），不承担编辑职责。
`.sd-prompt-sec` 等分段样式保留给 `design.html` 的结构对照，CSS 与样板页都注明了边界。

新增守卫 `test_prompt_editor_stays_single_block`：storyboard.js 里出现 `sd-prompt-sec`
或 `parts:` 就红。防的是「以后有人（包括我自己）觉得分段更整齐，又把它拆开」。

### 16.2 三栏结构

```

│ ● ep02_…  │ [续跑这一镜]     │ └─────────┘ │
│           │                  │ ⚠3 条 · 展开 │
└───────────┴──────────────────┴─────────────┘
```

| 决定 | 理由 |
|---|---|
| 三栏各自滚动 | 183 个镜头的列表与长提示词各自很长；共用一条滚动条时，看提示词会把列表滚走 |

| 视频加 `box-shadow: 0 0 0 1px` 边线 | 视频 buffer 是纯黑，画布底也接近黑，没边线会被误判成「视频没加载」 |

断点：`1440 → 250/386`、`1240 → 228/344`、`1040 起`单栏堆叠（列表 380、画布 560 限高）。

## 18. T20 版本对照 + 资产库的两条设计需求（2026-11-10）

### 18.1 T20：创作版本对照（已闭环）

`creation.write()` 每次覆盖前都会写 `.bak_<时间戳>.md`，但界面看不到 ——
用户听得到「改坏了能回滚」，实际只能去文件夹翻时间戳。

做法（**不新建版本库**，磁盘备份就是版本）：

| 层 | 变化 |
|---|---|
| `creation.versions()` | 列当前 + 该产物**自己的**全部备份（按 stem 隔离，导演手册 30 集互不串） |
| `creation.read_version()` | 读某版正文；三条拒绝规则（路径分隔符 / 非 `.md` / stem 不符） |
| `GET /api/create/versions` `/api/create/version` | 只读端点 |
| 创作页工具条「版本」 | 宽版弹窗：左右行级 diff + `+N/−N` + 两列滚动同步 + 一键恢复 |

diff 用「先裁公共前后缀、再 LCS」，改一两行时规模从「全文²」降到「改动²」；
超过 4M 单元退化成整体替换（宁可说清「差异过大」也不卡住浏览器）。
恢复走 `write()`，所以会再把当前内容备份一次 —— **这一步可撤回**。

### 18.2 修掉一个会静默毁数据的按钮绑定缺陷

用 CDP 真实点击验收时发现：保存 / 复制 / 版本 / 编辑预览切换**全都没有处理函数**。
原因：这些控件由 `renderDoc()` 用 innerHTML 生成，而它在 `loadDoc()` 里异步执行、
比 `mount()` 晚；在 mount 里 `querySelector('#edSave')` 拿到 null，静默失败。

抽成 `bindEditor()`，在 `renderDoc` 之后调用。这类缺陷的危害在于**页面看起来完全正常**，
而截图验收根本发现不了 —— 必须真点。

### 18.3 资产库需求一：人物资产图 = 三视图 + 表情四宫格

查清了三件事：

1. 存量项目**已经**有 `**三视图**` / `**表情四态**` 两段提示词，26/21 个题材 Skill 里也有规定；
2. 但旧规范与用户给的新规范有三处**结构性**偏差（实测出图 `P01_Elena_VIEW_00.png` 是 **1088×1920 竖图**）：
   9:16 竖构图 → 应 16:9 横；`stacked vertically` 纵向堆叠 → 应横向并排占左侧 60%；
   `three-quarter side view`（3/4 侧）→ 应**严格 90°**；表情另出一张 9:16 → 应并入右侧 40% 的 2×2；
3. 21 个 Skill 的资产卡段落已按新规范统一改写。

新增 `stages/import/view_sheet.py` 处理**存量** md：
只改「三视图 / 表情四态」两块，造型与表格一字不动；改写结果先过 **13 项结构自检**
（16:9 / 左 60% / 右 40% / front / 90° / back / 2×2 / 四个表情名 / 两条禁止项），
任一项缺失**整体不写**；默认干跑，`--apply` 才落盘并备份。

实测 `海外剧/7`：9 处改动（8 个 VIEW + 1 个 EXP）、自检 0 失败、干跑不写盘。

### 18.4 资产库需求二：同一角色的多套穿搭归并

**结论：数据结构早就是对的，缺的只是「按角色聚起来读」。**

磁盘证据：`P01_Elena_LOOK-A/B/C_00.png`、`P01_Elena_VIEW_00.png`、`P01_Elena_EXP_00.png`；
`refs.json` 里是 `P01@LOOK-A`；层别在 `pack_spec.VARIANT_KINDS`（turnaround/look/expression/state）。
也就是说「同一角色 + 多套穿搭」在引擎侧一直是分开存、按 code 区分的。

所以新增的是**读的视图**，不是新数据：

| 文件 | 作用 |
|---|---|
| `web/core/characters.py` | 把 `P01@*` 聚成一张档案卡；按层分组（三视图 → 造型 → 表情 → 状态） |
| `GET /api/studio/characters` | 只读端点（含 `/media` URL） |
| 资产页「角色档案」区 | 一人一卡：编号/名字/变体进度/一致性锚点 + 3:4 缩略图，图上直接标 `LOOK-B` |
| 点变体 | 看该变体全部图 + 提示词（可复制）；缺图时显式标「待出图」 |

三个设计决定：**不新增数据结构**（派生视图，不落盘不建索引）；
**不猜融合**（旧 `EXP` 与新 `VIEW` 都保留，不自动删）；**图上标 code**（那就是参考图 key）。

### 18.5 顺带修掉一个真正的出图 bug（T22）

验收 `refs.json` 时发现 `P01@VIEW / @EXP / @LOOK-A / @LOOK-B / @LOOK-C` **五个键全指向同一个文件**

## 19. 资产库按用户裁决重做（2026-11-10）

用户这次给了四条具体意见，逐条落地：

### 19.1 「要有一个主形象，然后再做各个变体」

之前没有主形象概念 —— 封面是「第一张有图的变体」，等于随手挑。现在 `characters.py`
显式选一个，顺序写死（不随机、不取最新）：

| 优先 | 层别 | 为什么 |
|---|---|---|
| 1 | `base` | 模板给的「主卡 / 基础造型」本来就是基准 |

| 3 | 第一个有图的 `look` | 老项目常常只有造型、没有主卡 |

都取不到 → `master_missing=true`，界面显示「尚无主形象」，把它变成下一步该做的事。
**不拿随便一张图冒充主形象** —— 那会让「主形象」这个词失去意义。

### 19.2 「一个角色一个框，框内可以滑动，下方文字选择变体」

```
┌ P01 / 5 图 ─── Elena Vargas ──── [主形象 VIEW] ── 5/5 变体 ┐
│  P01@VIEW  三视图                              看提示词  1 张 │
│  ┌──────────────────────────────────────────────────────┐  │
│  │              主形象大图（≤480 高，可滚动）             │  │
│  └──────────────────────────────────────────────────────┘  │

```

- 点文字 tab **只换图片区**，不重绘整页 —— 换一个变体就刷新整页，长列表会跳回顶部。
- 缺图的变体留着但置灰，因为它是「待出图」的待办，藏起来就没人记得。
- 图区**不按 code 猜横竖**：存量的 `VIEW` 是 9:16 竖图（1088×1920），
  按 code 判横图会拉到两千多像素高，结果只看得见人物头顶。
  交给浏览器 `max-height + width:auto`，横竖都对。
- 图区不铺色块背景：竖图在宽框里必然左右留白，铺成深色块就像两条「加载中」的黑边。

### 19.3 「参考图和散图不应存在」—— 判断成立，但处理方式是降级而不是删除

| `06-提示词/refs_h3` | `prepare_refs.py` 生成的**瘦身副本**（长边缩到 ≤2048、转 JPEG，只为绕开 H3 的 5760px/30MB 上限）；原图在 `04-资产/*` | 派生物，不该与素材并列 |

所以：主分类只留 **角色 / 场景 / 道具**；两者降级为「诊断」入口，**有内容才出现**，
不参与缺口与出图判定。为什么不直接删——删了那些散落根目录的图在界面上等于不存在，
用户会以为图丢了。归位之后诊断入口自然变空。

→ 分镜/视频按 `refs.json` 的 key（`P01@LOOK-B`）取图。`refs_h3` 是视频环节的上传副本，

## 20. 变体单张重出（2026-11-10）

**目标**：某一张图不满意时，只重出那一张，不重跑整批。

### 20.1 引擎早就有这个能力，UI 只是没暴露

`gen_assets_local.py` 的 `--only` 收的正是 `variant_key()` 的形状：

```
$ python phases/... --only "P01@LOOK-B"
资产数 : 1（人物 1）
  id                 类型   名字      画幅   层别    种子      提示词
  P01@LOOK-B         人物   Elena     9:16   look    20296871  Full-body 9:16 verti…
```

所以这一轮没有新造能力，做的是**把它接到界面上，并且接对**。

### 20.2 三个必须同时成立的开关

| 开关 | 不加会怎样 |
|---|---|
| `--only P01@LOOK-B` | 整批出图，连带别的角色全重跑 |
| `--force` | 引擎 `--skip-existing` 直接跳过已有产物 —— **不报错**，用户只看到「按钮没反应」 |
| `--backup` | 旧图被 `os.replace` 直接覆盖，重出更差时**永久丢失** |

`--backup` 是这一轮新加的（`T24`）。`comfy_client` 落盘是 `shutil.copyfile/os.replace`，从来没有旧版概念 —— 整批出图时没问题（一次跑完整套），但「重出」这个语义的前提就是「我要换一张更好的」，换坏了得能退回去。

### 20.3 备份为什么必须叫 `.bak` 而不是 `.png`

两处扫描都会把备份当成真产物：

* `_scan_outputs()`：`iterdir()` + `f.name.startswith(prefix + '_')`
* `pack_import._scan_asset_images()`：**rglob**，会递归进 `_bak/`，然后按 stem 解析成 `P01` + `LOOK-B`

第二处更危险 —— 备份图会和真产物**抢参考图**，出片时喂错图且不报错。用 `.bak` 后缀两处天然跳过。代价：找回时要手动去掉 `.bak`。对「防后悔」够用。

### 20.4 通道不由界面选

第一版我打算在弹窗里放「本地 / 云端」选择。查了 `_model_gate()` 后放弃：

```
if expected_engine != plan_engine:  → 退出码 4「确认了云端却用 local」
```

界面自定默认值必然与确认单打架，而用户看到的是「按钮没反应」。所以新增只读端点 `GET /api/studio/image-channel`，返回 `spec` / `paid` / `url` / `fake_cloud` / `backup`，真源就是 `model-plan.json`。`graph._cmd_for()` 早就是这么做的（注释里写着同样的坑），这是第三个调用者。

实测两个项目分道扬镳，说明这条判定不是形式主义：

| 项目 | model-plan | 结果 |
|---|---|---|
| `海外剧/7` | `cloud_comfyui` + 云容器地址 | `assets.cloud`，**paid=True**，弹窗写「确认计费并重出」 |
| `海外剧/10` | 无 image 节点 | `assets.local`，paid=False，弹窗写「开始重出」 |

RH 工作流通道直接拦住：它的 `--only` 是老 md 口径（`char_01`），不接受 `P01@LOOK-B`。与其让它「找不到资产」或更糟地误匹配，不如在界面上说清。

### 20.5 顺带修掉一个会阻断全部资产出图的边界

接完链路第一次干跑就被拦：

```
[FAIL] 制作包校验不过，不进入出图：
  | [E] SHOT019  ep01.json shots[0]（shot_001）缺 subject_definitions、summary…
  | [E] SHOT020  …没有 <Subject n>…
  … 549 条
```

`assets_from_pack()` 对 `rep.ok` 全量判断，而本机 30 集提示词**全是旧格式**（`{{Mixed n}}` + 「资产图锚定」）→ SHOT019/020 全红 → **任何项目都出不了资产图**，哪怕资产卡完全合规。

这个边界是错的：**资产卡天生早于分镜提示词定稿**。出资产图时 episodes 里要么还没写提示词，要么是上一版。两者之间没有依赖关系。

改为按错误码分级：资产级（`PACK`/`ASSET`/`STYLE`）照旧阻断，分镜级（`SHOT0xx`）降级为打印，并且**必须打出来**（不能静默绕过）：

```
[注意] 制作包里有 549 条分镜提示词问题（SHOT0xx），本次出资产图不受影响；
       它们会在导入/出片环节阻断
```

### 20.6 又发现一处「两套数据源」

做重出时意识到：角色档案的**提示词**读 `00-创作/02-资产库.md`，而**出图**只认 `pack/assets/characters.json`。

改了 md 没重建 pack 时，界面上看到的是新提示词，点重出会用包里的旧提示词（或直接 `rc=2`「找不到资产 id」）。

```
海外剧/10  P12 Rosa Quintero

  pack : BASE
```

页面上给一条警告，弹窗里对这种变体直接**禁用按钮**并写明「包里只有 BASE，先重建制作包」。登记为 `T25`（根治要在导入环节做，属门禁设计）。

### 20.7 又修了一条误导提示

## 零、一句话结论

**这不是出图模型的问题，也不是提示词措辞的问题，是三件事同时发生：**

1. **剧本层**：EP01 里「契约婚姻」出现 **0 次** —— 观众看到的是一部医疗剧的开场；
2. **提示词层**：8 个镜头的 H3 提示词里 **性别词 0 个**，全部用 `figure` 指代（38 次）—— 模型只能猜；
3. **参考图层**：角色卡是「1 张脸 × 4 个视角」，H3 把 4 个视角读成 **4 个人** —— 一帧里出现 3 个女主。

三者叠加，成片必然无法阅读。

## 一、剧本层（P25 · 最致命）

### 现象

EP01 成片 66.9 秒，8 个镜头。用户「不知道在讲什么」。

### 证据（可复现的量化）

```bash
cd <项目>/03-剧本
for w in contract 契约 sign 签 ninety 90 marriage 婚 deal 交易; do
  printf "%-12s %d 次\n" "$w" $(grep -io "$w" ep_01.md | wc -l)
done
```

实测输出：

| 关键词 | 出现次数 |
|---|---|
| contract | **0** |
| 契约 | **0** |
| sign | **0** |
| 签 | **0** |
| marriage | **0** |
| 婚 | **0** |
| 90 | **0** |
| deal / 交易 | **0** |
| ninety | 1（仅标题 `Ninety Days, Mr. Nobody`） |

### 根因（到集/镜头级）

**问题出在骨架层，不在正文层。** 查 `03-剧本/人工拆解.md` 与 `blueprint.md`：

| 集 | cold_open | 契约状态 |
|---|---|---|
| EP01 | 锅炉房里她把扳手递回去…… | **无** |
| EP02 | 她把自拟的 90 天契约摊在工具箱上 | 首次出现 |

也就是说：**契约被排到第 2 集（第 75 秒之后）才登场。**

而 EP01 的实际内容线是：

| 时间 | 镜头 | 内容 | 男主在场 |
|---|---|---|---|
| 0–9s | SC-01 | 锅炉房，递扳手 | ✓ |
| 9–19s | SC-02 | 他说病区要关，41 人 | ✓ |
| 19–27s | SC-03 | 她走廊看告示 | **✗** |
| 27–35s | SC-04 | 护士长抄号码 | **✗** |
| 35–43s | SC-05 | 楼梯追住他要号码 | ✓ |
| 43–51s | SC-06 | 他写下号码 | ✓ |
| 51–59s | SC-07 | 公寓排账单 | **✗** |
| 59–66s | SC-08 | 打那个号码，铃声在身后 | ✓（只出现剪影） |

四条硬伤：

1. **卖点缺席**：标题承诺「90 天契约」，正片 0 次。观众拿不到任何「这是契约婚姻剧」的信号。
2. **男主断线 16 秒**（SC-03/04，占全片 24%）。关系刚建立就被切断。
3. **四空间三跳时**（锅炉房夜 → 病区日 → 楼梯夜 → 公寓夜），60 秒承载不了。观众要花认知成本判断「这是什么时候、这两人怎么又碰上了」。
4. **开场不是冲突是日常**：递扳手 + 一句俏皮话既不是异常也不是悬念，违反 §3.3「EP1 黄金 3 秒、最高冲突前置」。

### 修法（待用户拍板，两选一）

**方案 A · 倒叙砸设定（推荐）**

| 时段 | 内容 | 目的 |
|---|---|---|
| 0–4s | 特写：一张纸上签字，纸面印着 **90 DAYS**。手抬起，对面坐着的男人是**刚才楼下修锅炉的那个** | 3 秒内砸出「契约」＋「认错人」双重悬念 |
| 4–14s | 闪回：两小时前锅炉房，她递扳手，灯灭 | 交代相识 |
| 14–34s | 病区要关，8.7 万债务，41 人 | 交代动机 |
| 34–52s | 她拦住他，用「我知道你不是修理工」当筹码，提出交易 | 关系成立 |
| 52–66s | 钩子：他签字，但第七条写着「九十天后你自己走」 | 契约的刀 |

这样 60 秒里：**契约出现 3 次以上、男主断线不超过 8 秒、两个空间**。

**方案 B · 保留现结构，只补视觉设定**

在 SC-01 开场加 2 秒字幕卡（`90 DAYS LATER` 或 `SIGNED: 90 DAYS`），并在 SC-07 让契约纸**进画面**。
成本低，但「契约婚姻」仍然是第 2 集才真正成立，留存率救不回来。

### 判据

```
grep -ci "contract\|契约\|ninety\|90 day" ep_01.md   → 必须 ≥ 3
男主不在场的连续镜头时长                           → 必须 ≤ 8s
EP01 使用的独立空间数                              → 必须 ≤ 2
```

## 二、提示词层（P26 · 直接导致「两个男人」）

### 现象

SC-02 剧本是「KANE 蹲下拧阀门 + ELLE 看手机」，成片是**两个中年男人**一起低头看阀门。

### 证据

```bash
python - <<'PY'
import json, re
d = json.load(open(r"<项目>/06-提示词/_eps/ep01/h3_prompts.json", encoding="utf-8"))
txt = "\n".join(v["prompt"].split("[STYLE]")[0] for v in d.values())
for w in ["woman","man","she","he","girl","lady","female","male","figure"]:
    print("%-8s %d" % (w, len(re.findall(r"\b%s\b" % w, txt, re.I))))
PY
```

实测：

| 词 | 次数 |
|---|---|
| woman | **0** |
| man | **0** |
| she | **0** |
| he | **0** |
| female / male | **0** |
| figure | **38** |

### 根因

人物指代是用**外貌相对描述**写死的，出处是项目侧脚本 `_tools/patch_storyboard_h3.py` 的 `LABEL` 字典：

```python
LABEL = {
    "char_elle": "the shorter figure in a worn cardigan",
    "char_kane": "the broad-shouldered figure in a canvas work jacket",
    "char_rosa": "the rounder figure with a clipboard",
    ...
}
```

当时的设计意图是「避免文字被画进画面，所以不用姓名」，但代价是：

- **没有性别**：`figure` 是中性词；`cardigan`（开衫）在英式语用里偏中年男性 → 模型把两人都画成男人
- **没有年龄**：无法与角色卡对齐
- **没有身份**：「护士」「集团持有人」这些决定走位与气质的词全丢
- **「shorter / rounder」是相对比较，不是绝对特征**：单独看一句话无法还原成一个人

### 修法（已验证）

把指代从「相对外貌」改为「姓名 + 性别 + 年龄 + 服装色签名」，并且**在 [SUBJECT] 里显式约束人数**：

```
[REFS] <Picture 1> ELLE — a woman in her early thirties, short brown bob,
        teal knit sweater with claret cuffs, teal trousers.
       <Picture 2> KANE — a man in his late thirties, short dark hair,
        tan canvas work jacket over a dark green shirt and brown work trousers.
       <Picture 3> the location only, an empty basement boiler room with nobody in it.

[SUBJECT] exactly two people in the frame — one woman and one man, nobody else.
          ELLE (Picture 1) stands holding a wrench out; KANE (Picture 2) crouches at
          the valve and takes the wrench without looking up at her.
```

要点四条：

1. **显式给性别与年龄段**（early thirties / late thirties），不用 `figure`；
2. **把服装色签名写进 [REFS]**，与角色卡同源，跨段才会一致；
3. **[SUBJECT] 第一句就锁人数**（`exactly two people — one woman and one man, nobody else`）；
4. **[ACTION] 里改用姓名**，不用「the standing figure」这种代词化描述。

### 判据

```bash
# 每段提示词必须含性别词，且 figure 出现次数 = 0（[STYLE] 段除外）
grep -c "woman\|man\b" <每段 prompt>   → ≥ 1
grep -c "\bfigure\b"                   → 0
```

## 三、参考图层（P27 · 直接导致「三个 ELLE」）

### 现象

放大后的 shot_001 第 2 秒：**画面里有三个 ELLE**（左 1、中 1）+ 一个 KANE。剧本这一镜只有两个人。

### 证据

角色卡 `04-资产/characters/char_elle_00.png`（1920×1088）的版式：

| 横向区间 | 内容 |
|---|---|
| 0–45% | 左脸大特写 |
| 45–70% | 正面全身 |
| 70–90% | 侧面全身 |
| 90–100% | 背面全身 |

**一张图里有同一个人 4 个视角。** H3 多参把「一张图里的 4 个人像」读成「4 个人物」，
于是按参考图复制出 2–3 个女主。

这解释了此前的两个现象：
- 本地 4 参考版出现 **2 个 ELLE**
- 云端放大后出现 **3 个 ELLE**（分辨率更高，模型更容易分辨出 4 个独立人像）

### 根因

《画风三轨规范》§1.3 规定真人轨角色卡是「16:9 纯白 + 左脸特写 + 右三视图」。
这个版式对**人工审阅**是合理的（一屏看全），但对**视频模型当参考图**是有害的 ——
它天然携带「多个人像」的信号。

### 修法（已验证）

从角色卡裁出**单人正面竖条**，作为视频参考图：

```bash
ffmpeg -i char_elle_00.png -vf "crop=420:1088:890:0" characters_single/elle_front.png
```

- `x=890, w=420`：只取正面全身那一竖条，**左右边缘不能带进相邻视角**（第一次用 `x=830,w=520`
  把侧面像切进了半个人，H3 仍然判成两个人）
- 输出 `04-资产/characters_single/<code>_front.png`
- `06-提示词/characters.json` 指向单人版

**已验证**：同一段提示词 + 单人参考图 → 8.5 秒内**全程恰好一男一女**，无复制。

### 判据

```bash
# 参考图里必须只有一个人像：用视觉模型核一次，或人工确认左右边缘无第三视角残片
# 成片抽 3 帧（1.0s / 4.5s / 8.5s），每帧人数必须等于剧本该镜人数
```

## 四、连带修复：RH 放大工作流（`2110614419863592961`）

原记录「跑了 11 分钟报 805，判定不可用」是**误判**。真实原因三条：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 输入是 `hevc / Main 10 / yuv420p10le`（RH 原始产物），服务端 LoadVideo 解不动 | 提交前转 `h264 / yuv420p / 8bit`（`libx264 -crf 17`） |
| 2 | 提交走 v1 通道 `/task/openapi/create`（legacy） | 改 `/openapi/v2/run/workflow/{id}`（`create_workflow_v2`） |
| 3 | 节点 4/5 是**短边/长边**不是宽/高 | 竖版给 `4=1080, 5=1920`；给反了输出 598×1080 |

修完实测：**9.4 秒片段 52–62 秒完成，10–12 币**，输出 1062×1920。

> 注意：输出宽 1062 而非 1080，是因为输入 672×1216 等比缩放到高 1920 得 1061.7。
> 要精确 1080×1920 需在 ffmpeg 里 `scale=1080:1920`（横向拉伸 1.7%，肉眼不可见）。

### 这条证据改变了结论

台词本身是一条完整的叙事线：**病区要关 → 41 人 → 并购审查 → 私人号码 → 要电话 → 8.7 万 → 别转身**。
只靠听，故事是懂的。

**所以「看不懂」= 画面与声音完全脱节。**

| 声音在讲 | 画面在给 |
|---|---|
| 病区要关，41 人 | 两个男人低头拧阀门 |
| 贴了告示，私人号码 | 一个护士走过走廊（墙上是乱码表格） |
| 8.7 万，她最后一年花的钱 | 她坐在桌边翻一叠纸（账单是乱码） |
| 别转身 | 门口一个黑影（这一镜反而是对的） |

### 根因：H3 只执行「动作」，不执行「事件」

提示词的 `[SUBJECT]` 和 `[ACTION]` 全部是**肢体动作**（holds out / takes / kneels / walks / copies / writes / lays out），
没有一条把**信息**翻译成画面里的**物件**：

- 「病区要关」→ 画面里应该有**封条、搬空的病床、打包的纸箱**
- 「41 个人」→ 应该有**一排空的名牌插槽**（有了，但出成乱码表格）
- 「8.7 万」→ 应该有**一叠账单的高度、红色催缴章**
- 「契约」→ 应该有一张**带签名的纸**

`[SUBJECT]` 写「她排账单」，模型就只画「她在排纸」——纸上的内容它不管，也画不出。

### 修法（分镜设计层，不是措辞层）

每条 `[SUBJECT]` 后面补一句 **`[PROP]`**：本镜必须出现的、承载信息的那一个物件。

```
[SUBJECT] exactly two people in the frame — one woman and one man, nobody else.
          ELLE (Picture 1) crouches in a hospital corridor holding up a phone,
          KANE (Picture 2) stands behind her.
[PROP] a sheet of paper taped to the wall beside them, edges curling, held down
       with two strips of yellow tape — the paper itself is turned away from the
       lens, only its back and the tape are visible.
```

要点：**信息物件可以用「背面/侧面/局部」表达，不必让模型写清上面的字**。
「一张被两条黄胶带压住、边角卷起的纸」比「一张写着 41 个名字的告示」可画得多，也稳得多。

### 判据

```
每个镜头：能指认出一个承载信息的物件（PROP）        → 必须存在
该物件不得依赖可读文字                             → 画面里无 ≥3 字的成串字符
```

## 八、重制过程中的三个新发现（P31–P33）

按方案 A 重写 EP01 并重出 8 段时，又踩到三处，均已修复。

### P31 引擎不支持「一镜多角色」

**现象**：新剧本第一版写 `CHAR: ELLE, KANE`，`tools/cli.py check` 一次性报 12 个错：
每个双人镜同时报 E002「角色 ELLE, KANE 出场但 HEADER 未声明锚点」与
E003「CHAR 引用未登记代号：ELLE, KANE」。

**根因**：`validate.py` 把 `s.char` **整串**拿去比对 `known_chars` 集合，
而集合里是单个代号。`"ELLE, KANE" not in {"ELLE", "KANE", ...}` → 必然报错。
HEADER 解析本身是正常的（逐行验证过）。

**影响**：一镜两个角色是短剧常态（对白交锋镜），照原实现根本写不出来。

**修法**：新增 `_split_codes()`，按 `, ， 、 ; ； /` 切分；`_check_codes` 与
`_check_char_anchor` 两处改为**逐个代号**比对，单代号行为不变。已同步五个工作区。

```python
def _split_codes(v: str) -> list:
    return [x.strip() for x in re.split(r"[,，、;；/]", v or "") if x.strip()]
```

### P32 宽景别会诱发边缘「补人」

**现象**：`shot_001`（`medium shot, 35mm`）右侧画框边缘多出半个人——
一条穿棕色裤子的腿和卡其夹克袖子，与主角 KANE 同款。其余 7 段是紧景别，**全部无此问题**。

**根因**：景别越宽，画面里越有「该有别人」的空位，模型在边缘补齐人群。
提示词里 `exactly two people` 这类**数量约束对宽景别效力不足**。

**修法**（双管）：
1. 景别收紧：`medium shot, 35mm` → `medium close shot, 50mm`，并在 `[SHOT]` 里写明站位关系
   （`ELLE standing at the near end in the foreground, KANE seated at the far end behind her shoulder`）；
2. `[SUBJECT]` 末尾追加**边缘约束**：`Nothing else enters the frame — no limb, no shoulder,
   no second body at either edge.`

**判据**：任何 `wide / full / medium shot` 都要配边缘约束；出片后必须看**画框四边**，
不能只看画面中心——这次的问题就在右下角，缩略图里几乎看不见。

### P34 整集 ASR 会让字幕逐段漂移（已修）

**现象**：烧完字幕抽帧检查——20 秒处画面是锅炉房，字幕却是上一镜（会议室）的台词，
整体错位一整句。

**根因**：整集合并后一次性转写，whisper 把**每段台词之后的静音**也算进这一句，
于是时间戳逐段累积漂移。实测第 1 条占了 0–13 秒，而 `shot_001` 只有 9.42 秒，
到第 3 段时已经错开一句话。

**修法**：`build_subs_ep.py` 改为 **逐段转写 + 段偏移**：

```python
clock = 0.0
for shard in shards:
    cue = whisper(extract_audio(shard))     # 段内时间
    for a, e, body in cue:
        cues.append((clock + a, clock + e, body))
    clock += duration_of(shard)             # 累加该段真实时长
```

**判据**（修正前后对比，均为实测）：

| 段 | 段边界 | 修正前字幕 | 修正后字幕 |
|---|---|---|---|
| SC-01 | 0–9.42 | 90 days…（0–13.0，越界） | 90 days…（0–6.28）+ You can laugh…（6.28–9.08） |
| SC-02 | 9.42–17.42 | Do you know…（13–22，越界） | Do you know…（9.42–17.26）✓ |
| SC-03 | 17.42–26.83 | The ward's closing（22–29，越界） | The ward's closing（17.42–26.62）✓ |

条数也从 8 条变 10 条（长台词被正确切成两句），更易读。

**附带修掉两处 ASR 错字**：`The awards closing` → `The ward's closing`；
钩子句外层多余引号。判据：烧完必须抽帧比对**字幕文本与画面场景**是否同属一镜。

### P35 `subtitles=` 塞 Windows 绝对路径必失败（已修）

**现象**：`ffmpeg ... -vf "scale=1080:1920,subtitles=D\:/剧本/…/ep01.ass"` 报
`Unable to parse "original_size" option value "/剧本/…" as image size`。

**根因**：`D\:` 的转义让 ffmpeg 把盘符之后的路径当成 `subtitles` 滤镜的选项值去解析。

**修法**：把 ASS 复制到临时工作目录，`subprocess.run(..., cwd=work)`，

### P36 字幕普遍比音轨提前（用户反馈，已修）

**现象**（用户验收原话）：「字幕普遍存在比实际音频提前的现象」。

**量化**：用 `ffmpeg silencedetect` 测每段真实语音起点，与 whisper 的 SRT 起点逐段比对：

| 段 | 真实语音起点 | whisper 标注 | 提前量 |
|---|---|---|---|
| SC-01 | 0.398 s | 0.000 | 0.40 |
| SC-02 | 0.313 s | 0.000 | 0.31 |
| SC-03 | 0.313 s | 0.000 | 0.31 |
| SC-04 | 0.730 s | 0.000 | 0.73 |
| SC-05 | 0.739 s | 0.000 | 0.74 |
| SC-06 | 0.421 s | 0.000 | 0.42 |
| SC-07 | 0.685 s | 0.000 | 0.69 |
| SC-08 | 1.357 s | 0.000 | 1.36 |

**根因**：`whisper.cpp` 输出的 SRT 起点习惯性标到 0（VAD 起点偏前），
而 H3 生成的语音在每段开头有 0.3–1.4 秒的呼吸/环境音。逐段转写保证了
**段间不漂移**（P34），但**段内仍整体提前**。

**修法**：逐段检测真实语音起点，把该段全部 cue 整体后移。

```python
def voice_start(path, noise="-32dB", min_sil=0.25) -> float:
    r = subprocess.run(["ffmpeg", "-i", str(path),
                        "-af", f"silencedetect=noise={noise}:d={min_sil}",
                        "-f", "null", "-"], capture_output=True, text=True)
    ends = re.findall(r"silence_end://s*([//d.]+)", (r.stderr or "") + (r.stdout or ""))
    return float(ends[0]) if ends else 0.0

shift = voice_start(shard) - cues_of_this_shot[0][0]
if 0.05 < shift < 2.0:           # 只在「标早了」且幅度合理时修正
    cues = [(a + shift, e + shift, b) for a, e, b in cues]
```

**坑中坑（必须记住）**：第一版正则写成 `r"silence_end://s*([//d.]+)"` —— 反斜杠被多转义成了正斜杠，
正则匹配不到任何东西，函数**静默返回 0**，日志里一行「校准」都不打，但流程照常跑完并出片。
这种「静默失效」比报错危险得多。判据必须是**看行为**而不是看有没有异常：
抽 0.2 s 与 0.7 s 两帧，0.2 s 应当**无字幕**、0.7 s 应当有字幕。

**验证**（实测）：

| 时间点 | 修正前 | 修正后 |
|---|---|---|
| 0.2 s | 已有字幕 | **无字幕** ✓ |
| 0.7 s | 有字幕 | 有字幕「90 days, that's the offer.」✓ |

**顺带**：新增 `<ep>.fix.json` 机制，每集可放 ASR 错字修正表
（如 `The awards closing` → `The ward's closing`），重跑不丢。


## 十、批量推进 EP02–EP08 时的三个新问题（P37–P39）

（校验 → 提示词 → data → 出片 → 放大 → 字幕 → 归档）。做这件事时又踩到三处。

### P37 主角与群演同色系会被淹没

**现象**：EP02 SC-01（病区公告栏，四五名护士围观）出片后，**找不到主角**——
ELLE 的青绿针织衫与护士刷手服的绿色几乎同色，人群里认不出来。

**根因**：色签名是按「跨阵营色相 ≥30°」设计的（角色之间不撞），但没约束
**角色与环境/群演**的关系。病区制服恰好是青绿系，与 ELLE 的主色同一色相。

**修法**：
1. 群戏镜的 `[SHOT]` 写明「其他人在焦外，不解析成面孔」（`stays as out-of-focus shapes`）；
2. 让主角占据前景或画面中心，群演退到后景；
3. 真正要拍群戏时，给主角一个**对比色小块**（她的紫红袖口或手中深色物件）落在画面里。

**判据**：群戏镜抽一帧，**三秒内能指出主角**；指不出就重排景别。

### P38 放大失败不阻断，静默产出残缺成片（最危险）

**现象**：EP03 成片时长 58.87 秒，而剧本是 66 秒。查下来 `shot_008`（钩子镜）
放大返回 `805 工作流运行失败`，`upscale_rh.py` 把这个失败**写进了 summary 但没有让进程失败**，
`pipeline_ep.py` 又没校验，于是拿 7 段拼了一集，照常烧字幕、照常归档。

**为什么比直接失败更危险**：成片能播、能看、看起来「完成了」，但**钩子没了**。
如果不是顺手核了一下时长，这一集就这么交付出去了。

**修法**：`pipeline_ep.py` 在两处加硬校验：
```python
missing = [s for s in range(1, 9)
           if (raw / f"shot_{s:03d}.mp4").is_file()
           and not (up / f"shot_{s:03d}_1080p.mp4").is_file()]
if missing:            # 自动重试一次，仍缺则中止，绝不进字幕
    raise SystemExit(...)
...
if copied < 8:
    raise SystemExit("待烧录片段只有 %d/8" % copied)
```
补跑 `shot_008` 后重新烧录：58.87 s → **68.29 s**，8 段齐全。

**判据**：成片时长必须接近剧本合计（容差 ±10%）；不等就查 `upscale_summary.json` 里
`ok=false` 的条目。

### P39 中文剧本不能直接生成提示词，必须中英分离

**现象**：`gen_h3.py` 第一版直接把剧本的 `ACTION` 拼进 `[SUBJECT]/[ACTION]`，
生成出「`beat 1 早班的病区走廊; beat 2 公告栏上贴着一张复印的契约`」这种中文提示词。
另外 `[REFS]` 里也残留「`齐耳内扣短发`」「`松石青`」。

**根因**：H3 只认英文。中文片段的处理等同于噪声——模型会按自己的语义随意发挥，
这正是「画面不知道在讲什么」的一个来源。

**修法**：**剧本与提示词分层**。

| 层 | 位置 | 语言 | 给谁看 |
|---|---|---|---|
| 剧本 | `03-剧本/ep_XX.md` | 中文 | 编剧 / 人工审阅 |
| 英文层 | `03-剧本/en/epXX.en.json` | 英文 | H3 |
| 提示词 | `06-提示词/h3_prompts.json` | 英文 | 机器（由前两者生成） |

`gen_h3.py` 缺英文层**直接报错退出**，不生成半中半英的提示词。
另外加了 `HAIR_EN` / `COLOR_EN` 两张映射表，把 `character-bible.json` 里的中文
发型名与色名翻成英文（`齐耳内扣短发` → `a chin-length bob turned under`，
`松石青` → `teal`）。

**判据**：`grep -P "[\x{4e00}-\x{9fff}]" h3_prompts.json` 必须为空。

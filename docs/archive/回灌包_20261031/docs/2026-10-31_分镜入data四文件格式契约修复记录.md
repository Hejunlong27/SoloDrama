## 一、K1 参考图路径的基准（最容易错）

`convert_storyboard.py` 把四文件写到 `06-提示词/`（**不是** `06-提示词/data/`），
而 `ingest_check.py` 用 `data_dir / r` 判存在 —— 那个 `data_dir` 就是 `06-提示词/`。

所以 `04-资产/refs.json` 里要写：

```json
{"characters": {"char_elle": "../04-资产/characters/char_elle_00.png"}}
```

**两个连带的坑**：

1. 我第一版按「相对 `04-资产`」写 `characters/char_elle_00.png` → 变成 `06-提示词/characters/...`，不存在。
2. 第二版用脚本做「相对化」，但输入本身已经是相对路径，`root / rel` 拼出了
   `D:/剧本/04-资产/...`，`relpath` 又算出同样的字符串 —— **相对路径被二次相对化**。
   正确做法：**从绝对路径（manifest 里的 png 实际位置）算一次 relpath**，不要拿已有的相对值再算。

## 二、K2 prompt 必须是多行字段

`convert_storyboard` 的字段解析是「一行一个 key」，非 key 行算续行。
实测：把 `[SHOT] … [DIALOGUE] <d>…</d>` 全塞在 `- prompt:` 那一行时，
`<d>` 与 `<Picture n>` 虽然在同一字符串里，但 `ingest_check` 的正则走的是**重建后的 prompt**，
一旦被截断就丢。稳妥写法：

```markdown
- prompt: |
    [Shot 1] At 00:00.000
    [REFS] <Picture 1> the shorter figure. <Picture 2> the location.
    [SHOT] medium shot, 50mm …
    [DIALOGUE] <d>[ELLE] You're not the super.</d>
```

## 三、K3 时间戳是段内相对

我按整集累计写了 `[Shot 1] At 00:00.000`、`[Shot 3] At 00:19.000`……
校验器读的是**每段自己的 duration**，于是「19 秒 > 8 秒」直接判死。
正确：**每段都从 00:00.000 起**。段与段的绝对时间由 `shots.json` 顺序与 duration 推，不需要写进 prompt。

## 四、K4 台词标签的方括号

`D_TAG = re.compile(r"<d>\[[^\]]*\]\s*([^<]*)</d>")` —— `<d>` 后面**必须紧跟 `[说话人]`**。
写成 `<d>You're not the super.</d>` 会被判「没有台词」，即使肉眼看得见。
正确：`<d>[ELLE] You're not the super.</d>`。

## 五、K5 `<Picture n>` 与槽位顺序

`character_refs` 在前、`scene_refs` 在后，**`<Picture 1>` 必须对应第一个 character_ref**。
写反了不会报错，但出片时人物会与场景错位 —— 这类错很难在成片前发现，只能靠约定。
本批做法：在 prompt 开头加一行 `[REFS] <Picture 1> … <Picture 2> …`，把编号与人/景写死。

## 七、附带的一条：分镜脚本自己别把段落粘在一起

用脚本重写 md 时，`"## ".join(blocks)` 若 block 末尾没有换行，
会得到 `…text## shot_002` —— 于是 `re.split(r"(?m)^## ")` 只切出 1 段，
`convert_storyboard` 只解析到 1 段，**而且 8 段的 prompt 全挤在一条里**，
表现就是「分镜数 1 / 时间戳非严格递增 [0.0, 0.0, 0.0]」。

修法：拼回时用 `"\n".join`，或在每块末尾补 `\n`；改完先 `grep -c "^## shot_"` 确认是 8。

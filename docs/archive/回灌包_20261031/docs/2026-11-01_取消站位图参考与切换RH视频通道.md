## 三、关键开关：`--video-only`

这条流水线默认是「① 九宫格出图 → ② 裁 3×3 → ③ H3 用 cell_01 当首帧」。
我们已经有角色卡与场景卡，不需要重新出分镜图。开关：

```bash
python run.py --video-only --limit 1 --data "<项目>/06-提示词"
```

日志对应用意：

```
① --video-only：跳过分镜图生成（不扣图费）
② --video-only：跳过裁剪（无分镜图可裁）
③ 已载入 H3 提示词（1782 字, duration=9.0）
④ 参考图匹配完成（角色 2 张 / 场景 1 张）
⑤ H3 视频完成 -> final.mp4
```

**走多参（reference generation），不用首帧、不用九宫格。**

## 五、踩到的四个坑

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **站点不匹配** | `code=1 API Key不存在` | 用户给的是**中文站** key（文件首行标「zh站」），必须 `runninghub_base_url = https://www.runninghub.cn`；国际站 `.ai` 的 key 用不到 .cn，反之亦然 |
| 2 | **probe 猜错节点** | banana 工作流的 prompt 被猜成 `36 CLIPTextEncode.text`（那是**负向词**），char_ref 被猜成 `49 megapixels` | 手动改：正向提示词是 `57 PrimitiveStringMultiline.value`；该工作流**没有 LoadImage**，是纯文生图，不该配 char_ref/scene_ref |
| 3 | **`data_dir` 是命令行参数** | 用 `configure.py set data_dir` 改了没用，仍读 `<workspace>/data` | 必须 `run.py --data <路径>`；`data_dir` 虽然在白名单里，但不是这个用途 |
| 4 | **refs 相对路径基准** | `--data` 指到 `_eps/ep01/` 就报「参考图不存在」，路径成了 `_eps/04-资产/...` | `refs.json` 里的相对路径是相对 `06-提示词/` 写的；`--data` 必须指 `06-提示词/`，并把该集数据放回这个目录 |

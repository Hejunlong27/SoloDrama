## 一、现象与逐层排查

| # | 现象 | 实际原因 |
|---|---|---|
| E1 | 启动即 `ModuleNotFoundError: No module named 'comfy_aimdo.storage'` | 装的是 `comfy-aimdo 0.4.15`，ComfyUI 0.42.1 的 `requirements.txt` 钉 **0.5.6**；`storage` 模块是 0.5.x 才有的 |
| E2 | 修完 E1 报 `No module named 'comfy_kitchen.int8_decode'` | `comfy-kitchen 0.2.31`，实际需要 **0.2.39** |
| E3 | 再修报 `No module named 'torchsde'` | `torchsde` 在 requirements 里，但**根本没装** |
| E4 | `torch.cuda.is_available() == False`（有 RTX 4060） | 该 standalone-env 装的是 **`torch 2.14.0+cpu`**（CPU 轮子） |
| E5 | 启动时 `comfyui-frontend-package 1.49.6`，服务端要求 1.55.18 | 前端包同样落后（只影响界面，不影响 API 出图） |

> 关键判断：**先比对 `requirements.txt` 的钉版与实际安装**，而不是一个一个报错去补。
> 这台机器 5 条钉版里有 4 条不一致 —— 说明整个环境是「装到一半」的，单点修补会一直踩下一个。

```bash
# 一条命令查出全部不一致（比逐个 ModuleNotFoundError 试错快得多）
python - <<'PY'
import re, subprocess, sys, pathlib
req = pathlib.Path("<ComfyUI>/requirements.txt").read_text(encoding="utf-8")
pins = {m.group(1).lower().replace("_","-"): m.group(2)
        for m in (re.match(r"^\s*([\w.\-]+)\s*==\s*([\w.\-]+)", l) for l in req.splitlines()) if m}
have = dict(l.split("==",1) for l in subprocess.run([sys.executable,"-m","pip","list","--format=freeze"],
        capture_output=True, text=True).stdout.splitlines() if "==" in l)
for k,v in pins.items():
    if have.get(k.strip().lower()) != v: print(k, "需要", v, "实际", have.get(k))
PY
```

## 二、修法（按顺序，四条）

### 1) 补齐 requirements（含 4 个钉版）

```bash
<env>\python.exe -m pip install -r <ComfyUI>\requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

> 已满足的包不会重装，**CUDA 版 torch 不会被降级**（下一节验证）。

### 2) 换 CUDA 版 torch（与已装版本号严格对齐）

```bash
# 先确认 pytorch 官方源上有对应 cp313/win 的 CUDA 轮子
curl -s https://download.pytorch.org/whl/cu132/torch/ | grep -oE "torch-2\.14\.0%2Bcu132-cp313[^\"]+whl"
```

```bash
<env>\python.exe -m pip install --no-deps --force-reinstall \
  torch-2.14.0+cu132-cp313-cp313-win_amd64.whl \
  torchvision-0.29.0+cu132-cp313-cp313-win_amd64.whl
```

**为什么要 `--force-reinstall` 且版本号一致**：`2.14.0+cpu` 与 `2.14.0+cu132` 在 pip 眼里是同一个版本号
的不同 local tag，不显式指定 `+cu132` 会被判「已满足」而跳过。

### 3) 网络：pip 直连 PyPI 会「假死」，用镜像 + 断点续传

实测：`download.pytorch.org` 单文件 2 GB 在 2.2 MB/s 且**中途断流**；`files.pythonhosted.org`
对某个 62 MB 包连续 10 分钟只下了 13 MB。

| 场景 | 做法 |
|---|---|
| PyPI 包（含 comfy 自家包） | `-i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com` —— 实测**秒装** |
| pytorch CUDA 轮子（镜像通常只有 CPU 版） | `curl -L -C - --retry 20 --retry-all-errors -o <whl> <url>` 先下到本地，再 `pip install <本地whl>`；`-C -` 支持断点续传 |

> 教训：**不要让 pip 去下载大轮子**。它中断后从零重来；`curl -C -` 能续传，断十次也只补差额。

### 4) 验证（三层，缺一层都不算修好）


## 四、★ 新发现：turbo 模式下负向提示词**完全失效**

`comfy_client.py` 自己会打这条警告，但值得单列：

```
[WARN] 本工作流 cfg=1 < 2（turbo 加速）：负向条件不参与引导，
       提示词里的 no / not / without / 禁止 / 不要 一律无效。
```

含义：我们在角色卡里写的那一长串
`no second person, no text, no watermark, no CG render look, no plastic skin…`
**一个字都没起作用**。首张样张能出对，靠的是正向描述（"纯白无缝背景上只有这一个人"），
不是靠那些否定词。

**两条处置**（择一，按题材定）：

1. **保持 cfg=1（快）**：把关键否定改写成**正向具体特征**。
   例：`no plastic skin` → `可见毛孔与细汗毛，颧骨处有浅淡晒斑`；
   `no second person` → `画面中只有一个人`；`no text` → `纯净背景，无任何排版元素`（仍偏否定，最好直接写"背景是连续的白"）。
2. **把 cfg 提到 2.0–3.0**：负向开始生效，但 turbo LoRA 的收益下降、耗时上升。

> 判断线：**资产卡**（要干净、要可复现）优先走方案 1；**分镜图**（要构图约束）可考虑方案 2。

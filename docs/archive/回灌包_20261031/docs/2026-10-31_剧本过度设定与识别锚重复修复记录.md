## 一、主问题：剧本创作被「设定卡」绑死（P1–P3）

### 现象

每一集剧本的 HEADER 都必须写 `# CHAR: ELLE: <一段具体长相>`，而且必须与资产库**逐字一致**。
实测结果：为了过校验，编剧只能把 `character-bible.json` 里的「左手虎口一处烫伤旧痕（皮肤发亮、无毛）」
原样抄进剧本。于是——

- 同一部剧 8 个角色，剧本里出现 8 段长相描写，**却没有一句推动剧情**；
- 换一部剧，因为下面的 P4/P5，抽到的还是同一批锚点，看起来「又是那道疤」；
- 更隐蔽的代价：**剧作家的第一决策变成了「他长什么样」，而不是「他想要什么」**。

### 根因（三处串联，缺一不成）

| 层 | 位置 | 行为 |
|---|---|---|
| ① 数据入口 | `tools/core/convert.py::world_bible_to_char_anchors` | `visual_anchor` 缺失 → `raise ValueError("缺 visual_anchor，无法冻结锚点")` —— **不写长相就不许开工** |
| ② 模板 | `stages/creation/scripts/script_rewrite.py::render_skeleton` | 写死 `<CHAR 代号>: <锚点>`，连占位符都在索要长相 |
| ③ 门禁 | `tools/core/validate.py::_check_char_anchor`（E002） | `sha1(header_anchor) != row.anchor_hash` → ERROR，**没有「留空」这条合法路径** |

三者构成闭环：入口逼着写 → 模板提醒写 → 门禁逼着抄准。**这是设计问题，不是模型问题。**

### 修法

| # | 文件 | 改动 |
|---|---|---|
| P1 | `tools/core/convert.py` | `visual_anchor` 改为**可选**；缺失时 `anchor_text=""`，不再抛错。docstring 写明「剧本阶段只登记代号与身份，长相留给 S3」 |
| P2 | `stages/creation/scripts/script_rewrite.py` | 骨架占位符 `<锚点>` → `<身份/关系>`；注释说明锚点是资产概念 |
| P3 | `tools/core/validate.py` | E002 增加三条短路：HEADER 锚为空 / 为 `-`·`无`·`待定`·`N/A` / 库内锚为空 → **跳过比对**。只有两边都写了才逐字校验 |

### 判据（以后照这个验）

- 剧本 HEADER 允许 `# CHAR: ELLE: 急诊护士，背着母亲的医疗债`，**不写任何外貌**，`check` 必须 PASS。
- 想写锚点的项目仍然可以写，写错照样报 E002 —— 能力保留，义务取消。
- 新骨架里**不应再出现**「锚点」二字（`grep -n "锚点" render_skeleton 的输出` 为空）。

### 验证

```bash
# 1) 去锚后的剧本仍全绿
cd <工作区> && python tools/cli.py import-bible
for e in 1 2 3; do python tools/cli.py parse --ep $e; python tools/cli.py check --ep $e; done
# 期望：ERROR 0 / PASS

# 2) 新骨架不再索要锚点
python -c "import sys;sys.path.insert(0,'stages/creation/scripts');import script_rewrite as S,pathlib;print(S.render_skeleton(pathlib.Path('<ws>'),S.C.read_json(S.C.pdir(pathlib.Path('<ws>'),S.C.BLUEPRINT)),4,8)[:400])"
# 期望： # CHAR: ELLE: <身份/关系>; ...
```

## 二、次问题：识别锚「跨剧重复」（P4–P5）

### 现象

不同项目、不同人物，抽到的识别锚高度重合：**4 组模拟名册里有 3 组，第二个角色都是「虎口烫痕」**。

### 根因

| # | 位置 | 行为 |
|---|---|---|
| P4 | `character_design.py::design` | `seed = str(roster.get("seed") or "solodrama")` —— 缺省值是**常量字符串**。没写 seed 的项目共用同一串哈希，等于所有人抽同一副牌 |
| P5 | `character_design.py` 的 `ANCHOR`（24 条） | 其中 **4 条是疤**（A02 眉尾旧疤 / A03 虎口烫痕 / A07 颈侧细疤 / A20 唇侧竖疤）＝16.7%；且 A02/A03 排最前；选取用 `_h(...) % len(free)`，**小余数反复命中靠前条目**，疤的概率被进一步放大 |

> 附带的认知污染：`docs/assets/角色差异化设计规范.md` 与 `docs/character-design-framework.md` 的示例
> 全部用「右眉尾一道浅白旧疤」「下唇左侧一道 8mm 竖疤」。文档是 LLM 写名册时的主要参考，
> 示例即模板，于是人写的名册也开始自带伤疤。

### 修法

| # | 改动 |
|---|---|
| P4 | `seed` 缺省改为**按名册内容派生**：`sha1(world + 全部角色名)[:12]`，前缀 `auto-`。显式给 seed 仍优先。→ 两个项目天然不同，无需用户操心 |
| P5 | ① 新增 `ANCHOR_KIND`（24 条逐条归类：痣/疤/饰/眼镜/发/斑/痕/纹/轮廓）与 `KIND_QUOTA`：**疤 1、痕 1、斑 1、痣 2、饰 2、纹 1**；<br>② 选取算法由 `hash % len(pool)` 改为 `sorted(pool, key=hash(seed+id))[0]` —— 全体等概率、可复现、不再偏爱靠前条目 |

### 判据

- 同一部剧里「疤/痕/斑」类识别锚合计 **≤1 人**（配额可通过 `KIND_QUOTA` 调整）。
- 两份不同的名册（不写 seed）必须得到不同的 `seed` 值，且锚点分布不同。
- 同一份名册 + 同一 seed 仍必须**逐字节可复现**（这是原有设计目标，不能牺牲）。

### 验证（实测输出）

```
剧A seed=auto-31b4281deb8c 疤类1 | 颈侧细疤 / 宽银拇指环 / 锁骨胎记 / 额角发旋 / 鼻梁压痕
剧B seed=auto-275d345dcb51 疤类1 | 唇侧竖疤 / 宽银拇指环 / 鼻梁压痕 / 腰间钥匙串 / 食指关节粗大
剧C seed=auto-405bbcb0703f 疤类0 | 细圆框眼镜 / 耳后纹身 / 食指关节粗大 / 单只旧金耳夹 / 泪痣
剧D seed=auto-2025eca4c354 疤类1 | 褪色徽章 / 鼻梁压痕 / 锁骨胎记 / 方形旧表 / 虎口烫痕
```

修改前同样四组名册：**3 组的第二个角色都是「虎口烫痕」**。

## 三、资产设计侧的配套修复（P6）与未修项（P7–P10）

### P6 全员强制有锚 → 改为可选（已修）

`R4 识别锚全局唯一` 原本隐含「每个人都必须有锚」。现在：

- `roster.characters[].overrides.anchor` 支持 `"none"` / `"无"` / `"不设"` / `"-"`；
- 未设锚的角色 `anchor.id=""`，**不参与 R4 判定**；
- 三份提示词里的「【唯一识别锚】」段落**整段省略**，不再生成一句空的「识别锚：。」

> 设计意图：**主卡必须有锚，配角可以没有**。8 个人 8 道标记，观众一个也记不住；
> 3 个人有标记、其余靠发型与色签名区分，反而更清楚。真正要「全员有锚」的项目，
> 在 roster 里逐个指定即可，规则不再替你做决定。

### P7 脚手架生成空别名目录（未修，建议）

`creation.py scaffold` 会建出 `04-资产/char`、`04-资产/scene` 两个**永远为空**的目录，
与 §3.7 规定的 `characters/`、`scenes/` 并列。这正是「资产找不到 → 重复出图」的复发土壤。

建议：删掉这两处 `mkdir`（或改为 `.gitkeep` 说明文件）。当前处置：每次 scaffold 后手工 `rmdir`（空目录安全）。

### P8 `# CHAR:` 多行只认第一条（未修，建议）

`validate.py` 用 `re.search(r"(?m)^#\s*CHAR\s*:\s*(.+)$", text)`，**只取第一行**。
写成多行的项目会报「KANE、ROSA 未在 HEADER 登记」，但人看着明明是登记了。

建议：改 `re.findall` 后合并，或在报错文案里直接写「多个角色请用 `;` 写在同一行」。
当前处置：约定单行 `;` 分隔（已写入项目 README）。

### P9 `plan --from-outline` 相对路径按仓库解析（未修，建议）

传 `03-剧本/人工拆解.md` 会去**引擎仓库**找，报「拆解表不存在」。
建议：相对路径先按 workspace 解析，找不到再按 CWD。

### P10 设计器不产真人轨模板（已修）

`character_design.py` 的 `maincard_prompt` / `headshot_prompt` / `board_prompt` 原本全是
**竖版 3D 漫剧模板**（「竖版角色主卡」「电影级写实 3D CG 渲染」）。而《画风三轨规范》§1.3 要求
真人轨是「16:9 纯白 + 左脸特写 + 右三视图半身」。**照它出图会直接跑偏画风**，
此前每个真人项目都得在外面手写一套提示词 —— 那层手工就是这次要消灭的。

**修法**：`plan` 新增 `--card-style {auto,3d_manhua,2d_animation,live_action}` 与 `--scenes <world-bible.json>`。

- `auto`（缺省）读名册 `style_lock`：`live-*` 自动走真人轨，其余保持原三件套；
- `live_action`：一人一张 `prompts/live/<代号>_<名>_card.txt`（16:9 / 纯白 / 左脸特写 + 右三视图），
  不再产出 3D 的 board/maincard/headshot；`--scenes` 另出场景卡（16:9 纯白，绝对无人物）；
- 名册可给 `code`，文件名与剧本代号对齐；
- 风格串去重：名册 `style_anchor` 已含材质项时不重复拼接。

```bash
python stages/assets/scripts/character_design.py plan \
  --roster 04-资产/design/roster.json --out 04-资产/design \
  --scenes 03-剧本/world-bible.json          # card_style 由 roster.style_lock 自动判定
```

### P11 人群桶按身份整句匹配，导致年龄错配（已修）

**现象**：31 岁急诊护士被判定为「长者」，表情写成「眼睑松弛…情绪收在皱纹里」；
44 岁护士长因身份里有「病区」被判成「病态者」，写成「唇无血色」。

**根因**：`_bucket()` 把 `identity` 整句拼进匹配文本（`" ".join([identity] + persona)`），
于是「背着**母亲**留下的医疗债」命中 B7 的 `母`、「**病区**工会」命中 B10 的 `病` ——
**命中的是剧情词，不是性格**；且没有任何年龄闸门。

**修法**：
① 只匹配 `persona` 词，不匹配 `identity`；
② `BUCKET_AGE` 年龄闸门（B7 长者 ≥50、B3 天真者 14–32），不在区间不参与竞争；
③ 名册可显式给 `persona_bucket`；
④ 无任何命中时**不再固定回落 B2**（此前 8 人里 6 个「隐忍者」，表情一模一样），
   改为在年龄可用桶里按种子分散；
⑤ 名册可用 `overrides.expression` 写「这个人怎么用脸演戏」，优先于桶的默认表情。

## 六、回滚方式

三处改动都是**行为放宽**，不回滚也不会让旧项目失效：

- P1/P3：旧项目本来就有锚，两边都有值 → 仍走逐字比对，行为不变。
- P2：只影响新生成的骨架。
- P4/P5：**会让重跑 `plan` 的项目换一套锚点**——已出图的项目**不要重跑**，否则图与 bible 对不上。
  需要旧行为时，在 roster 里显式写 `"seed": "solodrama"` 并把 `KIND_QUOTA` 放宽即可。

## 七、这次真正该记住的一句

> 剧本阶段回答「他要什么」，资产阶段回答「他长什么样」。
> **两件事一旦耦合，编剧就开始为一张脸写戏。**

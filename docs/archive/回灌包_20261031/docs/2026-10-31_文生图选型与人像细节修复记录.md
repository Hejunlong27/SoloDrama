# 文生图选型与人像细节修复记录（2026-10-31）

> 触发：用户反馈「人物面部细节有点漂移，不够清晰」，随后要求「生图模型还是全部切回 Qwen image 2.1 turbo 文生图，但要解决人像飘逸的问题」。
> 适用范围：`stages/assets/comfyui/` 全部出图通道；`_tools/build_manifest.py` 清单生成。
> 结论先行：**「飘」不是模型不行，是四个参数同时错了**——cfg=1 让负向失效、1.5MP 人脸像素不够、seed 没固定、步数被误以为越多越好。

---

## 一、现象

| # | 现象 | 实际观感 |
|---|---|---|
| 1 | 角色卡面部「发虚、涂抹感」 | 针织衫织纹糊成一片，看不出毛线走向 |
| 2 | 同一角色重跑一次就换一张脸 | 以为是「模型随机性大」，其实是没人指定 seed |
| 3 | 提示词里写了一整段「不要画成 AI 美人脸：不削尖下颌、不放大眼裂、不做磨皮」 | **一个字都没生效** |
| 4 | 换 Moss-image 后细节变实，但 38 岁出成 50 岁、指定短寸偏分出成大背头 | 细节换来了「听话度」下降 |

## 二、根因（按影响排序）

### R1 · cfg=1 让负向条件完全不参与引导 ★最隐蔽

位置：工作流 `497 SamplerCustom.inputs.cfg = 1`

`SamplerCustom` 的 `cfg=1` 意味着**不做无分类器引导**，此时 `negative` 输入不参与任何计算。
工作流里 `471 TextEncodeQwenImage21.negative_prompt` 是空字符串 `""`，而 `497.negative = ["471", 1]`，
看起来「接了负向」，实际是**接了个空字符串并且不参与**。

真正的杀伤在于配套：

`stages/assets/scripts/character_design.py` 生成的提示词里有一段【反默认】：

```
【反默认】不要画成通用 AI 美人脸：不削尖下颌、不放大眼裂、不垫高鼻梁、
不做无毛孔磨皮、不做左右绝对对称的脸；五官不混入亚裔眼型与扁平鼻骨。
```

**这一段 100+ 字全是否定句，在 cfg=1 下 100% 无效。** 而它恰恰是「反 AI 塑料脸」的唯一约束。

> 同类问题在 2026-10-20 就记录过一次（`comfy_client.py::_warn_negation` 会在 cfg<2 且提示词含否定词时打警告），
> 但当时只做了**告警**，没改工作流 —— 告警打在日志里，没人看。

### R2 · 1.5MP 下的人脸像素密度不够

16:9 / 1.5MP = **1632×918**。角色卡版面是「左半脸特写 + 右三视图」，左脸特写约占画面宽度 40%
→ 脸部实际只有约 **300×350 px**。这个像素量下人脸只能「像」，不可能「实」。

实测 1.5 → 2.0MP：
- 针织衫织纹：**从糊成一片 → 可辨认单根毛线走向**
- 皮肤：从均匀的哑光面 → 能看到毛孔与细微色差
- 这是**唯一一个「加了就一定好、没有副作用」的变量**

### R3 · manifest 不带 seed → 每次重跑换脸

`_tools/build_manifest.py` 只写 `{id, kind, name, prompt, aspect}`，**没有 seed**。

`comfy_client.py::build()` 里：

```python
if seed is not None:
    ...
```

`seed` 来自 `item.get("seed")` → `None` → 不写 → 用工作流的默认值（每次提交前被 UI 覆盖为随机）。

**后果**：同一个角色重跑 3 次得到 3 张不同的脸，且无法通过「调提示词」做受控实验 ——
因为你改提示词的同时，seed 也变了，你分不清是提示词的功劳还是运气的功劳。

这是「漂移」最难查的一条：它不在任何一张图上，而在「每次都不一样」这件事本身。

### R4 · 步数不是越多越好：12/16 步会把 31 岁画成 40+

Qwen-Image 2.1 **turbo** 是蒸馏模型，8 步是设计点。实测加步数：
- 织物纹理更「实」
- **但皮肤年龄整体上浮**：12 步约 40 岁，16 步更甚，且出现过度写实（细纹加深、眼窝凹陷）

用户设定是 31 岁急诊护士，画成 40+ 就是错的。**步数不能凭「越清晰越好」的直觉加。**

### R5 · hires fix 不划算

二段采样（1.2MP 生成 → 1.5× 放大 → 低 denoise 重采样）：

| denoise | 耗时 | 结果 |
|---|---|---|
| 0.40 | 87 s | 锐度好，但相比 2MP 直出无质的提升 |
| 0.55 | 62 s | **开始改脸**：鼻梁压痕被重绘变形、右脸轮廓糊 |

denoise 0.4 是安全上限，但 87 s vs 25 s 换不到明显收益 → **不做默认**。

## 三、修法

### P1 · 固化高质量文生图工作流

新增 `stages/assets/comfyui/workflow_qwen21_t2i_hq.json`（14 节点），相对用户原版改三处：

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `13 ResolutionSelector` | `3:4` / `2.0 MP` / `multiple 8` | `16:9 (Widescreen)` / `2.0 MP` / `multiple 32` | 角色卡是横版三视图；multiple 32 对齐 VAE 下采样 |
| `497 SamplerCustom.cfg` | `1` | **`2`** | 让 negative 真正参与引导（R1） |
| `471 TextEncodeQwenImage21.negative_prompt` | `""` | 见下 | cfg=2 时负向才起作用，空串等于白开 |

负向词（通用反塑料脸，实测不损伤其他方面）：

```
plastic skin, waxy texture, airbrushed, over-smoothed, symmetric face,
cgi render, 3d render, illustration, painting, doll-like, blurry, low detail
```

**步数保持 8 步**（`496 ManualSigmas` 原序列不动），理由见 R4。

同时把 `comfy_client.py` 的默认映射改成新工作流的节点 id（否则开箱即用会崩）：

```python
DEFAULT_WORKFLOW = ".../workflow_qwen21_t2i_hq.json"
PROMPT_NODE = "488"   # PrimitiveStringMultiline
PREFIX_NODE = "487"   # SaveImage
SEED_NODE   = "497"   # SamplerCustom(noise_seed)
ASPECT_NODE = "13"    # ResolutionSelector
LATENT_NODE = "474"   # EmptyLatentImage
```

### P2 · 固定 seed（`build_manifest.py::stable_seed`）

```python
def stable_seed(project: str, asset_id: str) -> int:
    h = hashlib.sha1(("%s::%s" % (project, asset_id)).encode("utf-8")).hexdigest()
    return int(h[:8], 16) % (2 ** 31 - 1)
```

写进每个资产：`{"id": "char_elle", ..., "seed": 759121625}`。

设计意图：
- **同资产跨批次可复现** —— 改提示词时 seed 不动，能判断「是提示词的功劳还是运气」
- **不同剧/不同角色不撞脸** —— 哈希含项目名
- 不写死常量 seed（否则全公司所有角色同一张脸，等于把 R3 换成另一种死法）

### P3 · 客户端支持图生图（P13）与多输出（P14）

用户后续要求「图像编辑使用 Qwen image 2.1 turbo 图生图」。该工作流有两个 `LoadImage`
（`images.image_1` / `images.image_2`）和一个布尔开关 `494 PrimitiveBoolean`：

```
494=true  → 492 ComfySwitchNode → on_true  = 474 EmptyLatentImage   （纯文生图）
494=false → 492 ComfySwitchNode → on_false = 471[2] 编辑后的 latent （图生图）
```

`comfy_client.py` 新增三个环境变量：

| 变量 | 作用 |
|---|---|
| `COMFYUI_NODE_LOADIMAGE` | 逗号分隔的 LoadImage 节点；按顺序接收 `ref_images` |
| `COMFYUI_NODE_MODE` | 布尔开关节点；有 reference 时写 `False`，否则 `True` |
| `COMFYUI_NODE_SAVE` | 指定只取哪个 SaveImage；留空则多输出按**像素数取最大** |

**参考图必须先上传**：`LoadImage.image` 只认 ComfyUI 服务器 `input/` 目录里的文件名，
写本地绝对路径无效。新增 `upload_image()`（纯标准库手写 multipart，不引入 requests），
上传名用「内容 sha1 前 16 位 + 扩展名」——ASCII 安全、同图重复上传可复用。

**多输出按像素数取最大**：Moss+SeedVR2 这类工作流有「低清 / 高清」两个 SaveImage，
若两个都落盘，一张资产会变成 `x_00.png` + `x_01.png`，下游 `refs.json` 的 glob
与 `--skip-existing` 判重全部被污染。`_img_size()` 读 PNG IHDR / JPEG SOF 纯标准库实现。

### P18 · 落盘改名加固（本次批量里真实撞到的回归）

P3 把落盘改成「先写临时文件 → `os.replace` 换名」，这在 Windows 上会撞：

```
!! FAILED: [WinError 5] 拒绝访问。
   '...\scenes\.__tmp_scene_ward_00.png' -> '...\scenes\scene_ward_00.png'
```

**成因**：目标文件被占用（看图程序、资源管理器预览、杀软扫描都会短暂持有句柄），
`os.replace` 在这里比原来的 `open(wb)` 更严格 —— 原来能「覆盖写」的情况，换名会直接失败。
19 张批量里必撞 1 张。

**修法**：三级降级链，失败时保留临时文件并把路径写进报错（图已经生成，别让用户重跑）：

```python
try:
    os.replace(path, final)
except OSError:
    try: os.remove(final)          # 先删（很多时候删得掉、换不掉）
    except OSError: pass
    try: os.replace(path, final)
    except OSError:
        shutil.copyfile(path, final); os.remove(path)   # 兜底覆盖写
```

> 现场处置：那张图其实已经生成好了，直接把 `.__tmp_scene_ward_00.png` 改名即可，
> **不需要重跑 50 秒**。批量脚本的报错信息里带上临时文件路径就是为了这个。

### P19 · 场景提示词把「信息内容」当成了「视觉元素」（本次最意外的坑）

**现象**：换到 2MP 后，11 个场景卡里 5 个出现伪文字——

| 场景 | 看到的 |
|---|---|
| `scene_clinic` | 整面墙布满「12 个 xxx / 15 个 xxx」的数字表格 |
| `scene_board` | 白板上是一张乱码的折线图，刻度全是乱码 |
| `scene_ward` | 护士站名牌墙上全是乱码卡片 |
| `scene_diner` | 玻璃上的「手写菜单」变成一堆乱码笔画 |
| `scene_lab` | 白板上有伪字 |

**先试了负向词，没用**：把 `text, letters, words, numbers, signage, posters, labels, charts`
加进 `negative_prompt`（cfg=2 确实生效了），重跑同一张 `scene_clinic` —— **墙上还是字**。

**真因在正向提示词**。`【空间】` 行写的是：

```
一年后的社区诊所：白墙、二手候诊椅、墙上 32 个名字
医院病区走廊：日光灯、磨旧地胶、护士站与 41 个名牌墙
集团董事会会议室：长桌、落地玻璃、墙上一张并购进度表
街角餐馆：卡座、转页灯箱、玻璃上的手写菜单
```

模型**忠实照做了**——你让它画 32 个名字，它就画 32 个「名字」。它没有画错，是我们让它画字。

**更深一层**：这些数字是**剧本叙事细节**（纪念墙刻着 32 个死者、护士站挂着 41 个离职护士的名牌），
它们属于「人物/剧情」层，不该出现在「视觉呈现」层。这是 §3.8.1「剧本与资产解耦」的**复发**，
只是这次泄漏的不是长相，而是**信息内容**。

**修法：只描述物质痕迹，不描述其上承载的信息。**

| 原描述 | 改后 |
|---|---|
| 墙上 32 个名字 | 墙上留着一片撕剩的便签残胶与纸痕 |
| 护士站与 41 个名牌墙 | 护士站与一排空的名牌插槽（插槽泛黄、卡片早已抽走） |
| 墙上一张并购进度表 | 墙上挂着一块被反复擦过的白板（只剩擦拭痕与磁粒） |
| 玻璃上的手写菜单 | 玻璃上的油渍与水汽痕 |
| 白板 | 擦净的白板 |

改完重跑 `scene_clinic`：**整面墙的伪数字表格消失**，只剩一处真实的撕纸残胶。
角色卡提示词零变化（`cmp` 逐文件核对，8 张全同），所以角色图不用重出。

**判据（可自动化）**：`world-bible.json` 的 `scenes[].desc` 与场景提示词的 `【空间】` 行
**不得出现承载信息的名词**——`名字 / 名单 / 文字 / 标语 / 海报 / 菜单 / 进度表 / 名牌 / 招牌 / logo`。
出现即改写成材质与痕迹（`残胶 / 划痕 / 褪色 / 擦拭痕 / 空插槽 / 油渍`）。

> **一条更普适的教训**：负向词只能「减少」，不能「撤销指令」。
> 当正向提示词明确要求某个元素时，任何负向词都压不住它 —— 先查正向，再调负向。
> 这次如果只看负向词失效就断定「cfg=2 没用」，会走偏很远。

### P20 · 女主脸上凭空多了一道疤（锚的「强度」没有分档）

**现象**：用户直接指出「女主角为什么脸上还是有个疤」。

**三层根因，缺一层都不会发生**：

**① 锚库条目本身自相矛盾**

`A14` 的原描述是：

```
鼻梁上一道横向浅压痕（长期戴眼镜留下，但不戴眼镜）
```

「长期戴眼镜留下」与「不戴眼镜」在语义上打架。模型无法理解「压痕但没戴眼镜」，
只能按最接近的视觉经验解释 —— **伤疤**。

**② 模板对所有锚都要求「必须清晰可见」**

`live_card_prompt()` 里是一句写死的：

```
【唯一识别锚 · 先读这一条】%s 这个锚必须清晰可见、非对称、在左半脸与右三视图里都能认出来
```

这句话对「素银印章戒」「方框眼镜」是对的，对「一道**浅**压痕」是灾难 ——
你要求它清晰，它就把浅痕加深加宽，变成疤。
再叠加 2MP（P1）的高像素密度，这道「浅压痕」在脸上非常扎眼。

**③ 我把锚交给了算法分配，女主抽到了最显眼的位置**

为了消除「每部剧都同一道疤」（V0.7.26 P6），我把 `overrides.anchor` 全删了、交给配额算法。
算法只保证「不重复、疤类≤1」，**不判断「这个锚放在主角脸上是否合适」**。
鼻梁是整张脸最中心的位置，风险最高，却没有任何闸门。

**修法三件套**：

1. **锚的可见度按类型分档**（新增 `_anchor_sentence()`）：

| 锚类型 | 句式 |
|---|---|
| `饰 / 眼镜 / 纹` | 「必须清晰可见、非对称，在左半脸与右三视图里都能认出来」 |
| `疤 / 痕 / 斑 / 痣 / 轮廓 / 发` | 「要按它本身的尺寸与淡度如实呈现：**不要加深、不要扩大、不要加高光、不要画成伤疤或妆效**，自然光下能辨认即可」 |

2. **`A14` 从「鼻梁压痕」改为「无名指戒痕」**（id 不变，仍属「痕」类配额）：

```
左手无名指根部一圈比周围略浅的肤色（长期戴戒指留下的戒痕，戒指已不在）
```

位置从「脸的中心」移到「手指」，性质从「伤」变成「肤色差」——同属「痕」配额，
但模型不会把它画成伤口。而且对「豪门/老钱」角色（VIVIAN）来说，戒痕本身就是戏。

3. **主角显式指定锚**：`roster.json` 给 ELLE 写 `overrides.anchor: "磨损编织绳"`
   （A08，右手腕，无坠）。理由：急诊护士不能戴戒指手表，但手绳可以一直戴着；
   且在「经济拮据」的人设下，一条磨旧的编织绳比任何首饰都合理。

**判据（可自动化）**：
- 角色卡提示词的锚点句，动词强度必须与 `_anchor_kind()` 匹配（loud / soft 二分）
- **主角（`tier == "lead"`）不得使用 `疤 / 痕 / 斑` 类锚**，除非剧本明确要求
- 锚库条目不得含自相矛盾的因果解释（「A 造成 B，但没有 A」）

**顺手修的同类问题（P15 去否定化）**：
`live_card_prompt()` 里原来有一整段【反默认】是否定句：

```
【反默认】不要画成通用 AI 美人脸：不削尖下颌、不放大眼裂、不垫高鼻梁、不做无毛孔磨皮、
不做左右绝对对称的脸；五官不混入亚裔眼型与扁平鼻骨。
```

cfg=1 时它 100% 无效（R1），cfg=2 后「正向段落里的否定」语义仍不稳定。
改为**正向描述要什么**，把族裔禁忌拆成独立一段：

```
【脸型基准】真实寻常面孔，不是平面化的美人模板：下颌角明确、骨量偏小；
眼裂宽度与脸型成比例、上睑有厚度；鼻梁高度自然、鼻背有轻微起伏与骨点；
皮肤保留毛孔、细纹、不均匀反光与轻微色差；左右脸在眉高、颧宽、嘴角位置上存在可见差异。
【族裔约束】<region_forbid>。
```

### P20b · 锚被画成别的东西（描述太抽象）

女主换锚后第一版出图，脸上确实干净了，但**手腕上的「素色编织绳」被画成了金属手链**——
三个视图里都是银色链子，与 KANE 的「方形旧表」在材质上撞了，锚等于失效。

原因：`A08` 原描述「右手腕一条磨损的**素色**编织绳（无坠）」太抽象。
「素色」「编织」在图像先验里指向不明确，模型默认往首饰方向靠。

修法 —— 给**材质、工艺、构造**，不给形容词：

```
右手腕系着一条米色棉线编织绳（三股细棉线搓成，绳头留短须，无金属件、无吊坠）
```

重出后三个视图里都是浅色细绳、可见绳头须，与金属完全区分开。

**规律**：识别锚的描述必须能被**画出来**，而不是被**理解**。
「素色」「低调」「不明显」这类词模型无法转成像素；
「三股棉线」「绳头留短须」「无金属件」可以。
同一条规律也解释了 P20 的疤：`浅压痕` + `必须清晰可见` 是一对无法同时满足的指令。

### P21 · 分镜三格画成了同一张（描述没给足动作差异）

重出 8 张分镜图后发现 `shot_001` 的三格**几乎是同一画面**，只有色调差异。

查提示词，三格写的是：

| 格 | 描述 |
|---|---|
| top | 两人面对面，工具在中间 |
| middle | 光源灭了，两人变剪影 |
| bottom | 站立者头部**微抬几度**，其余不变 |

差别只有「光灭」和「抬头几度」——**模型忠实照做，于是看起来一样**。
对照组 `shot_008`（钩子镜）三格是「独自举纸 → 右侧入画半身黑影 → 门口站定完整黑影」，推进清晰，一次就对。

修法：把三格改成**可画出来的动作差异**——

| 格 | 改后 |
|---|---|
| top | 坐着的人**伸手去够**，站着的人把工具举在**够不到的高度** |
| middle | 两只手**在工具上碰到**，同时光灭 |
| bottom | 工具已被**收回胸前**，站着的人手臂**收到半空**，两人距离**拉开** |

重出后三格可读：够不着 → 将触未触（黑场）→ 到手后退开。

**判据**：分镜三格的描述，任意两格之间必须至少有一项**可画的物理差异**
（肢体位置 / 物体位置 / 人物进画面 / 距离变化 / 光源状态）。
只写「情绪更紧张」「气氛变了」「头微抬几度」这类**程度副词**，出图必然雷同。

**本次未解决**：2MP + cfg=2 下，剪影带出了鼻梁与下颌的轮廓线，
而硬约束要求「无五官、无 chin or jaw line」。视觉上更易读（能看出朝向），
但严格说不合规。若要严格，需给分镜单独一套负向词
（`facial features, eyes, nose, mouth, profile line, photorealistic`）——
**不能加到通用工作流**，否则角色卡的五官会被削平。

> **该问题随后被整体方案取代，见 P23：剪影已弃用。**

### P23 · 弃用剪影，分镜图改为俯视站位图（★ 破坏性变更）

**触发**：用户看完剪影分镜图，直接要求「把剪影这个环节删掉，不要用剪影了」。

**决策**：改用**俯视站位图**（`top-down floor-plan blocking diagram`）。
这不是新发明——`docs/styles/画风三轨规范.md` §1.3.1 的对照表里本来就有这一项，
当时定位是「调度补充」，现在升为**主方案**。

**为什么这个替换是对的**（不是迁就用户，是剪影本身选错了重点）：

| | 三格剪影 | 俯视站位图 |
|---|---|---|
| 表达的 | 景别 + 光位 + 构图 | 谁在哪、机位在哪、视锥盖哪块地、关键物在哪 |
| 与 H3 提示词的关系 | **重复**——景别光位本来就写在提示词里 | **互补**——调度信息提示词写不清 |
| 一镜产出 | 一张 9:16 纸塞三格 | 一张 16:9 |
| 三格雷同风险 | 高（P21 实测） | 不存在（一镜一张） |
| 文字 | 靠画风结构性消除 | 标题/机位/图例是**需求**，可画对 |

一句话：剪影把**已经写清楚的东西**画了一遍，却画不出**最容易出错的东西**。

**实现三件**：

1. **站位图专用工作流** `workflow_qwen21_blocking_16x9.json`（16:9 / 2MP / cfg=2）。
   与通用工作流**唯一差别是负向词**——必须去掉 `text, letters, numbers, signage, labels`，
   否则标题与图例会被一起压掉；改成
   `photograph, 3d render, perspective view, realistic figures, human faces, hands, colour, gradient, shading, texture, drop shadow, blurry, low detail, watermark`。

2. **提示词模板**（`05-分镜/manifest_sb.json`，8 条全部重写）：

```
A top-down floor-plan blocking diagram for one shot, horizontal 16:9 white sheet,
black uniform-weight line art on pure white, no colour, no shading, no texture,
no perspective, no realistic figures, no faces, no hands.
Human positions = ROUND black dots about the size of a coin, each with ONE short straight
arrow showing facing direction; no letters, numbers or labels inside the dots.
Camera = one filled black triangle standing OUTSIDE the room outline at the bottom edge,
pointing up into the room, with a dashed wedge-shaped field of view; CAM A sits beside it.
ROOM: <walls / furniture footprints / openings>
FIGURE A: <position + facing>
FIGURE B: <position + facing>
KEY MARKER, the most important element on the sheet: <the object that carries the beat>
Title along the top edge reads BLOCKING - EP01 SC01 in small monospace lettering.
One short legend line at the bottom edge: dot A = …, dot B = …
```

3. **规范同步** `docs/styles/画风三轨规范.md` §1.3.1：
   ① 标题改「统一画俯视站位图」，剪影标为**2026-10-31 弃用**并写明原因；
   ⑥「剪影的代价」改为「站位图的边界」；⑦ 改为「站位图必须写文字，负向词要单独配」；
   ⑧ 模板补「相机在房间外」并加三个新坑（相机跑进房间 / 单人镜凭空多一个人 / 缺图例无法审阅）；
   ⑨ `weak_reference` 的解释由「复刻剪影质感」改为「把平面调度图当画面去复刻」。

**实测结果**（Qwen 2.1 turbo / 2MP / cfg=2 / 单张约 50 秒）：

- 标题 `BLOCKING - EP01 SC01`、机位 `CAM A`、图例 `dot A = nurse, dot B = owner` **全部清晰可读，无乱码**
- 圆点带朝向箭头、视锥虚线扇开、关键物方块位置准确
- 无透视、无人物、无彩色、无多余元素

**判据**：
1. 图纸必须是**俯视平面**，无透视、无写实人物、无脸
2. 每个人物是**一个圆点 + 一条朝向箭头**，点内无字母数字
3. 相机三角必须在**房间轮廓之外**，且有 `CAM A` 与虚线视锥
4. 底部必须有**一行图例**，否则无法审阅
5. 单人镜必须显式写 `exactly ONE human dot on the whole sheet`

**已删除**：`05-分镜/scenes/` 下 8 张三格剪影图（1920×1088 的 9:16 版已作废）。
**保留**：`manifest_sb.json` 的 8 条记录改为站位图提示词，画幅改 16:9。

### P24 · 多集分镜图串集：EP02 的 8 张图标题写着 EP03（★ 数据流缺陷）

**现象**：EP02 的站位图出完后，随机抽一张 `ep02/shot_007_00.png` 检查，
图上标题是 **`BLOCKING - EP03 SC07`**，画的是楼梯间 —— EP03 的内容。

**根因（三层，缺一层都不会串）**：

1. `convert_storyboard.py` 的 `data_dir = W.data_dir(ws)` 是**固定目录**（`06-提示词/`），
   不按集分子目录。所以每转换一集，就覆盖上一集的 `shots.json` / `h3_prompts.json`。
2. `build_sb_manifest.py` 默认从 `06-提示词/shots.json` 读 —— 那个位置**只保留最后一集**。
3. 触发点：我把 `kind` 从 `scene` 改成 `shot` 之后，跑了一次「批量重建三份清单」：

```bash
for ep in ep01 ep02 ep03; do
  python build_sb_manifest.py --project <项目> --ep $ep     # ← 三次都读同一个 shots.json
done
```

三次都拿到当时 `shots.json` 里的内容（= EP03），于是 `manifest_sb_ep01/02/03.json`
**全是 EP03 的 8 条**，只有文件名不同。

后果分集看：
- **EP01 的图反而是对的** —— 它在污染之前就已经出完了，只是后来 `mv` 进了 `scenes/ep01/`
- **EP02 的 8 张全错** —— 用被污染的清单出的，标题、空间、站位全是 EP03
- **EP03 碰巧对** —— 它跑的时候清单内容正好就是 EP03

**修法**：

1. `build_sb_manifest.py` 新增 `--shots`，**显式绑定本集源文件**：

```bash
python build_sb_manifest.py --project <项目> --ep ep02 \
  --shots "<项目>/06-提示词/_eps/ep02/shots.json"
```

2. 每集转换后归档一份 data 快照到 `06-提示词/_eps/<ep>/`（本项目的 `_tools` 流程已加）。
3. 站位图按集分目录：`05-分镜/scenes/ep01|ep02|ep03/`，清单按集命名
   `manifest_sb_<ep>.json` —— 因为**每集的 shot_id 都从 `shot_001` 起**，不分目录会互相覆盖。
4. 清单里的 `kind` 用 `shot`（不是 `scene`）—— `comfy_client` 会把 `scene` 映射到
   `scenes/` 子目录，那样按集分好的 `--out` 又会被套一层。

**判据（可自动化，务必加上）**：
1. 生成清单后，检查**首条** `ROOM:` 描述是否属于本集场景 —— 本项目 EP01/EP02 是锅炉房、EP03 是会议室
2. 每份清单的 `assets` 数量等于本集分镜段数
3. 出图后**抽检图上标题的集号**是否等于目标集（这次就是靠这个发现的）

> **普适教训**：任何「读当前状态」的批处理，在存在多版本产物时**必然串**。
> 循环 `for ep in ...` 里读一个固定路径，等于让三次迭代共享最后一次的输入。
> 要么显式传源路径，要么在循环体里先切工作目录 —— 不要依赖「默认路径刚好是对的」。

**遗留（未修，属引擎缺陷）**：`convert_storyboard.py` 不支持按集分目录，
多集项目必须靠外部归档 `_eps/` 绕。若要根治，应给 `data_dir` 加 `--ep` 维度
（如 `06-提示词/<ep>/`），并同步修改 `ingest_check.py` 与出片脚本的读取路径。

> **判据 4 的写法是实测修正过的，不要写成「像素 md5 一致」。**
> 本机 ComfyUI 启了 `Using async weight offloading with 2 streams` + `cudaMallocAsync`，

> 也就是说：**固定 seed 保证的是「身份与构图稳定」，不保证字节级复现。**
> 对角色卡来说前者才是业务需要的；硬拿 md5 当验收线只会得出「seed 没用」的错误结论。

## 八、附：为什么最终没用 Moss-image

Moss 的细节确实更实（毛孔、胡茬、发丝都在），但两个「听话度」问题解决不了：

| 项 | Moss-image | Qwen 2.1 turbo |
|---|---|---|
| 皮肤毛发细节 | ★★★ | ★★（2MP + cfg2 后接近） |
| 年龄遵循 | ✗（38 岁出成 50 岁） | ✓ |
| 发型遵循 | ✗（短寸偏分 → 大背头） | ✓ |
| 负向词 | ✓ 生效（cfg 3） | ✓（cfg 2 后） |
| 耗时 | 46 s | 50 s |

角色卡是**用于全剧身份一致性的工业件**，年龄/发型错了就得重画；
细节可以靠分辨率和 cfg 补，五官年龄补不回来。故最终统一 Qwen。

工作流文件保留在 `workflows/moss_image_16x9.json`，需要时可切换。

### 附带的 SeedVR2 环境修复（已修，暂不启用）

用户要求「后面把 SeedVR2 加进去」，排查后发现节点根本没注册：

```
ModuleNotFoundError: No module named 'comfy_api'
```

**根因**：`diffusers 0.27.2` 太旧，其 `dynamic_modules_utils` 仍在 import `cached_download`，

修法（装完节点即恢复，无需改代码）：

```bash

  "diffusers>=0.33.1" gguf peft omegaconf rotary_embedding_torch
# → diffusers 0.42.1 / huggingface_hub 1.33.0 / gguf 0.19.0 / peft 0.21.2
```

已产出 `workflows/moss_hires_16x9.json`（Moss + SeedVR2，19 节点）备用，参数要点：

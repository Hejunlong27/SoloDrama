## 3. 回灌顺序建议

建议按依赖顺序改，每改完一层跑一次验证，不要一次性全铺。

### 第 1 步：校验层（影响所有已有项目）

```bash
# 改 tools/core/validate.py、convert.py、tools/cli.py
python -m unittest stages.production.scripts.tests.test_setup_workflow_pipeline   # 期望 57 passed
```

> ⚠️ **破坏性**：`LATIN_SENT_MAX` 从 55 改为 0（不限），单镜句数 2→4。
> ⚠ **2026-11-01 更正（实测打破了原结论）**：这句「不会变严，安全」是**错的**。
> 取消 55 字符上限确实放宽了长句，但新增的「词/秒预算」会**收紧短镜**：
> 4 秒镜 + 两句共 19 词 → 旧口径 PASS，新口径 E007 FAIL（预算 `int(4×3.8)=15`）。
> 存量项目升级前请先 `--dry-run` 比对新旧判定，不要默认「只会变松」。
> 但 `_split_codes` 让 `CHAR: A, B` 从「报错」变「合法」，如果有下游脚本自己解析
> `CHAR` 字段，要同步改成按分隔符拆。

### 第 2 步：资产设计层

```bash
# 改 character_design.py + 测试
cd stages/assets/scripts && python tests/test_character_design.py               # 期望 28 passed
```

> ⚠️ **破坏性**：`seed` 缺省值由常量 `"solodrama"` 改为按名册派生。
> **已出图的项目重跑 `plan` 会换锚点与配色**，图片要重出。改之前先备份 `character-bible.json`。

### 第 3 步：出图客户端

## 4. 三条最值得先看的结论

如果只能记住三件事：

**① 负向词只能「减少」，不能「撤销指令」。**
正向提示词里明确要求的元素，任何负向词都压不住。EP01 的场景出现满墙乱码，先加
`no text, no letters` 完全无效——真因是正向里写着「墙上 32 个名字」。**先查正向，再调负向。**

**② 凡上游生成的产物，改它等于没改。**
`convert_storyboard.py --apply` 会按 `04-资产/refs.json` 重写 `characters.json`。
直接改产物，下次转换就回滚——单人参考图的修复就这样被无声撤销过一次。**定位「谁生成它」再改源。**

**③ 静默失效比报错危险。**
字幕提前的反编译修复里，正则被多转义成 `//s`，匹配不到任何东西，函数静默返回 0，
日志一行不打、流程照常出片。判据必须是**看行为**（抽 0.2 s 的帧，没有字幕才算修好），
不是看有没有异常。

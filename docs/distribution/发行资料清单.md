## 一、总览：一次交付五类东西

| 类 | 落点 | 关键要求 | 缺失后果 |
|---|---|---|---|
| **剧集**（发布版成片） | `09-发行/剧集/` | **严格 `EpisodeNN.mp4`**（`Episode01.mp4` …）；集号连续；随包 `剧集清单.json`（见 §二） | 上架要手工改名，且无法证明集序完整 |
| **封面** | `09-发行/封面/` | 多尺寸成组；**必须有抓马度与视觉冲击**（见 §三） | 信息流里点不进来 = 没有播放 |
| **文案** | `09-发行/文案/` | 标题六槽位 + 三档描述 + 关键词 | 搜索与推荐拿不到特征 |
| **发布清单** | `09-发行/发布清单.md` | 逐项勾选 + 发布节奏 | 漏项返工 |
| **版权资料** | `09-发行/版权资料/` | **平台两个入口各 ≥4 张**（AI 生成过程 / 原始文件素材）**+ 7 页签章权利声明**（见 §四） | 被质疑「搬运」或「无权发行」时**无法举证**；2026-11-07 就是这样被驳回的 |

> 一句话：前四类决定「**能不能被看到**」，版权资料决定「**被质疑时能不能保住**」。

## 二、发布版剧集：命名与落点（★ 2026-10-19 用户要求，不许自行发挥）

> 用户原话：「发布版剧集的命名，严格以 `Episode+**` 的格式，如 Episode01、Episode02、Episode03。
> 不要每次输出之后，发布版文件名字都是乱七八糟的。」

| 项 | 规定 |
|---|---|
| **文件名** | `Episode` + **至少两位编号** + `.mp4` → `Episode01.mp4`、`Episode02.mp4`、`Episode40.mp4`；≥100 集自动加位（`Episode100.mp4`） |
| **大小写与形式** | 前缀必须是 `Episode`（大写 E），**不得**写成 `EP01` / `ep01` / `第1集` / `最终版` |
| **落点** | `09-发行/剧集/` —— 「发布版」属于**发行物料**，与封面/文案/版权资料并列 |
| **随包清单** | `09-发行/剧集/剧集清单.json`（集号 → 文件名 / 字节数 / 来源），由脚本生成，**勿手改** |
| **中间产物不算发布版** | `07-成片/<批次>/`、`07-成片/subs/<ep>/<ep>_subbed.mp4`、`<ep>_master_<W>x<H>.mp4`（如 `1080x1920`）都是**工作产物**，名字不必规范；**只有导出到 `09-发行/剧集/` 的才算发布版** |
| **集号连续性** | 整季交付前必须 1…N 连续（连载中允许缺号，门禁只告警；命名不符则**直接拦**） |

**唯一正确的做法（别手工改名）**

```powershell
# 1) 干跑：先看「哪个源 → 哪个目标」
python stages/production/scripts/release_export.py --workspace "<工作区>" --all
# 2) 真写：导出到 09-发行/剧集/EpisodeNN.mp4（自动探测来源；指定来源用 --from）
python stages/production/scripts/release_export.py --workspace "<工作区>" --all --apply
python stages/production/scripts/release_export.py --workspace "<工作区>" --from "<已编码发布版目录>" --all --apply
# 3) 门禁：命名不符 / 缺集 一律退出码 2
python stages/production/scripts/release_check.py --workspace "<工作区>"
```

**来源优先级**（同一集在多个目录都有时取「最接近可发布」的那份）：
已编码发布版（`1080p` / `hd` / `final` / `pub`） → `_subbed`（烧字幕成片） → `_master_<W>x<H>`（放大母版，旧名 `_master_2k` 仍识别） → `_master`。

**反例（出现即判未完成）**：`EP01_1080p_ES.mp4`、`ep01_拼接_11段_672x1216.mp4`、`ep01_西语硬字幕_11段_672x1216.mp4`、
`第一集.mp4`、`Episode1.mp4`（编号不足两位）、`Episode01_final_v2.mp4`（额外后缀）。

## 三、封面：抓马度与视觉冲击（**本版新增硬要求**）

### 3.1 目标：0.5 秒法则

封面唯一 KPI 是**信息流里 0.5 秒内让人停住手指**。因此：
宁可「**过度戏剧化**」也不可「**平稳无张力**」—— 封面**不是**剧照精选，是**冲突海报**。

### 3.1.1 生产路径（2026-10-20 起）

**封面由 AI 一次画出来（含标题排版），不用程序在底图上叠字。**

| 环节 | 工具 / 规范 |
|---|---|
| 提示词编译 | `stages/production/scripts/cover_prompt.py`（五段式 + 标题断行 + 字数体检） |
| 提示词规范 | `stages/production/references/cover/prompt-guide.md`（**必读**） |
| 出图通道 | 本地 ComfyUI（`stages/assets/comfyui/comfy_client.py`，￥0） |
| 兜底（不默认用） | `stages/production/scripts/cover_forge.py`（底图 + PIL 叠字；仅当 AI 反复写错标题时） |

理由：程序叠字的标题永远压在图上、不参与构图，抓马度上限低；
AI 直出能让「两个人的距离、眼神、手的位置、光落点」一起为标题服务。
代价是**AI 可能拼错字**，处置见 `prompt-guide.md §七` 五级降级（重试 → 拆行 → 加权 → inpaint → 兜底叠字）。

### 3.2 抓马度六抓手（逐条自评，命中 ≥5/6 才可发行）

| # | 抓手 | 具体要求 | 反例（不允许） |
|---|---|---|---|
| 1 | **单主体大特写** | 人物**情绪到脸**（愤怒 / 落泪 / 冷笑 / 震惊），主体占画幅 **≥45%** | 全身远景、群像平铺 |
| 2 | **强明暗对比** | 背景压暗 ≥1.5 档，主体打亮；vignette 收边 | 全图均匀光、灰蒙蒙 |
| 3 | **冲突可视化** | 画面内必须有一个**可指认的冲突物**（见 §3.5 道具表） | 只有人物站姿，无物件叙事 |
| 4 | **大字标题** | 中文 **≤6 字** / 西语 **≤3 词**，字重最重，描边或色块压底保可读 | 长标题铺满、细体字 |
| 5 | **悬念留白** | 只露一半信息（半张脸、被遮住的第二人、背对镜头的对手） | 把剧情结果直接画在封面上 |
| 6 | **情绪色** | 按题材定调（见 §3.3 色板），高饱和撞色，**冷暖对冲** | 低饱和滤镜、糖水调 |

### 3.3 题材 → 色板与情绪对（可直接抄）

| 题材 | 底色 | 撞色 | 情绪对 |
|---|---|---|---|
| 逆袭 / 打脸复仇 | 墨黑 `#0E0F12` | 金 `#E9C79C` + 正红 `#C81E1E` | 冷蔑视 × 被压抑的怒 |
| 虐恋 / 离婚 | 冷蓝灰 `#141A22` | 一抹正红 `#C81E1E` | 落泪 × 冷脸 |
| 家族争产 / 商战 | 深棕 `#1B140F` | 香槟金 `#DFC08A` | 冷笑 × 惊愕 |
| 悬疑 / 复仇 | 青黑 `#0B1416` | 冷白高光 + 血红点 | 背身 × 正脸 |
| 甜宠 / 先婚后爱 | 酒红 `#3A1020` | 暖粉 `#F0A0A8` | 对视 × 躲闪 |

> 平台 UI 会盖住**右下角**与**底部字幕区**：主标题、脸部、冲突物一律**不得**落在下方 20% 与右下角安全区。

### 3.4 硬约束（违反即返工，与引擎口径一致）

1. **不得裁切标题与角标**：3:4 海报装 9:16 画布时，采用「**模糊放大 + 压暗 12% 作背景，海报等比缩放居中**」，不允许裁切。
2. **首帧亮度必须恒定**：先合成**静帧 PNG**，再 `-loop 1` 编码成视频；直接在滤镜链里 `-loop 1` 输入会让前 5 帧从纯黑爬亮（实测 0.0 → 8.4 → 18.2 → 27.5 → 37.1），首帧不是海报即失效。
3. **色彩范围必须显式声明**：JPEG 原图为 full range（`yuvj420p`），成片为 `yuv420p + tv`；不做
   `scale=in_range=full:out_range=tv` 会**整片发灰**。
4. **不得出现第三方水印 / 台标**（合规条款 Unoriginal Content and IP Rights）。
5. **AIGC 真人化必须标注**：全剧统一在片头/片尾/文案位标注，**不得只在部分集标注**（未标注 = 降流）。
6. **四视图设定板必须先切分**：2368×1344 一类设定板直接送封面引擎 → 封面出现四宫格拼贴。
   送引擎前裁最左特写面板（`crop=592:1344:0:0` 类），并在资产入库时标记版式类型。

### 3.5 冲突物道具表（第 3 抓手的可选清单）

> 抓马的本质是**让观众一眼看出"发生了什么事"**。选用**可指认、有法律或伦理重量**的物件：

`撕裂的离婚协议` `验孕棒（两道杠）` `支票 / 转账短信` `亲子鉴定报告` `房产证 / 股权书`
`黑卡 / 车钥匙` `被泼的咖啡渍` `监控截图` `病危通知书` `欠条 / 借据` `旧照片（被撕一半）` `手铐 / 传票`

### 3.6 反例（出现任一即打回重做）

- 四宫格 / 九宫格 / 多主体平铺拼贴；
- **纯文字无人物**，或人物只占画面一角；
- 低对比灰调、重滤镜糖水脸（第三方平台会识别为「AI 感过重」）；
- 把剧情**结果**直接画出来（悬念归零）；
- 主标题压住脸部或落在右下角安全区。

### 3.7 抓马度自评表（写进 `cover_brief.json` 的 `notes`，随封面一起交付）

```json
{ "drama_check": { "single_subject": true, "contrast": true, "conflict_prop": "撕裂的离婚协议",
                   "title_chars": 4, "suspense": true, "emotion_palette": "逆袭",
                   "score": 6, "reviewer": "<放行人工号或名字>" } }
```

`score < 5` 或 `reviewer` 为空 → 视为**未完成**。

## 四、版权资料（**两个平台入口 + 权利声明，2026-11-07 按驳回诊断重写**）

### 4.0 定位：先分清「是我做的」与「我有权授权」

一次真实驳回（《La Heredera Oculta》2026-11-07，TikTok Drama Center）：

> **材料不足：提交的版权材料不足以证明本剧所需的相关权利。**

当时交的是 8 张**数据面板** —— 批次记录、工作流参数、目录树、ffprobe 输出。两个错：

| 错 | 具体 | 后果 |
|---|---|---|
| **对标错** | 平台要求截图「能够对应拟上线作品的**具体画面、角色、场景或片段**」，我们交的全是数字和表格 | 审核员无法把任何一张图指向某一集某一帧 |
| **层次错** | 截图只能回答「这片子是我做的吗」；平台问的是「**发行权在你手上吗**」 | 缺权利人、缺权属声明、缺授权链 ⇒ 必然驳回 |

所以版权资料分两**层**，缺一层都过不去：

| 层 | 回答什么 | 载体 | 谁来做 |
|---|---|---|---|
| **截图层** | 内容确由本项目生成、素材文件在手上 | 平台两个入口的 PNG | 引擎生成（`copyright_kit.py`） |
| **权利层** | 谁拥有、原创性、AI 合规、第三方清零、授权范围 | 7 页 A4 声明书（签章） | 引擎出模板，**人签字盖章** |

> 一句话：截图解决「质疑搬运」，声明书解决「质疑无权」。上一版只做了前者，且做偏了。

### 4.1 平台两个入口（原文要求，张数区间 4–20）

| 入口 | 平台原文 | 张数 | 落点 |
|---|---|---|---|
| **A · AI 生成过程** | 可提供至少 4 张、最多 20 张能够展示**提示词、操作过程及对应生成结果**的截图。截图需要能够对应**拟上线作品的具体画面、角色、场景或片段**。 | 4–20（建议 6） | `09-发行/版权资料/AI生成过程/` |
| **B · 原始文件或素材文件信息** | 可提供至少 4 张、最多 20 张包含**文件信息**的截图，材料类型可包括**剧本、角色矢量图、场景设计图、视频 raw 文件、项目素材文件**等。 | 4–20（建议 6） | `09-发行/版权资料/原始文件/` |
| **C · 剪辑工程**（2026-11-10 新增） | 平台没有为它单列入口，但它回答的是两个入口共同的追问：**「这几十秒是怎么剪出来的」**——素材顺序、字幕何时进、BGM 铺多长。以补充材料随包提交。 | 4–20（建议 4 + 1 张人工截图） | `09-发行/版权资料/剪辑工程/` |

### 4.2 入口 A：每张板必须「四者指向同一镜」

一张板 = A4 竖版，四块内容缺一不可：

| 位置 | 内容 | 数据来源 |
|---|---|---|
| 左栏 | 该镜**实际提交**的提示词原文（不英文化、不美化） | `06-提示词/<ep>/h3_prompts.json` |
| 中栏 | 该镜**分镜图**（首帧参考） | `04-资产/boards/<ep>/<shot>.png` |
| 右栏 | 该镜**成片抽帧**（片长 55% 处，可复现） | `07-成片/<ep>/<shot>/final.mp4` |
| 底部 | 该镜**用到的角色/场景/道具卡**（≤3 张，带文件名） | `04-资产/{characters,scenes,props}/` |

参数行固定写 `SHOT / DURATION / SEED / RENDER / RATIO` —— 种子与耗时来自
`07-成片/<ep>/_batch_local.json`，**是这台机器真跑出来的数字，不是估的**。

**选镜规则**（`copyright_kit.pick_shots`）：集层面均匀分布（第 1 张必须是开局，审核员靠它
判断这剧讲什么）；集内取「cast 最多、时长最长」的一镜 —— 出镜角色越多，越能对上
「对应具体画面、角色、场景」。要指定就用 `--shots ep01:shot_007,ep13:shot_002`。

命名：`ai-gen-<NN>-<ep>-<shot>.png`，如 `ai-gen-01-ep01-shot_007.png`。

### 4.3 入口 B：六类原始文件，每张带文件信息条

| # | 文件名 | 内容 | 平台列举的类型 |
|---|---|---|---|
| 1 | `src-01-screenplay.png` | 剧本文件名/大小/时间 + 正文首页 | **剧本** |
| 2 | `src-02-character-design.png` | 主角三视图 + 造型卡（≤4 张） | **角色设计图** |
| 3 | `src-03-set-design.png` | 主要场景设计图（≤4 张） | **场景设计图** |
| 4 | `src-04-storyboard.png` | 导演手册：逐镜时长/着装/机位/台词 | **项目素材文件** |
| 5 | `src-05-video-raw.png` | 逐镜 `final.mp4` + 集母版的文件清单（名/大小/分辨率/时长） | **视频 raw 文件** |
| 6 | `src-06-asset-inventory.png` | 资产卡与分镜图总览 + 样例 | **素材文件** |

每张顶部必须有**文件信息条**（文件名 / 大小 / 修改时间 / 路径）—— 平台原文就是
「包含**文件信息**的截图」，这一条就是那个「信息」。

### 4.3.1 出口 C：剪辑工程（4 张机器板 + 1 张人工时间轴截图）

成片只能证明「有一段视频」；工程能证明「这一段是**逐镜拼的、每一镜可回溯到素材、字幕时间来自对齐**」。
一集一个剪映工程，落 `07-成片/<ep>/_draft/<ep>_剪映工程/`，由 `stages/edit/scripts/edit_draft.py` 生成。

| # | 文件名 | 内容 | 数据来源 |
|---|---|---|---|
| 1 | `draft-01-overview.png` | 各集工程：目录 / 画布 / fps / 总时长 / 轨内容 / 自检结论 | `draft_manifest.json` |
| 2 | `draft-02-timeline.png` | 逐镜起止与素材（封面片头单列一行）+ 轨汇总 | `tracks.video` |
| 3 | `draft-03-subtitles.png` | 字幕逐条起止 + 文本 + **对齐来源**（ctc-/asr-） | `tracks.text` |
| 4 | `draft-04-digest.png` | 素材 SHA-256 台账（可回原文件核对） | `tracks.{video,audio}.sha256` |
| 5 | `draft-shot-01-<ep>.png` | **人工**：在剪映里打开草稿截的时间轴图 | 人截 |

三个必须知道的边界：

1. **工程不是成片**。剪映 7+ 已隐藏导出控件，`pyJianYingDraft` 的自动导出只支持剪映 6 及以下，
   本仓库不使用该能力 ⇒ `EpisodeNN.mp4` 仍由 ffmpeg 链出。两条轨**必须一致**，
   `edit_draft.py` 用 `verify()` 逐项比对（画布 / 总时长 / 每条字幕起点 / 素材可读），不一致就退出码 2。
2. **不伪造 UI 截图**。本机不装剪映，也不该画一个假的界面。第 5 张只能人截；
   门禁对「缺截图」只告警，对「缺机器板」直接拦。
3. **工程里存的是绝对路径**。换机器会断链；需要整体搬走时用 `--copy-media`。

生成与校验：

```bash
python stages/edit/scripts/edit_draft.py --workspace "<剧目录>" --ep ep01
python stages/production/scripts/copyright_kit.py --workspace "<剧目录>" edit-draft
python stages/production/scripts/release_check.py --workspace "<剧目录>"   # 校验 draft-01..04
```

### 4.4 权利声明 7 页（A4，打印签章后拍照上传）

落点 `09-发行/版权资料/权利声明/`，尺寸 1654×2339（A4 @200dpi）。

| 文件 | 内容 | 对应平台实质要求 | 是否必须 |
|---|---|---|---|
| `rights-01-ownership.png` | 权属声明：作品标识 + 独占所有权 + 无权利负担 | 权利人身份、权属依据 | **必须签章** |
| `rights-02-originality.png` | 原创性证明：按文件日期排的六阶段创作链 + 人类创作贡献清单 | 剧本原创性 | **必须签章** |
| `rights-03-ai-disclosure.png` | AI 使用披露：模型与许可基础、提示词作者、权利立场、标注 | AI 环节合规 | **必须签章** |
| `rights-04-third-party.png` | 第三方素材声明：音乐/素材/字体/肖像/商标/场地，六项逐条 | 音乐字体授权状态 | **必须签章** |
| `rights-05-inventory.png` | 逐集清单：文件名 + 时长 + 分辨率（真实 ffprobe） | 授权范围 | 建议签章 |
| `rights-06-authorisation.png` | 发行授权书 | 上传账号 ≠ 权利人时 | **视情况**（同主体可省） |
| `rights-07-index.png` | 提交索引：每页证明什么 + 常见驳回对照 | — | 建议一并上传 |

**三条措辞纪律**（写死在 `copyright_kit.rights_docs` 里，别改回去）：

1. **只写事实，不写核不了的授权主张**。字体说「已栅格化进画面、MP4 里没有字体程序」，
   而不是「Arial 商用嵌入已获授权」；音乐说「全部由模型音频分支合成、无第三方」——
   没有第三方正是最干净的答案。
2. **日期取真实 mtime**，不写死。换项目写死就是假的，审核员一对就穿。
3. **把能力边界写进正文**（提示词作者是谁、DOC 6 何时适用），让审核员能据此追问。
   「说得清边界」比「看起来完美」更可信。

### 4.5 格式与命名硬要求

| 项 | 要求 |
|---|---|
| 格式 | PNG（首选）/ JPG（`quality ≥ 92`） |
| 长边 | **1200–2560 px**（`copyright_kit` 输出 1654×2339，落在区间内） |
| 可辨认性 | 提示词、文件名、时间戳必须肉眼可读 |
| 敏感信息 | **必须**打码 API Key / 手机号 / 收款账号；**不得**打码文件时间戳（那是证据本体） |
| 命名 | 入口 A `ai-gen-NN-epNN-shot_XXX.png`｜入口 B `src-NN-<slug>.png`｜剪辑工程 `draft-NN-<slug>.png`（人工截图 `draft-shot-NN-<ep>.png`）｜声明 `rights-NN-<slug>.png` |
| 序号 | 连续不缺号（缺号门禁只告警：多半是漏传） |

### 4.6 `版权资料清单.md`（必须随包交付）

逐张一行：文件 / 类别 / 拍的是什么 / 生成时间 / 关键可见信息。外部人靠它读懂举证链。

### 4.7 提交顺序

**三个入口分开传，别混着传**：

1. 入口 A：`ai-gen-01 → NN`（第 1 张最重要，放全剧钩子那一镜）
2. 入口 B：`src-01 → NN`（若只收 4 张：01 剧本、02 角色、03 场景、05 video raw —— 正好覆盖平台列举的四类）
3. 权利声明：`DOC 1 → 7`（06 视情况）

### 4.8 旧口径（2026-11-07 废止，但文件别删）

`ai-process-01..04` / `source-file-01..04` **不再作为主材料**。它们是「创作过程台账」，
在被追问「这些 AI 内容真是你生成的、不是搬运的」时作为**补充证据**有价值，
但**替代不了**上面三层。

门禁对残留文件只告警（`release_check` 会点名），不要求删除 —— 删除会毁掉追询时的台账。

### 4.9 生成与门禁

## 五、文案（六槽位 + 三档描述）

| 槽位 | 内容 | 约束 |
|---|---|---|
| `title` | 发行标题 | ≤12 字（中文）/ ≤6 词（拉丁语系）；与封面主标题一致 |
| `subtitle` | 副标题 | 一句话点出身份反差（如「被扫地出门的总裁夫人」） |
| `logline` | 一句话故事 | ≤40 字，含**谁 / 冲突 / 赌注** |
| `tags` | 关键词 | 5–8 个；含题材词 + 情绪词 + 平台热词 |
| `desc_short` | 短视频平台简介（≤50 字） | 前 15 字必须有钩子 |
| `desc_long` | 详情页简介（≤300 字） | 三档描述之一，不得剧透反转底牌 |

**三档描述**：`short / medium / long` 三份，供不同位上架时选用；`copy.json` 为机器真源。

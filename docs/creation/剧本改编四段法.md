# 剧本改编四段法（S3 工作流）

> 日期：2026-10-20 ｜ 适用：`stages/creation/` 的 ④ 剧本改写环节
> 定位：`剧本强度工程.md` 回答「什么样的剧本才够强」，本文回答「**按什么顺序做、每步用什么卡**」。
> 起因：`plan` 能产出格式齐全的 N 集四件套，但内容常是句库拼装 —— **结构齐、内容空**。
> 实测反馈集中在两件事：动笔前没判断「这个选题靠什么留住观众」；写完没人以观众视角验一遍。

---

## 一、核心判断

短剧不好看，通常不是「不够狗血」，是四件事缺了一件：

| 缺什么 | 观众侧表现 | 对应关卡 |
|---|---|---|
| 卖点判断 | 什么都有，但没有一个非看不可的理由 | ① 诊断（A） |
| 改动取舍 | 照搬源稿结构，或改成另一个故事 | ① 诊断（B/C） |
| 局势变化 | 每集都在吵，但没有一集改变局面 | ④ 结构审查 |
| 观众验收 | 创作者觉得没问题，观众第 3 集就走了 | ④ 观众审稿 |

**一句话**：先把「靠什么留人」写下来，再把结构搭出来，最后请观众视角的人来挑刺 —— 顺序错了，后面所有努力都是给一个错的故事做美化。

---

## 二、四段流程与门禁

```
① 诊断        diagnose           A 选题诊断 / B 改编策略 / C 故事主线
              ├ 产物 03-剧本/diagnosis.json + .md
              └ 门禁 diagnose --check 全绿 → diagnose --confirm
                    ↓（未确认禁止写正文：build --emit 退出码 4）
② 骨架        plan               D 分集大纲（逐集 cold_open/core_conflict/reversal/hook）
              ├ 产物 03-剧本/blueprint.json + .md + script-brief.md
              └ 门禁 review（第二轮结构审查）退出码 2
                    ↓
③ 正文        build --ep N --emit → LLM 按 prompts/s3-script-rewrite.md 写
              └ 门禁 lint --ep N（FFS 结构 + 留存四件套）+ tools/cli.py check
                    ↓
④ 验收        audience          观众视角七问
              ├ 产物 03-剧本/audience-review.md
              └ 门禁 audience --check 退出码 2
```

四段的产物都在 `03-剧本/`（有 `layout.json` 的项目自动落到分阶段目录），可断点续跑、可只重跑一段。

---

## 三、① 诊断：先回答问题，再动手写

### A. 选题诊断（七个问题，缺一不可）

1. **核心卖点**：这个设定里最吸引人的那一点是什么（不是剧情简介）
2. **情绪共鸣点**：目标观众在哪一刻会愤怒/憋屈/爽
3. **主角四项**：想要什么 → 谁在阻碍 → 输了失去什么 → 靠什么反击
4. **落差**：身份差 / 信息差 / 权力差 / 情感差，至少一条
5. **观众期待**：他们追下去是为了看到哪个结果
6. **钩子落位**：开场钩子 / 阶段性高潮 / 集尾悬念，各给一个具体设计
7. **硬伤**：可能让观众弃剧的风险（写「无」视为未诊断）

> 第 7 项是这套流程最容易走过场的一项。**没有风险的选题不存在**，写不出来通常意味着还没判断清楚。

### B. 改编策略：每一处改动都要有戏剧目的

| 类型 | 判断标准 |
|---|---|
| `keep` 保留 | 删了会伤到卖点（核心设定、人物关系、爽点机制） |
| `adjust` 调整 | 顺序、节奏、视角需要改，骨架保留 |
| `cut` 删减 | 不服务任何 3 集内的爽点 / 与主线无关 |
| `merge` 合并 | 两个功能重复的人物或场景 |
| `add` 新增 | 缺铺垫、缺见证者、缺可量化筹码 |

**红线**：不许把「改动多」当作改编质量。每条改动必须写清「为什么这样改能让观众更想看」。

### C. 故事主线

一段话说清：**从什么处境出发 → 经历哪些关键事件（≥3）→ 完成什么目标 → 付出什么代价或发生什么改变**。
这一段先写不出来，说明故事还没成形，不要进入分集。

### 命令

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> diagnose          # 生成/补缺诊断卡
python stages/creation/scripts/script_rewrite.py --workspace <ws> diagnose --check  # 校验（退出码 2 未过）
python stages/creation/scripts/script_rewrite.py --workspace <ws> diagnose --confirm
```

预填只带**事实型上下文**（logline / 冲突 / 受众 / 源剧本体量），判断型字段一律留空 —— 空着就是在提醒你还没想清楚。

## 四、② 骨架：D 分集大纲 + 第二轮结构审查

`plan` 产出逐集四件套。**默认值来自句库**，只可作占位；真正可用的大纲必须人工覆盖：

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> plan --episodes 40 \
    --from-outline 03-剧本/人工拆解.md
```

拆解表写法（列数决定覆盖范围）：

```
EP01 | 开场钩子 | 核心冲突 | 反转 | 集尾钩子 | 情绪
EP02 | 开场钩子 | 核心冲突 | 反转 | 集尾钩子 | 情绪
```

### 第二轮结构审查（`review`）查什么

| 检查项 | 判定 | 说明 |
|---|---|---|
| 主角是否主动 | FAIL（零主动集）/ WARN（<30%） | 只挨打的主角不产生爽感 |
| 反转是否改变格局 | FAIL（连续三集无筹码/身份/信息变化） | 只改情绪不算反转 |
| 冲突是否在推进 | FAIL（去重 <55%）/ WARN（<75%） | 换场景重复同一场羞辱 = 注水 |
| 连续三集同一冲突 | FAIL | 观众会觉得上一集已经看过 |
| 集尾钩子是否由本集推出 | WARN（<50%） | 空降新事件的钩子是硬截断 |
| 情绪曲线是否被设计过 | WARN | 句库轮转 = 没设计 |
| 爆点间隔 | WARN（>6 集） | 中段动力衰减 |
| 句库残留 | WARN | 仍是 `plan` 默认值 |
| EP1-3 钩子类型 | FAIL | 三集互不相同 |
| EP1 黄金 3 秒 | WARN | 禁铺垫开场 |

**句库残留会污染所有基于文本信号的判断**：一旦检测到残留，原本判 OK 的项会降级为「需人工复核」—— 避免出现「30 集套话 + 报告全绿」的假安全感。

题材侧重表（`references/genre-profiles.json`）里的 `must_check` 项，WARN 会升级为 FAIL：不同题材的底线不同，不能只告警。

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> review --write-fixes
```

`--write-fixes` 额外产出 `blueprint-fixes.md`：按检查项列出集号 + 现写法 + 该题材的改法提示，直接当待改清单用。

## 五、③ 正文：按骨架写，不即兴改结构

按 `prompts/s3-script-rewrite.md` 逐集写 FFS 正文。三条纪律：

1. **不偏离已确认的骨架**：发现骨架有问题，回 `plan` 改，不要在正文里私改主线。
2. **每场戏有明确目的**：推进事件 / 改变关系 / 释放情绪 / 揭示信息，四者不占就删。
3. **重要转折必须有铺垫**：底牌前文埋过；临时掏出的底牌是金手指，爽感归零。

---

## 六、④ 验收：换成观众的眼睛

脚本只做**完整性校验**（答满七问、引用具体集号、Q7 落成三条带改法），内容由人或 LLM 填。
这不是形式主义 —— 它挡的是「节奏不够快、冲突不够强」这类无效结论。

```bash
python stages/creation/scripts/script_rewrite.py --workspace <ws> audience           # 生成模板
python stages/creation/scripts/script_rewrite.py --workspace <ws> audience --check   # 校验
```

七问见 `prompts/s3c-audience-review.md`。判定标准：**每条回答必须能指到某一集的具体情节**，指不到就是没看进去。

## 七、情绪承诺表（每段剧情该给观众什么）

| 剧情阶段 | 观众需要得到 | 对照写法 |
|---|---|---|
| 开场 | 好奇：到底发生了什么 | 结果先给，成因后置 |
| 冲突建立 | 共情或愤怒：为什么会这样 | 具体羞辱动作，不是「她嘲讽她」 |
| 压力升级 | 担忧或期待：主角怎么办 | 让观众短暂相信她这次要输 |
| 反转反击 | 惊喜或爽感：局势为什么变了 | 底牌前文埋过 + 见证者在场 |
| 情绪兑现 | 满足：之前的铺垫有没有回报 | 得失都落到可量化物件 |
| 集尾卡点 | 悬念：接下来会发生什么 | 由本集因果推出，不空降 |

每一集至少要落在其中一格；**连续两集落在同一格且没有升级，就是注水**。

## 八、题材分轨（不要一套公式套所有故事）

真源：`stages/creation/references/genre-profiles.json`（新增题材加一条即可，无需改代码）。

| 题材 | 结构侧重 | 观众承诺 | 底线（必检） |
|---|---|---|---|
| 复仇逆袭 `revenge` | 压迫 → 筹谋 → 反击 | 先被踩到底，再一级一级打回去 | 主角主动、反转改格局、冲突不重复 |
| 甜宠 `sweet` | 关系推进 → 情感拉扯 → 人物选择 | 每次靠近都差点错过，每次选择都加码 | 关系刻度逐集变化、冲突不重复 |
| 悬疑 `suspense` | 线索 → 信息差 → 合理误导 | 拼图越全，越不像原来那张图 | 信息差持续推进、钩子可追溯、反转推翻旧结论 |
| 家庭伦理 `family` | 利益冲突 → 亲密背叛 → 情感代价 | 最亲的人先动手，最疼的账最后算 | 冲突不重复、反转改话语权 |

题材的**逐集硬约束**（打脸节拍 / 阶梯 / 见证者 / 金句）仍由 `genre-formulas/*.json` 负责；
本表只管「靠什么撑住观众」，两者是分层关系，不互相替代。

## 九、四条最容易犯的错

1. **跳过诊断直接写 30 集** —— 写出来的东西格式全对，但没有任何一集非看不可。
2. **把「狗血」当「爆款」** —— 反转多不等于节奏好；无铺垫的反转消耗的是观众的信任。
3. **用句库默认值当大纲** —— `review` 会报「句库残留」，那不是误报。
4. **只验格式不验观看体验** —— `lint` 全绿只证明能拍，不证明好看。

## 十、往下游交什么（剧本 → 分镜 → H3 提示词）

剧本是**唯一事实源**，分镜与提示词只做编排层增强。这条纪律此前只写在技能提示词里，
现在有机器门禁：`stages/production/scripts/script_continuity.py`。

| 锚 | 剧本侧 | 下游侧 | 判据 |
|---|---|---|---|
| 镜头号 | `[SC-nn]` —— **是镜头，不是场次** | `shot_id` / `epNN_scMM_prompt.txt` 的 `MM` | 少 = 丢镜（FAIL）；多 = 拆镜（≤2×） |
| 台词 | `DIALOG` / `VO` 引号内文本 | H3 `Staging` / `<d>` / 对白列 | 逐字（前 24 字指纹，容忍标点） |
| 人物 | `CHAR` 代号，必须在 HEADER `# CHAR:` 登记 | `Picture N = … (Character)` | 代号可映射（Héctor = HECTOR） |
| 时长 | `DUR` | `duration` / `N-second` | 合计偏差 ≤10% |
| 剧情节点 | blueprint `plot_points`（`EPnn-P1..P4`） | 首镜落 `cold_open`、末镜落 `hook` | 实义实体共享 ≥1 |

```bash
python stages/production/scripts/script_continuity.py --workspace <ws> --all
# 退出码：0 通过 / 2 割裂 / 4 缺剧本或缺产物（不空转通过）
```

三条判断原则：

1. **要改内容，回剧本改**。在提示词里改台词、换人物、丢开场，门禁会报割裂。
2. **跨语种不假装通过**。blueprint 写中文、剧本是外语时，节点承接无法逐字比，只告警并要求人工确认。
3. **配角没参考图可以接受，主角没有不行**。图片槽上限 6，取舍是导演权；但本集出场最多的人物一次都没引用，必然漂。

> 已知命名歧义：FFS 的 `[SC-nn]` 是**镜头**，分镜模板的 `## 场景 SC##` 是**场次**。
> 跨阶段一律按**镜头号**对齐（`[SC-nn]` ↔ `shot_id` ↔ `epNN_scMM`），不要按 `SC` 字面理解。

## 十一、一页速查

```
diagnose → --check → --confirm      （A/B/C 想清楚，否则不许写正文）
plan --from-outline 人工拆解.md      （句库只做占位）
review --write-fixes                （结构不过，别急着写对白）
build --ep N --emit → lint --ep N   （正文按骨架写）
audience → audience --check         （换观众的眼睛再看一遍）
script_continuity --all             （剧本 → 分镜 → 提示词 是不是同一条内容）
```

退出码：`2` = 关卡未过（诊断/审查/审稿）｜`4` = 前置未确认（诊断未 confirm 就写正文）。

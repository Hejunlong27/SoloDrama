# 创作链与 Skill：从一句话到可拍的镜头

> 这份文档回答：**Skill 是什么、装到哪、怎么和本项目配套**，以及**画风为什么必须归项目**。

## 一、分层：三条流水线，各管一段

```
00-创作/          ← 人 + 模型写的（Markdown，可改、可推翻）
   01-企划案.md
   02-资产库.md
   03-分集剧本.md
   04-导演手册/第01集.md
        ↓ 转换（pack.convert）
pack/             ← 制作包：引擎能吃的 JSON 契约
        ↓ 导入（pack_import）
06-提示词/ep01/    ← 引擎唯一输入（shots / boards / h3_prompts / characters / scenes）
        ↓ 执行
04-资产/  07-成片/  ← 引擎产物（图片、视频，不该手改）
```

**为什么创作产物单独一个目录**：Skill 的约定是 `片名/01-企划案.md`，而引擎工作区已有
`03-剧本/`、`05-分镜/`。混在一起会出现「剧本有两个版本、不知道哪个是引擎在读」。
定死分工之后，「改剧本」和「改提示词」永远不冲突 —— 改前者要重跑转换，改后者只影响出片。

## 二、Skill 是什么

`<目录>/<name>/SKILL.md`：YAML frontmatter（`name` / `description`）+ 正文提示词。
它**不是可执行程序**，是给大模型看的创作说明。

当前来源（`configs/skills-sources.json`）：

```
D:/整合包/ai-manju-skills-main/skills    21 份题材模板
```

| 模板 | 题材 |
|---|---|
| `tianchong-manju` | 总裁甜宠 |
| `chuanyue-manju` | 古代穿越重生 |
| `gongdou-manju` | 宫斗 |
| `xuanyi-manju` | 悬疑 |
| …（共 21 份，覆盖重生/都市/家庭/民俗/末世/年代/权谋/商战/武侠/校园/修仙/星际/系统/玄幻/娱乐/宅斗/种田） |

装载 = **复制到 `<ws>/skills/<id>.md` + 写 `<ws>/skills.json`**。不 import、不执行。

## 三、画风归项目，不归 Skill（这条是硬规矩）

模板里通常写死了风格（"现代精致国漫，电影级 2.5D 动画"）。而本项目的画风由
`project.json` 的 `style_lock` 决定。两者会打架。

**裁决：Skill 管叙事结构与题材套路，style_lock 管画风。**

拼装给模型的指令时，style_lock 被插在**最前面**，并明确要求忽略模板里的风格描述：

```
━━━━━ 本项目画风（优先级最高）━━━━━
cinematic live-action short drama, 35mm anamorphic lens, desaturated cold-blue palette…
（上面的画风优先级高于 Skill 正文里任何关于画风的描述）
━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━ 创作模板：总裁甜宠AI漫剧全流程模板 ━━━━━
（模板正文 7554 字）
```

这条不写在提示词里，就会出现「换了题材模板，出图却还是国漫」——
而用户会以为是模型的锅。界面上有「看模型将收到的指令」按钮，随时可查实际发出去的内容。

## 四、五个环节与四个用途

| 环节 | 用途 id | 需要什么 | 产出 |
|---|---|---|---|
| 灵感 | —（人填） | 一句话 | `brief.json` 的 `idea` |
| 企划案 | `create.plan` | 灵感 + Skill + style_lock | `01-企划案.md` |
| 资产库 | `create.assets` | 企划案 | `02-资产库.md` |
| 分集剧本 | `create.script` | 企划案 + 集数范围 | `03-分集剧本.md` |
| 导演手册 | `create.director` | 资产库 + 某一集剧本 | `04-导演手册/第NN集.md` |

用途表 `web/core/llm/templates.py::PURPOSES` 同时是**界面的按钮顺序**：
企划 → 资产 → 剧本 → 手册。按字母排会让人看不出「下一步该点哪个」。

模板正文在 `stages/import/prompts/skill_*.md`，每份只干一件事：
**补「怎么落到本项目的契约上」**（镜头 4–15 秒、每集 6–12 镜、台词 ≤ 24 字、参考图 ≤ 6 张），
题材套路由 Skill 负责，两边不重复。

## 五、模型的输出契约分两类

`TEMPLATE_MAP[tid]["output"]`：

- `pack`（只有 `pack.convert`）→ 写文件：`pack.json` / `assets/*.json` / `episodes/epNN.json`
- `text`（四个创作用途）→ **直接给 Markdown 正文**，不写文件

混用会让「生成企划案」的模型也去写 `pack.json` —— 那是下一步的事，写了反而要人删。

## 六、状态判据与安全

**三态**：`empty` / `done`。`done` 的判据是「文件存在且非空」，不设字数阈值 ——
编一个阈值只会让人为了过线灌水。

**写盘规则**：内容为空一律拒绝（空文件会让状态显示"已完成"）；覆盖不同内容前自动
留 `.bak_<时间戳>`。这两个不是洁癖：这些是模型写的、人要改的文本，
一次「重新生成」冲掉改了三小时的东西，是这类工具最容易造成的不可逆损失。

**演练 vs 真稿**：模型提供商是 `mock` 时，返回的是一份明确标注「演练」的样例。
界面在 toast 里会写「离线演练，非真实创作」—— 不说清的话，用户会拿着"演练片名"
去问为什么片名是假的，而真正原因是模型还没配。

## 七、大模型出网需要显式放行

网络出口守卫（`stages/_netguard.py`）默认只许本机/内网。大模型是远端，必须：

```bash
SOLODRAMA_ALLOW_REMOTE=1 python -m uvicorn app:app --port 8788
```

被拦时错误会原样贴出「这是网络出口守卫拦的」，不吞成「生成失败」。

# SoloDrama Studio · 产品定义 v1.0

> 状态：生效中（2026-10-28）。本文是**产品口径**，不是功能清单；功能实现以 `web/` 代码为准，
> 引擎口径以 `docs/` 为准。两者冲突时，先改本文再改代码。

## 1. 一句话

**一个人、一台电脑、一条流水线**：把「短剧创作」从散落的命令行脚本，变成一个有项目、有连接、有作业、
有成本台账的工作台。创作者在这里完成从选题到发布版的全过程，AI 是执行者而不是黑箱。

不做的事：不做素材站、不做分发投放、不做多人协同编辑。

## 2. 用户与场景

| 角色 | 要什么 | 产品给的 |
|---|---|---|
| 主用户（个人创作者/工作室） | 一次管理 5–30 部剧，任何一步都能查「为什么没做」 | 项目列表 + 11 环节完成度 + 失败原因翻译 |
| 同行/AI 助手 | 照文档就能复现一条流水线 | 每条动作都是一个具名 spec，可被脚本调用 |
| 评审/客户 | 不进终端也能看懂「做到哪了」 | 只读 demo 链接（hosted 模式） |

## 3. 三个一等公民

**项目（Project）** — 一部剧 = 一个工作区目录。产品不发明状态，只读引擎的 `layout.json` 与
`project-setup.json`；环节完成度来自 `workflow status` 的 probes。

**连接（Connection）** — 模型、出图、出片三类外部能力。连接是**机器级**配置，不是项目级：
同一台机器上的所有剧共用一个 ComfyUI、一个 RunningHub 账号。连接必须能在界面上**被验证**，
不能只写「请去终端设环境变量」。

**作业（Job）** — 任何会超过几秒、会花钱、会占 GPU 的动作都进队列。作业有日志、可取消、
有退出码语义、有钱的闸门（428 + confirm）。

## 4. 核心闭环（七步）

| # | 用户动作 | 产品呈现 | 花钱 |
|---|---|---|---|
| 1 | 新建项目，填一句设定 | 项目卡 + 前置检查（9 项） | 0 |
| 2 | 让 AI 写第 1 集 | 草稿（`llm-drafts/`）→ 人工改 → 确认落盘 | 按 token |
| 3 | 结构自检 | FFS lint / 连续性 / 时长审计，红黄绿 | 0 |
| 4 | 生成资产 | 本地 ComfyUI 或 RH；缩略图墙 + 缺口 | 0 / RH 币 |
| 5 | 分镜与视频 | 每镜一卡（图 + 提示词 + 视频），可重跑单镜 | RH 币 |
| 6 | 后期 | 拼接 / 放大 / 字幕 / BGM，按集看进度 | 0（本地算力） |
| 7 | 发行 | `EpisodeNN.mp4` + 封面 + 文案 + 发布清单 | 0 |

**贯穿原则**：每一步都回答三个问题——做没做（判据）、花了多少（台账）、下一步是什么（唯一推荐动作）。

## 5. 信息架构

```
全局  工作台 · 项目管理 · 任务中心 · 成本中心 · AI 模型中心 · 连接中心
项目  项目详情 · 创作中心 · 资产中心 · 分镜与视频 · 后期制作 · 发行中心
系统  系统设置
```

「连接中心」与「AI 模型中心」的分工：模型中心管 **LLM 的用途路由与调用记录**（哪个用途用哪个模型、
花了多少 token）；连接中心管 **三类通道是否接通**（Key、地址、版本、余额、最近一次成功时间）。
两者都读同一份 Key 存储，不重复维护。

## 6. 连接模型

| 通道 | 引擎认的变量 | 探测方式（全部 0 费用） | 失败怎么解释 |
|---|---|---|---|
| LLM | 走 `core/llm` 网关，不落环境变量 | `GET /models` 或最小 `chat`（需勾选） | 区分「地址错 / Key 错 / 模型名错 / 额度不足」 |
| ComfyUI | `COMFYUI_URL` | `GET {url}/system_stats` | 未启动 → 给启动命令；版本过低 → 给最低版本 |
| RunningHub | `RUNNINGHUB_API_KEY`、`RUNNINGHUB_BASE_URL` | 只读查工作流节点表（免费） | 站点选错（.ai/.cn）/ Key 无效（401）/ 工作流不存在 |

**存哪里**：`web/var/connections.json`（非密钥）+ `web/var/connections.keys.json`（密钥，0600）。
`web/var/` 已在 `.gitignore`。界面读回**只有指纹**（末 4 位 + 长度），永远不回显明文。
注入方式：`runner.base_env()` 每次把连接值合并进子进程环境，**用户不需要设任何环境变量**。

> 与「密钥不落盘」的关系：该纪律约束的是**仓库与日志**（不进 git、不进日志、不进 prompt）。
> 本地运行态需要持久化，落 `web/var/`（gitignored、0600）是产品层的等价实现；
> 仍然禁止把 Key 写进任何会被注入上下文或提交的文件。

## 7. 发布形态

**本地优先（默认）**：`start.cmd` 起单端口 8788，全部能力可用（含本地 GPU、ffmpeg、Topaz）。

**托管 demo（只读）**：同一套前端 + 后端，`SOLODRAMA_STUDIO_MODE=demo`：
不探测本机引擎，读打包好的 `demo/` 快照（一部样例剧的产物与截图），所有写操作返回
`403 demo`。用途是给评审/客户看「这套流水线长什么样」，**不用于生产**。

选择理由：短剧生产的瓶颈在本地 GPU 与素材落盘，纯云端跑不通；把「能用」和「能看」拆成两种形态，
比假装云端全功能更诚实，也更容易维护。

## 9. 验收标准（可测，不靠"感觉"）

1. 断网/未启动 ComfyUI 时，连接中心显示**红色**且给出可执行的下一步，不是"未知错误"。
2. 把 ComfyUI 地址改成错的，测试在 5 秒内返回，且不产生任何作业。
3. Key 保存后，`GET /api/connections` 响应体中**不含明文**；用 grep 搜响应全文必须为 0 命中。
4. 保存的连接值能让 `gen_assets_local.py` 在不设环境变量的情况下跑通（由 `base_env` 注入）。
5. 首启引导三格状态与后端探测结果一致（同一请求源，不各算一套）。
